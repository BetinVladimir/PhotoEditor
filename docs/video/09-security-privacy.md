# 09. Безопасность, приватность, права на контент

Статус: спроектировано, не реализовано (2026-10-22). Начало: [README](README.md). Видео — самый тяжёлый и опасный тип входных данных платформы: многогигабайтные недоверенные файлы разбираются сложными декодерами. Сохраняются все ограничения изоляции фото-системы ([17-integration-security.md](../implementation-v2/17-integration-security.md)).

## 1. Модель угроз

| Угроза | Вектор | Меры | Проверка |
|---|---|---|---|
| Эксплуатация уязвимости декодера (ffmpeg, кодеки) | специально собранный файл при probe/proxy/рендере | ограниченная среда (раздел 2), обновляемая закреплённая сборка, минимальный набор демультиплексоров/кодеков, отсутствие сети и записи вне scratch | набор злонамеренных образцов, фаззинг-прогон в CI-окружении воркера |
| Исчерпание ресурсов (декомпрессионные бомбы, гигантское разрешение, бесконечные потоки) | малый файл с огромными параметрами | лимиты probe до декодирования, лимиты кадра/потоков/длительности, таймауты, лимиты памяти процесса | негативные образцы: 100000×100000, миллионы потоков, зацикленные контейнеры |
| SSRF/чтение чужих файлов через медиаформаты (HLS-плейлисты, `concat`, субтитры) | ссылки внутри контейнера/плейлиста | `-protocol_whitelist file,pipe`, запрет внешних ссылок, вход только из файлов задачи | образцы с `file:///etc/passwd`, `http://…` |
| Доступ к чужому tenant | подмена идентификаторов в API, SSE, портале | составные FK, проверки области в каждой функции БД, одинаковые ответы «не найдено», клиентские проверки области | межтенантные тесты на каждом эндпоинте |
| Кража/угадывание ссылки выдачи | перебор `share_id`, утечка секрета | UUID + секрет, ограничение попыток (как [`access-link-attempt-store.ts`](../../apps/photographer/src/access-link-attempt-store.ts)), лимиты, срок, отзыв | негативные тесты, лимиты скорости |
| Обход квоты | параллельные загрузки/задания, повтор запросов | атомарные резервы в транзакции, идемпотентность, блокировки в закреплённом порядке | конкурентные интеграционные тесты |
| Подмена результата | замена объекта после проверки | иммутабельные артефакты, версии объектов, SHA-256, проверка перед публикацией | тесты целостности |
| Утечка метаданных через файл | GPS, имя устройства, серийные номера в выходном MP4 | `-map_metadata -1` для результата; политика переноса метаданных — только явным выбором (V2) | проверка выходного файла |
| Перегрузка портала стримингом | много параллельных Range-запросов | лимиты потоков и скорости, учёт трафика, отказ управляемой ошибкой | нагрузочный тест |
| Вредоносные LUT | `.cube` с гигантскими значениями, ссылки, бесконечные строки | строгий парсер: размер файла, число строк, диапазон чисел, размерность ≤ 65 | фаззинг парсера |
| Загрузка запрещённого или нарушающего права контента | пользователь | условия использования, декларация прав на музыку, механизм отключения администратором ([08](08-delivery-portal.md), раздел 7) | процедурная проверка |

## 2. Изоляция исполнения

1. Воркер выполняет операции в контейнере с корневой ФС только для чтения, `cap_drop: ALL`, `no-new-privileges`, без сетевого доступа кроме gateway ([`compose.rtx-worker.yaml`](../../deploy/compose.rtx-worker.yaml)).
2. ffmpeg/ffprobe — внешний процесс под отдельным непривилегированным пользователем, с seccomp-профилем, лимитами `RLIMIT_AS`/CPU/числа процессов, собственной временной директорией на задачу и принудительным завершением группы процессов по таймауту/отмене.
3. Для особенно опасных шагов (probe чужого файла) используется отдельный вызов с минимальным `probesize` и без декодирования; полное декодирование начинается только после проверки допустимости контейнера и параметров.
4. Сборка ffmpeg: закрепляемая, с минимальным набором компонентов (нужные демультиплексоры, декодеры, фильтры, энкодеры); версия, хеш, конфигурация сборки и список лицензий попадают в SBOM ([`release/`](../../release)) и в `render_fingerprint`. Обновление безопасности — по регламенту реагирования на CVE (срок и ответственный определяются владельцем эксплуатации).
5. Gateway по-прежнему разрешает воркеру только объекты его задачи (`AuthorizeTaskObject`, [19-runtime-protocol.md](../implementation-v2/19-runtime-protocol.md)); исходящие артефакты проходят проверку роли, размера и числа.

## 3. Загрузка и ingest

1. Классификация по содержимому: список разрешённых контейнеров/кодеков/потоков; всё остальное — `rejected` с кодом, объект удаляется.
2. Лимиты до дорогой обработки: размер, длительность, разрешение, число потоков, число глав/вложений, битрейт, частота кадров.
3. Вложения, данные, субтитры и неизвестные потоки не копируются в производные.
4. Все ошибки и журналы воркера санитизируются: нет путей хоста, ключей объектов, имён файлов пользователей; длина ограничена.
5. Дубликаты по SHA-256 внутри tenant допустимы (подсказка пользователю); перекрёстная дедупликация между tenant **запрещена** (утечка факта наличия файла).

## 4. Приватность и персональные данные

1. Видео с людьми — персональные данные: действуют существующие правила удаления tenant и отзыва доступа ([11-consent-lifecycle.md](../implementation-v2/11-consent-lifecycle.md), [project-asset-withdrawal-contract.md](../implementation-v2/project-asset-withdrawal-contract.md), [v32-tenant-purge-buckets-runtime.md](../implementation-v2/v32-tenant-purge-buckets-runtime.md)). Видео-префиксы входят в очистку tenant, в отчёты о статусе удаления и в проверки восстановления.
2. Модели детекции граней не используют лица и биометрию; обнаружение людей, лиц и голосов в видео вне объёма. Любое будущее добавление такого анализа требует отдельного ТЗ с согласиями.
3. Логи, события SSE и аналитика не содержат содержимого видео, имён файлов, транскриптов, значений секретов ссылок.
4. Превью-кадры и производные — те же персональные данные, что и оригинал: те же права доступа, срок жизни определяется источником (кроме технического кэша, [05](05-storage-quota-retention.md), раздел 1.1).
5. Метаданные результата очищаются по умолчанию (раздел 1, «Утечка метаданных»).

## 5. Права на музыку и контент

1. Платформа не предоставляет музыкальную библиотеку и не проверяет права автоматически. Перед первым рендером с аудиоклипом пользователь декларирует наличие прав; декларация фиксируется в ревизии документа (`rights`) и в журнале (кто, когда, для какого монтажа). Без декларации `VIDEO_RIGHTS_DECLARATION_REQUIRED`.
2. Условия использования и процедура жалоб (контакт, сроки реакции, отключение выдачи администратором) утверждаются владельцем продукта до публичного запуска; техническая возможность отключения реализуется в V1.
3. Автоматическое распознавание музыки (fingerprint) — вне объёма V1; решение о его необходимости принимается по результатам юридической проверки.

## 6. Лицензии и патенты

Нормативный разбор лицензий, реестр компонентов и решения — [22](22-tools-models-licenses.md). Кратко: (1) лицензия проверяется на пяти уровнях — код, веса, данные обучения, патенты, среда исполнения; (2) в образах, уходящих в эксплуатацию, только LGPL-сборка FFmpeg с аппаратными кодировщиками и нативным AAC; `libx264` (GPL) допускается лишь в профиле `gpl_internal` для внутренних образов; `libfdk_aac` и OpenSSL-сборки запрещены; (3) авторско-правовая лицензия не даёт патентных прав на H.264/HEVC — вопрос Q-16 решает юрист; (4) каждая библиотека и каждый файл весов проходят автоматический гейт (SBOM и замок моделей) до включения в образ; (5) условия драйверов и оборудования (лицензия GeForce запрещает развёртывание в дата-центре) — Q-17. До проверки в продукте включаются только компоненты с подтверждённой лицензией.

## 7. Аудит и наблюдаемость

- Аудит-события: загрузка (begin/complete/abort), удаление, запуск и отмена заданий, публикация/снятие/отзыв выдачи, смена секрета, отключение администратором, декларация прав.
- Метрики: ошибки probe по кодам, время стадий, очередь по классам, использование GPU/NVENC, OOM, отмены, скорость стрима, объём трафика по ссылкам, отказы по лимитам.
- Тревоги: рост `rejected`/`VIDEO_CORRUPT` по tenant (возможная атака), аномальный трафик на ссылку, застрявшие резервы, нехватка scratch.

## 8. Требования

| ID | Требование |
|---|---|
| VID-SEC-01 | Недоверенные файлы обрабатываются только в изолированной среде раздела 2; набор злонамеренных образцов не приводит к чтению/записи вне каталога задачи, сетевым вызовам или аварии воркера. |
| VID-SEC-02 | Все проверки лимитов выполняются до дорогостоящего декодирования. |
| VID-SEC-03 | Межтенантная изоляция проверена тестами на каждом новом эндпоинте, событии и операции воркера. |
| VID-SEC-04 | Ссылки выдачи защищены секретом, сроком, лимитом попыток и отзывом; отказ не раскрывает существование объектов. |
| VID-SEC-05 | Логи, события и ошибки не содержат персональных данных, путей, ключей объектов и секретов. |
| VID-SEC-06 | Результат рендера не содержит исходных метаданных устройства по умолчанию. |
| VID-SEC-07 | Видео-префиксы входят в очистку tenant и проверку восстановления; ошибка очистки не превращается в успешный статус. |
| VID-SEC-08 | Декларация прав на музыку обязательна, фиксируется и недоступна для подмены клиентом после сохранения ревизии. |
| VID-SEC-09 | Лицензии ffmpeg-сборки, моделей и библиотек проверены и записаны в SBOM до включения видео для внешних пользователей. |
| VID-SEC-10 | Администратор может отключить ссылку или рендер, действие аудируется и применяется на следующем запросе клиента. |
