## 1. Пользователи и права

| Роль | Кто | Что делает с видео | Основание в системе |
|---|---|---|---|
| Владелец / Editor проекта | фотограф или видеограф | загружает, монтирует, запускает задания, рендерит, выдаёт клиентам, удаляет | роли и `tenant`/`project` authority — как у фото ([`workspace-access-context.tsx`](../../apps/photographer/src/workspace-access-context.tsx)) |
| Участник с чтением | студия | смотрит медиатеку, монтажи и результаты, не меняет | та же модель, право `read` |
| Клиент | получатель ссылки | смотрит и скачивает опубликованные ролики по ссылке | сессия портала `share_id + secret` ([`apps/portal/src/lib/api.ts`](../../apps/portal/src/lib/api.ts)) |
| Администратор платформы | оператор | отключает ссылку/медиа по жалобе, настраивает ёмкость воркеров | [`backend/internal/admin`](../../backend/internal/admin) |

## 3. Сценарии

Каждый сценарий — основной путь, затем обязательные отказы. Отказы проверяются так же строго, как основной путь (правило MVP-плана: восстановление включённых функций обязательно).

### S1. Загрузка исходников

1. Пользователь открывает «Видео» проекта → «Загрузить», выбирает один или несколько файлов (видео, аудио, фото).
2. Приложение считает SHA-256 по частям, показывает прогресс хеширования, затем начинает multipart-загрузку с контрольными точками.
3. По завершении сервер проверяет размер/целостность и создаёт задание ingest. Карточка в медиатеке показывает стадии: загружено → анализ → готово.
4. Результат: исходник `ready` с proxy, раскадровкой, волной и данными probe.

Отказы: обрыв сети (возобновление с контрольной точки), закрытие вкладки (журнал попытки в `AsyncStorage`, как [`interchange-archive-attempt-store.ts`](../../apps/photographer/src/interchange-archive-attempt-store.ts)), неподдерживаемый кодек/контейнер (явная причина, объект не попадает в квоту), превышение квоты (отказ **до** передачи данных), повреждённый файл (`rejected` после ingest, резерв освобождён), дубликат (подсказка «уже загружен», без повторной оплаты места — решение пользователя), истёкшая сессия загрузки (перезапуск с начала с явным текстом).

### S2. Поиск границ склеек

1. Из карточки исходника: «Найти границы склеек». Выбор чувствительности и режима («только жёсткие» / «включая наплывы и затемнения»).
2. Асинхронное задание `video.detect_cuts` на GPU-воркере; прогресс в реальном времени.
3. Экран результатов: полоса времени с кандидатами, порог уверенности, кадры «до/после» для каждого кандидата, принять/отклонить, «применить».
4. «Применить» создаёт в новом или выбранном монтаже разрезанные клипы (по принятым границам) без повторной обработки видео.

Отказы: модель недоступна на бэкенде (причина в UI, предлагается классический метод на CPU), нулевое число найденных границ (честный пустой результат), отмена пользователем, перезапуск после сбоя воркера (идемпотентно, результат не дублируется).

### S3. Монтаж

1. «Новый монтаж» (имя, частота кадров, разрешение, пресет канала).
2. Перетаскивание исходников из бина на дорожки; разрез, сдвиг, обрезка краёв, удаление зазоров, переходы, скорость.
3. Фото проекта добавляются с длительностью и движением.
4. Автосохранение: каждое подтверждённое действие порождает новую ревизию с `expected_revision`.
5. Просмотр на прокси в плеере с синхронизированной аудио-дорожкой.

Отказы: конфликт ревизии (диалог выбора как [`editor-draft-conflict.tsx`](../../apps/photographer/src/editor-draft-conflict.tsx)), удалённый или недоступный источник (клип помечается «источник отсутствует», рендер блокируется, монтаж остаётся открываемым), сеть пропала (локальный черновик, повтор без дублей), превышены лимиты документа (понятное сообщение).

### S4. Цвет

1. Выбор клипа или дорожки → вкладка «Цвет»: базовые регуляторы, кривые, колёса, LUT, «подобрать по эталону».
2. Предпросмотр: превью-кадры (асинхронное задание `video.preview_frames`, ответ за секунды на выделенном интерактивном пуле) и сравнение «до/после».
3. «Авто-анализ» (`video.color_analyze`) предлагает параметры по статистике клипа; пользователь принимает или правит.
4. Эффекты хранятся в документе монтажа и применяются только при рендере (недеструктивно).

Отказы: LUT не проходит валидацию (ошибка с причиной), несовместимое цветовое пространство источника (предупреждение и явное преобразование), превью устарело относительно ревизии (помечается, не применяется молча).

### S5. Музыка и звук

1. Импорт аудиофайла (как в S1) или выбор из медиатеки; перетаскивание на аудиодорожку.
2. Волна, метки битов (опциональный анализ `audio.analyze`), привязка склеек к битам.
3. Громкость, fade in/out, «приглушать музыку под речью» (ducking), целевая громкость выхода (пресеты −14 / −16 LUFS).
4. Обязательная декларация прав на музыку при первом использовании (хранится вместе с монтажом).

Отказы: файл без аудиопотока, частота дискретизации не 44.1/48 кГц (приводится на рендере), музыка длиннее/короче видео (обрезка/зацикливание по явному выбору).

### S6. Рендер

1. «Рендер»: пресет (разрешение, частота, битрейт-профиль), отдельное имя файла.
2. Экран показывает оценку размера и длительности, доступность бэкенда, необходимое место в квоте. Нехватка места блокирует отправку **до** создания задания.
3. Резервирование квоты → постановка в очередь → воркер рендерит → результат в MinIO → резерв пересчитывается в фактический объём.
4. Экран задания: стадии (подготовка, декодирование, фильтры, кодирование, проверка, выгрузка), процент, оценка остатка, отмена.

Отказы: отмена (резерв возвращается, частичные объекты чистятся), OOM/ресурсы (один контролируемый повтор на меньшем профиле, иначе ошибка `RESOURCE_EXHAUSTED`), нет подходящего воркера (задание ждёт в очереди с видимой причиной, ограничение времени ожидания), потеря воркера (повторная выдача другим воркером по lease), результат не прошёл проверку (ошибка, не публикуется).

### S7. Выдача клиенту

1. «Выдать клиенту»: выбор готовых рендеров, название, срок действия, секрет ссылки.
2. Генерация ссылки `/s/{share_id}` (формат портала сохраняется) и тест «посмотреть как клиент».
3. Клиент открывает ссылку, вводит секрет (если нужен), смотрит ролик и скачивает файл.
4. Владелец видит статистику (просмотры, скачивания, трафик) и может отозвать ссылку.

Отказы: отозванная/истёкшая ссылка (понятный отказ без утечки данных), исчерпан трафик (отказ с объяснением владельцу, не клиенту), снятие публикации во время скачивания (новые ссылки не выдаются, уже выданная подписанная живёт ≤ 60 с).

### S8. Управление объёмом

Экран квот показывает занятое по категориям (оригиналы, производные, результаты, музыка), резервы активных заданий, остаток трафика; владелец удаляет медиа/результаты вручную (автоудаления нет). Удаление источника, используемого в монтаже, требует подтверждения и оставляет в монтаже «пустые» клипы.

## 4. Поддерживаемые форматы и лимиты (стартовые значения)

Значения лежат в серверной политике и сообщаются клиенту через capability-ответ ([`capabilities-response.ts`](../../apps/photographer/src/capabilities-response.ts)), клиент не хардкодит их.

| Параметр | V1 |
|---|---|
| Контейнеры видео | MP4, MOV, M4V, MKV, WebM |
| Видеокодеки (декодирование) | H.264, HEVC, VP9, AV1 (если сборка FFmpeg поддерживает), ProRes |
| Аудио | AAC, MP3, WAV (PCM), FLAC, ALAC, Opus, Vorbis |
| Фото на таймлайне | то, что уже принимает пайплайн проекта (версии активов проекта) |
| Размер одного файла | до 16 ГиБ (ниже 20 ГиБ — предела скачивания воркера) |
| Длительность | до 3 часов |
| Разрешение | до 4096×2304, не менее 64×64; 8K отклоняется |
| Частота кадров | 1–120 fps; переменная (VFR) приводится к постоянной на ingest proxy, оригинал не меняется |
| Дорожки монтажа | видео ≤ 4, аудио ≤ 4 |
| Клипов в монтаже | ≤ 2 000; документ ≤ 8 МиБ |
| Одновременно активных заданий на tenant | политика ёмкости (по умолчанию: 1 рендер, 2 анализа) |
| Выходные пресеты | 720p / 1080p / 1440p / 2160p; 16:9, 9:16, 1:1; 24/25/30/50/60 fps или «как в монтаже» |

Определение типа — по содержимому (probe), а не по расширению и не по `Content-Type`, присланному клиентом.

## 5. Функциональные требования

| ID | Требование |
|---|---|
| VID-F-01 | Система принимает видео, аудио и использует фото проекта как источники монтажа; исходные байты не изменяются (оригинал неизменяем, производные — отдельные артефакты). |
| VID-F-02 | Для каждого видеоисходника создаются proxy для предпросмотра, раскадровка (спрайты), волна и запись probe; пока ingest не завершён, исходник нельзя использовать в рендере. |
| VID-F-03 | Поиск границ склеек запускается по запросу, выполняется асинхронно моделью на GPU-воркере (CUDA или MLX) либо классическим методом на CPU; результат — список границ с кадром, типом и уверенностью. |
| VID-F-04 | Пользователь принимает/отклоняет границы и применяет их к монтажу, получая разрезанные клипы без перекодирования. |
| VID-F-05 | Монтаж — многодорожечный документ с неизменяемыми ревизиями; сохранение защищено ожидаемой ревизией и идемпотентно. |
| VID-F-06 | Цветокоррекция и аудио-эффекты недеструктивны и записываются в документ монтажа; к исходникам не применяются. |
| VID-F-07 | Финальный рендер выполняется воркером по зафиксированной ревизии монтажа; результат пишется в MinIO и регистрируется как артефакт. |
| VID-F-08 | Все долгие операции показывают стадию и прогресс, поддерживают отмену, безопасный повтор и восстановление после перезапуска клиента и воркера. |
| VID-F-09 | Объём оригиналов, производных, результатов и музыки учитывается в общей квоте; нехватка места блокирует операцию до начала. |
| VID-F-10 | Готовые ролики выдаются клиентам по ссылке портала с просмотром и скачиванием; ссылка отзывается; трафик учитывается. |
| VID-F-11 | Недоступные возможности (нет воркера/модели/бэкенда) показываются в UI с реальной причиной от сервера, а не скрываются и не обещаются. |
| VID-F-12 | Все строки интерфейса доступны на EN/RU/BG; тексты ошибок не раскрывают данные другого tenant. |
