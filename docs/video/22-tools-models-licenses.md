## 1. Что значит «разрешает коммерческое использование без оплаты»

Лицензия компонента проверяется на **пяти уровнях**; достаточно провала на одном, чтобы компонент не попал в продукт.

| № | Уровень | Вопрос | Пример провала |
|---|---|---|---|
| 1 | Код | можно ли использовать код коммерчески бесплатно и на каких условиях | AGPL, «source-available» с запретом SaaS |
| 2 | Веса | лицензия самого файла весов (она может отличаться от лицензии кода) | OpenRAIL с ограничениями применения, «research only», отсутствие лицензии |
| 3 | Данные обучения | вправе ли автор весов был обучаться на данных и разрешено ли коммерческое применение результата | веса, обученные на видео с YouTube без разрешения |
| 4 | Патенты | лицензия на авторское право не даёт прав на патенты (кодеки H.264/HEVC и др.) | `libx264` под GPL не включает патентную лицензию |
| 5 | Среда | условия драйверов, ОС и оборудования, на которых это запускается | лицензия драйвера GeForce запрещает развёртывание в дата-центре (раздел 5) |

Метка лицензии на Hugging Face — **заявление загрузившего**, а не проверка. Конвертация (ONNX, GGUF, MLX) не меняет лицензию оригинала и не снимает вопросы уровня 3.

## 2. Политика

### 2.1 Вердикты

| Вердикт | Что означает | Что можно |
|---|---|---|
| `allow` | разрешительная лицензия, бесплатное коммерческое использование | включать в образ и замок без дополнительных решений |
| `conditional` | копилефт, бесплатное коммерческое использование допустимо **при условиях** (отдельный процесс или динамическая линковка, нет распространения за пределы владельца, исходники по запросу) | только для **кода**; решение записывается в реестре исключений (TK-921) |
| `review` | лицензия неизвестна, нестандартна или с ограничениями применения | нельзя без письменного решения человека (запись исключения с именем утверждающего и сроком) |
| `deny` | запрет коммерческого применения, производных, отсутствие лицензии или сетевой копилефт | нельзя; исключения не допускаются |

Пояснение к `conditional`: GPL и LGPL **не запрещают** платное и бесплатное коммерческое использование. Обязанности копилефта возникают при **распространении** программы (передача образов или бинарников третьим лицам, поставка клиенту). Воркеры работают на собственных машинах владельца, поэтому для GPL-компонентов, которые не покидают эту инфраструктуру, ограничение — организационное, а не запрет. По этой причине GPL-компоненты помечены `conditional`, а не `deny`; но продукт по умолчанию строится так, чтобы не зависеть от этого (D-20). Применимость к конкретной схеме эксплуатации подтверждает юрист (Q-03).

### 2.3 Чистые функции (определения; векторы — `vectors/license.json`)

**FN-X-01 `licenseVerdict(expr, kind) → {verdict, reasons[]}`**, `kind ∈ {code, weights, data}`.

1. `kind` вне набора → `{error: 'KIND_INVALID'}`. Пустая или состоящая из пробелов `expr` → `{verdict: 'deny', reasons: ['NO_LICENSE_GRANT']}`.
2. Разбор: лексемы `(`, `)` и последовательности без пробелов и скобок. Операторы `AND`, `OR`, `WITH` — без учёта регистра. Грамматика: `выражение := терм (OR терм)*`; `терм := множитель (AND множитель)*`; `множитель := '(' выражение ')' | идентификатор [WITH исключение]`. Исключение после `WITH` проверяется только на наличие и не влияет на вердикт. Любая синтаксическая ошибка, лишние лексемы или непарные скобки → `{verdict: 'deny', reasons: ['EXPR_INVALID']}`.
3. Лист: нормализовать (нижний регистр, `+`, суффикс `-only`), найти в таблице 2.2. Причины листа: `allow` → `[]`; `CC-BY-3.0/4.0` → `['ATTRIBUTION_REQUIRED']`; `conditional` при `kind=code` → `['COPYLEFT_CONDITIONS']`, при другом `kind` → `review` и `['COPYLEFT_ON_NON_CODE']`; `review` из списка → `['NEEDS_HUMAN_REVIEW']`; любой `LicenseRef-*` вне `allow` → `review`, `['NEEDS_HUMAN_REVIEW']`; неизвестный → `review`, `['LICENSE_UNKNOWN']`; `deny`: `AGPL`, `SSPL` → `NETWORK_COPYLEFT`; `CC-BY-NC*`, `non-commercial` → `NON_COMMERCIAL`; `CC-BY-ND*` → `NO_DERIVATIVES`; `BUSL-1.1`, `proprietary`, `research-only` → `RESTRICTED_USE`; `all-rights-reserved`, `unlicensed`, `none`, `unknown` → `NO_LICENSE_GRANT`.
4. `AND`: ранг = максимум рангов операндов (`allow` 0 < `conditional` 1 < `review` 2 < `deny` 3), причины — объединение без повторов в порядке появления. `OR`: берётся операнд с **наименьшим** рангом (при равенстве — первый), причины — его причины.

**FN-X-02 `ffmpegBuildVerdict(buildconf, profile) → {ok, violations[]}`**, `profile ∈ {lgpl, gpl_internal}`, иначе `{error: 'PROFILE_INVALID'}`. Вход — вывод `ffmpeg -buildconf` или строка `configuration:` из `ffmpeg -version`. Учитываются только лексемы, начинающиеся с `--enable-` (без учёта регистра); имя флага = часть после `--enable-` до `=`, в нижнем регистре, `_` заменяется на `-`. Нарушения в порядке появления, без повторов, формат `КОД:исходная лексема`:

- `NONFREE` (в любом профиле): `nonfree`, `libfdk-aac`, `openssl`, `libnpp`, `cuda-nvcc`, `cuda-sdk`, `decklink`;
- `GPL` (только профиль `lgpl`): `gpl`, `libx264`, `libx265`, `libxvid`, `libvidstab`, `librubberband`, `frei0r`, `libcdio`, `libxavs`, `libxavs2`, `libdavs2`, `postproc`.

`--disable-*`, `--enable-version3` и прочие флаги нарушением не являются. Это проверка **списка флагов**, а не доказательство лицензии бинарника: бинарник дополнительно проверяется по разделу 7.3.

**FN-X-03 `modelApprovalGate(entry) → {eligible, reasons[]}`** — может ли запись замка моделей получить `approved_for_install = true`. Поля: `code_license`, `weights_license`, `training_data_license` (может быть `null`), `redistribution_policy`. Порядок проверок (причины в этом порядке):

1. `licenseVerdict(code_license, 'code')` не `allow` и не `conditional` → `CODE_<ВЕРДИКТ>` (например, `CODE_DENY`);
2. `licenseVerdict(weights_license, 'weights')` не `allow` → `WEIGHTS_<ВЕРДИКТ>`;
3. `training_data_license` равно `null` или пусто → `DATA_NOT_RECORDED`; иначе `licenseVerdict(…, 'data')` не `allow` → `DATA_<ВЕРДИКТ>`;
4. `redistribution_policy = 'unresolved'` → `REDISTRIBUTION_UNRESOLVED`.

`eligible = true`, если причин нет. Для `conditional` кода запись замка дополнительно требует действующего исключения из реестра (проверяет TK-923, функция остаётся чистой). Эквивалентная проверка для SBOM — TK-921.

### 2.4 Правила для Hugging Face

1. Источник — репозиторий с зафиксированным `revision` (хеш коммита), как уже требует замок моделей ([`lock.py`](../../workers/photo_worker/models/lock.py): поле `revision`, список файлов с SHA-256, разрешённые хосты загрузки включают `huggingface.co`).
2. В запись замка вносятся три лицензии (код, веса, данные), текст карточки на момент проверки сохраняется в `notices` (ссылка и SHA-256 снимка).
3. Метка лицензии без текста, без указания происхождения весов или с цепочкой `base_model`, не ведущей к первоисточнику, считается **неподтверждённой**: вердикт `review` до проверки первоисточника.
4. Репозитории без лицензии (`license` не указан) — `deny`.
5. Порты и конвертации (ONNX, GGUF, MLX) наследуют вердикт оригинала по худшему из уровней; метка `mit` на порте не повышает вердикт.
6. Закрытые («gated») модели, требующие принять условия, — `review`.
7. Загрузка в рантайме запрещена, установка офлайн по замку (без изменений относительно [06](06-workers-and-models.md)).

## 5. Условия среды исполнения

1. **Драйвер GeForce.** Лицензия NVIDIA на ПО GeForce содержит пункт 2.1.3: «The SOFTWARE is not licensed for datacenter deployment, except that blockchain processing in a datacenter is permitted» ✔ ([nvidia.com/drivers/geforce-license](https://www.nvidia.com/en-au/drivers/geforce-license/)). Образец воркера в репозитории — «RTX-хост» ([`compose.rtx-worker.yaml`](../../deploy/compose.rtx-worker.yaml)); класс карты в репозитории не зафиксирован. Нужно подтвердить: какой именно класс GPU и драйвера используется и считается ли развёртывание «дата-центром» в смысле лицензии. Если применяются потребительские карты в серверной среде, нужны карты и драйверы с серверными условиями лицензии. Это вопрос эксплуатации и юриста, не разработки (A-13, Q-17).
2. **Лимиты NVENC** на потребительских картах (число одновременных сессий) — техническое ограничение (A-8), не лицензионное.
3. **macOS-воркеры** (VideoToolbox, MLX): лицензия macOS и условия аренды/размещения Mac-хостов проверяются при вводе в эксплуатацию (входит в Q-17).
4. Отчёт квалификации воркера ([06](06-workers-and-models.md), раздел 9) получает обязательную запись `gpu_license_class` (`datacenter`, `workstation`, `consumer`, `unknown`). Это операторская процедура ([runbook TK-925](15-task-cards.md)), а не код планировщика: оператор не включает воркер в пул `video_heavy`, если класс `consumer` или `unknown`, пока в Q-17 не записано решение владельца.

## 7. Интеграция

### 7.1 Замок моделей ([`models/lock.py`](../../workers/photo_worker/models/lock.py))

Уже есть: `code_license`, `weights_license`, `notices`, `redistribution_policy`, `approved_for_install`, запрет утверждения при `unresolved` ✔ (прочитано в репозитории). Нужно добавить (TK-923):

1. Поле `training_data_license: str | None = None` и список `data_provenance: list[str]` (пути к манифестам данных).
2. Идентификаторы моделей `video_boundary_transnet` и `video_beat_this` в `MODEL_IDS` (запись `video_beat_this` не создаётся до решения V2).
3. Для идентификаторов с префиксом `video_`: поле `training_data_license` обязательно, а `approved_for_install = true` допускается только при `modelApprovalGate(...).eligible`. Для прежних идентификаторов поведение **не меняется** (их тесты остаются зелёными).
4. Для `video_*` в `backends` добавляется ключ `mlx` (по D-06; сочетается с `VID-WP-03`).
5. Capability `detect_cuts.methods` строится из замка: `classic` всегда; `model` — только если запись `approved_for_install` и прошла квалификацию на соответствующем бэкенде.

### 7.2 SBOM ([`release/sbom.cdx.json`](../../release/sbom.cdx.json), формат CycloneDX)

Гейт лицензий (TK-921) читает компоненты SBOM, вычисляет `licenseVerdict(…, 'code')` и завершается кодом 1 при любом компоненте с вердиктом, отличным от `allow` (`conditional`, `review`, `deny`), без действующего исключения; для `deny` исключение недопустимо. Исключение — запись в `release/license-waivers.json`: `component`, `version`, `accepted_verdict`, `reason`, `approver` (непустое имя), `approved_on`, `expires_on`; запись без утверждающего или просроченная недействительна. Первый прогон на текущем SBOM входит в `TK-001` (V0): найденное либо заменяется, либо получает исключение.

### 7.3 Сборка ffmpeg

1. Рецепт сборки образа `deploy/images/ffmpeg-lgpl/` фиксирует версию, SHA-256 исходников и флаги. Обязательные: `--disable-gpl --disable-nonfree --enable-version3 --enable-ffnvcodec --enable-nvenc` (для cuda-образа; `--enable-videotoolbox` для macOS), `--enable-shared`; запрещённые перечислены в FN-X-02.
2. Тест сборки (TK-922) выполняет `ffmpeg -buildconf` → FN-X-02 с профилем `lgpl` → `ok`; затем проверяет **наличие** необходимого: фильтры `lut3d`, `xfade`, `fade`, `crop`, `scale`, `fps`, `concat`, `split`, `format`, `loudnorm`, `ebur128`, `sidechaincompress`, `alimiter`, `amix`, `afade`, `atrim`, `asetpts`, `aresample`, `volume`; кодировщики `aac`, `mjpeg`, `pcm_s16le` и (по образу) `h264_nvenc` или `h264_videotoolbox`; демультиплексоры/мультиплексоры `mov`, `mp4`, `image2`, `wav`. Список — минимум и расширяется вместе с `compile_graph` ([07](07-timeline-edl-and-render-spec.md)).
3. Если нужного фильтра нет в LGPL-сборке (часть фильтров FFmpeg GPL-only ✔ по LICENSE.md), его **не** включают через `--enable-gpl`: функциональность реализуется иначе (`numpy`) либо убирается из V1. Тест показывает, какой именно фильтр отсутствует.
4. Вывод `ffmpeg -L` (текст лицензии сборки) сохраняется в артефакте образа и в `render_fingerprint`.

### 7.4 Сканирование образа

Тест (TK-922) ищет в образе воркера все файлы `libavcodec*`, `libavformat*`, исполняемые `ffmpeg`/`ffprobe`, в том числе внутри каталогов `site-packages` (колёса `av`, `cv2`, `imageio_ffmpeg`, `decord`), и для каждого проверяет строку конфигурации (`strings … | grep -- '--enable-'`) через FN-X-02. Единственный допустимый результат — собственная сборка; любая другая находка = провал.

## 8. VID-WP-18. Собственные веса детектора (условный пакет)

Назначение: получить веса ML-01 с `eligible = true`. Пакет **не для слабой модели**: выполняет ML-инженер; слабой модели достаются карточки TK-923 и проверки.

1. **Исходные данные:** только источники с вердиктом `allow` для `data` (раздел 3.6). Каждый ролик — запись манифеста `workers/training/video_boundary/manifest.json`: `id`, `source_url`, `license_page_url`, `license` (SPDX или `LicenseRef-*` из таблицы 2.2), `author`, `sha256`, `retrieved_on`, `split` (`train`/`val`/`test`). Проверка: все `license` дают `allow` (FN-X-01, `kind=data`); тестовая часть не пересекается с обучающей.
2. **Метод:** обучающий код TransNet V2 (MIT) без изменений архитектуры; синтетические склейки (резкая, растворение разной длины) из плана, как в статье: 85 % синтетических, 15 % реальных ✔ (в статье это соотношение для IACC.3/ClipShots); реальные переходы — только из собственных или разрешённых материалов, размечаются вручную. Время обучения в статье — около 17 часов на одной Tesla V100 ✔; основная трудоёмкость — сбор и разметка чистых данных, которых меньше, чем у авторов.
3. **Приёмка:** F1 по правилам [16](16-test-logic.md), раздел 6, на тестовой части, не участвовавшей в обучении; паритет бэкендов; запись замка с `weights_license = LicenseRef-Own-Work`, `training_data_license` = выражение из манифеста, `notices` = ссылка на манифест и NOTICE с авторами CC-BY (условие атрибуции).
4. **Если порог F1 не достигнут:** ML-01 остаётся недоступным, продукт работает на ML-02. Это допустимое состояние, а не блокер выпуска.
5. Остаточный риск: вопрос о том, считаются ли веса производной работой от CC-BY-материалов, не имеет однозначного ответа; риск ниже, чем у весов с неустановленными данными, но решение остаётся за юристом (в Q-03).

## 10. Требования, тесты, критерии

| ID | Требование |
|---|---|
| VID-LIC-01 | `licenseVerdict`, `modelApprovalGate`, `ffmpegBuildVerdict` дают результаты `vectors/license.json` (48 + 14 + 20 кейсов) во всех реализациях. |
| VID-LIC-02 | Гейт SBOM завершается ошибкой при любом компоненте с вердиктом, отличным от `allow`, без действующего исключения (для `deny` исключений нет); исключение без утверждающего или просроченное недействительно. |
| VID-LIC-03 | Запись замка для `video_*` не может быть утверждена без `training_data_license` и при `eligible = false`; тесты прежних моделей не затронуты. |
| VID-LIC-04 | Образы воркера содержат только LGPL-сборку ffmpeg, проходящую FFmpeg-проверки раздела 7.3; обязательный набор фильтров и кодировщиков присутствует. |
| VID-LIC-05 | В образе нет ни одной сторонней сборки `libavcodec`/`ffmpeg`, не прошедшей FN-X-02. |
| VID-LIC-06 | `detect_cuts.methods` в capability отражает только методы с утверждённой записью замка; без неё доступен `classic`, и вызов с `method = model` отклоняется кодом `VIDEO_METHOD_UNAVAILABLE`. |

Тесты и карточки: TK-920…925 ([15](15-task-cards.md), раздел 11), критерии ACC-57…ACC-62 ([17](17-acceptance-and-dod.md)), строки `license.json` в [16](16-test-logic.md). Пересчёт векторов: `python3 -I vectors/reference/ref_license.py > vectors/license.json` (напоминание: векторы проверяют соответствие тексту, а не правильность юридических выводов).
