# 18. Варианты использования (use cases)

Статус: спроектировано, не реализовано (2026-10-22). Начало: [README](README.md). Основа для сквозных (e2e) тестов; пошаговые сценарии — [19](19-user-flows-e2e.md). Экраны — [03](03-photographer-screens.md), API — [04](04-data-model-and-api.md), коды ошибок — [13](13-data-structures.md) (DS-24), критерии — [17](17-acceptance-and-dod.md).

## 1. Участники и права

| Код | Участник | Права и особенности |
|---|---|---|
| A-OWN | Фотограф-владелец | полный доступ к проекту и квоте; создаёт выдачи |
| A-EDT | Сотрудник с правом `edit` | всё, кроме управления тарифом и квотой |
| A-VWR | Сотрудник только с правом чтения | видит медиатеку и монтажи, любые действия записи скрыты и объяснены |
| A-OTH | Пользователь другого tenant | не должен видеть ничего из чужих данных (неотличимо от «не найдено») |
| A-CLI | Клиент (портал) | открывает ссылку выдачи; смотрит, скачивает; не авторизован в приложении |
| A-ADM | Администратор платформы | включает capability `video` для tenant, kill switch, лимиты |
| A-WRK | Воркер | не человек; его поведение проверяется в сценариях сбоев |

## 2. Тестовое окружение и данные (общие предусловия)

| Код | Что | Как создаётся |
|---|---|---|
| ENV-1 | Стенд: PostgreSQL, MinIO, RabbitMQ, Go API, один CPU-воркер видео (и опционально GPU/MLX-воркер) | `make dev-infra`, сборка и запуск сервисов; воркер с `PHOTO_WORKER_BACKEND=cpu` |
| ENV-2 | Web-сборка приложения фотографа | `cd apps/photographer && npx expo export --platform web` и раздача статики; портал: `cd apps/portal && npm run build` |
| TEN-A | Tenant A: пользователи `owner@a`, `editor@a`, `viewer@a`; capability `video` включён; квота 100 ГиБ; проект `P1` | сидирование через существующие админ-функции/SQL-фикстуры стенда |
| TEN-B | Tenant B: пользователь `owner@b`; проект `P2` | то же |
| TEN-C | Tenant C: `video` **выключен** | то же |
| FX-VID | `hard_cuts.mp4` (150 кадров, склейки 50, 100), `dissolve.mp4`, `fades.mp4`, `srcA.mp4`, `srcB.mp4` | [16](16-test-logic.md), раздел 5 |
| FX-AUD | `music.wav`: синус 440 Гц, 20 с, 48 кГц (`sine=frequency=440:duration=20`) | ffmpeg |
| FX-LUT | `warm.cube` (валидная 17³), `bad.cube` (17³ без одной строки) | [`cube_cases.json`](vectors/cube_cases.json) |
| FX-BAD | `random.bin` (1 МиБ случайных байт), `trunc.mp4` (первые 1000 байт `hard_cuts.mp4`) | генерируется тестом |
| FX-BIG | синтетический файл 1 ГиБ (`байт i = i mod 251`); для релизного прогона — 16 ГиБ | генератор в тесте |
| FX-PHOTO | 3 готовых фото в проекте `P1` | существующие фикстуры фото-потока |

Сброс между сценариями: каждый сценарий создаёт **свой** проект (или префикс имён с уникальным суффиксом прогона) и в конце удаляет созданное через публичные эндпоинты; общие tenants не пересоздаются. Сценарии, меняющие лимиты квоты, используют отдельный tenant `TEN-Q` (квота задаётся при создании).

## 3. Каталог вариантов использования

Формат: **Цель · Участник · Предусловия · Основной поток (номера шагов в [19](19-user-flows-e2e.md)) · Альтернативы/ошибки · Постусловия (проверяемые)**.

### Блок U — загрузка и медиатека

**UC-01. Загрузить видео.** A-OWN/A-EDT · TEN-A, `video` включён, место есть · поток F-01 · альтернативы: UC-02, UC-03, UC-04, UC-05 · постусловия: медиа `ready`; `used` вырос на фактические байты оригинала + производных; резерв закрыт; оригинал побайтно равен загруженному.
**UC-02. Возобновить прерванную загрузку.** вкладка закрыта/сеть пропала на середине · поток F-02 · постусловия: те же, что UC-01; повторно передано ≤ числа частей «в полёте».
**UC-03. Отказ из-за нехватки места.** квота мала · F-03 · постусловия: ни сессий, ни резервов, ни объектов; `used/reserved` не изменились.
**UC-04. Отклонённый файл.** `random.bin`, `trunc.mp4` · F-04 · постусловия: `rejected` с кодом (`VIDEO_UNSUPPORTED_FORMAT` / `VIDEO_CORRUPT`); квота восстановлена; объект удалён.
**UC-05. Отмена загрузки.** пользователь жмёт «Отменить» · F-05 · постусловия: сессия `aborted`; резерв освобождён; части удалены.
**UC-06. Загрузить аудио (музыку).** `music.wav` · F-01 (вариант «аудио») · постусловия: медиа `kind=audio`, `ready`, есть волна, нет proxy.
**UC-07. Загрузить LUT.** `warm.cube` / `bad.cube` · F-18 · `bad.cube` → отказ `VIDEO_UNSUPPORTED_FORMAT` (внутренне `LUT_INVALID`) без списания.
**UC-08. Просмотреть медиатеку.** все роли с чтением · F-06 · пусто/список/пагинация; A-VWR не видит кнопок записи.
**UC-09. Открыть карточку исходника.** F-07 · плеер играет proxy; видны раскадровка, волна, таблица probe, предупреждения.
**UC-10. Удалить медиа.** F-08 · альтернативы: медиа используется в монтаже (диалог со списком, подтверждение) · постусловия: клипы монтажа помечены «источник удалён»; квота освобождается после физического удаления.

### Блок D — детекция границ

**UC-11. Запустить детекцию.** F-09 · диалог показывает только доступные бэкенды с причиной недоступных; создаётся ровно одно задание; резерв квоты.
**UC-12. Проверить и принять границы.** F-10 · порог уверенности фильтрует; принять/отклонить; применение → новая ревизия монтажа с разрезами.
**UC-13. Повторное применение.** F-10 (шаг повтора) · документ не меняется.
**UC-14. Детекция при недоступном бэкенде.** F-11 · TEN-C или бэкенд без квалификации → `CapabilityNotice` с реальной причиной; запуск невозможен.

### Блок E — монтаж

**UC-15. Создать монтаж.** F-12 · допустимые fps/разрешения; создаётся пустая ревизия 0/1.
**UC-16. Собрать черновик.** добавить клипы из бина, фото, разрезать, обрезать, переместить, удалить (с закрытием зазора), скорость, переход · F-13 · автосохранение; ревизии растут; индикатор «сохранено».
**UC-17. Отменить/вернуть правку.** Ctrl/Cmd+Z, Shift+Z · F-13.
**UC-18. Конфликт ревизий.** два окна, одно сохраняет первым · F-14 · второе получает диалог, правка не теряется, возможно «сохранить как копию».
**UC-19. Работа офлайн.** F-15 · черновик на устройстве; при возврате сети — одно сохранение.
**UC-20. Дублировать и архивировать монтаж.** F-12 (вариант).
**UC-21. Монтаж с недоступным источником.** источник удалён · F-16 · клип с пометкой; «Рендер» заблокирован списком причин.

### Блок C/A — цвет и звук

**UC-22. Цветокоррекция клипа.** базовые параметры, кривые, колёса, LUT · F-17 · превью-кадр от воркера; метка «устарело» на время ожидания; значение вне диапазона отвергается.
**UC-23. Авто-подбор цвета.** F-17 (ветка) · предложение не применяется молча.
**UC-24. Музыка и звук.** трек, сдвиг, обрезка, громкость, ducking, цель LUFS, декларация прав · F-19.

### Блок R — рендер

**UC-25. Отрендерить монтаж.** F-20 · пресет, оценка, блокеры, задание, готово, проверка QC.
**UC-26. Отменить рендер.** F-21 · ≤ 10 с, без остатков.
**UC-27. Рендер при сбое воркера.** F-22 · один результат, одно списание.
**UC-28. Рендер превышает резерв / нет места.** F-23.
**UC-29. Повторить неудачное задание.** F-24.

### Блок S — выдача клиенту

**UC-30. Создать выдачу.** F-25 · выбор `ready`-рендеров; срок; секрет; скачивание вкл/выкл; лимит трафика.
**UC-31. Клиент смотрит и скачивает.** A-CLI · F-26.
**UC-32. Снять с публикации / отозвать / продлить / сменить секрет.** F-27.
**UC-33. Ссылка с истёкшим сроком / лимитом трафика.** F-28.
**UC-34. Статистика выдачи.** F-29 · счётчики совпадают с событиями трафика.

### Блок Q/Z — квоты, права, безопасность, администрирование

**UC-35. Просмотр квот и хранилища.** F-30 · разбивка по категориям, резервы, трафик.
**UC-36. Видео выключено для tenant.** TEN-C · F-11 · пункты меню и карточка «Видео» скрыты; прямой URL → экран «недоступно».
**UC-37. Ограничения прав.** A-VWR · F-31 · записывающие действия отсутствуют/заблокированы с объяснением; API-вызов от имени A-VWR → 403.
**UC-38. Изоляция tenant.** A-OTH · F-32 · любые чужие идентификаторы → «не найдено».
**UC-39. Kill switch.** A-ADM · F-33 · новые задания и выдачи отказывают; существующие ссылки перестают работать на следующем запросе; данные целы.
**UC-40. Смена языка.** EN/RU/BG · F-34 · все видео-экраны и ошибки локализованы; язык сохраняется при навигации.
**UC-41. Восстановление после перезагрузки страницы.** F-35 · очередь загрузок, черновик монтажа, наблюдение за заданием восстанавливаются.
**UC-42. Нагрузка и конкуренция.** две загрузки + рендер + фото-операция одновременно · F-36 · нет взаимных блокировок; квота согласована.
**UC-43. Достигнут лимит заданий.** A-OWN/A-EDT · лимит группы или суточный бюджет исчерпан · F-37 · `VIDEO_TENANT_LIMIT` с названием лимита; нет нового задания, резерва, списания бюджета; после завершения задания повтор проходит.
**UC-44. Система загружена.** пул перегружен · F-38 · `VIDEO_CAPACITY_BUSY`, обратный отсчёт из `retry_after_s`, автоповтора нет; предпросмотр кадров работает.
**UC-45. Быстрая правка цвета.** F-39 · серия изменений параметров даёт один запрос предпросмотра; предыдущий ожидающий отменён.
**UC-46. Лимит сохранений монтажа.** F-40 · при превышении `AUTOSAVE_RATE` черновик остаётся локально и сохраняется после паузы без потери правок.
**UC-47. Собрать монтаж мышью.** A-OWN/A-EDT · монтаж с двумя видео и фото · F-41 · альтернативы: перенос на занятое место откатывается без ревизии; заблокированная дорожка не меняется · постусловия: каждая ревизия соответствует жесту таблицы [23](23-editor-playback-timeline.md) §9; каждое действие — один шаг отмены.
**UC-48. Просмотреть монтаж с переходами.** F-42 · альтернативы: источник недоступен → клип помечен, остальное играет · постусловия: стыки без остановок при готовых источниках; на переходе видны оба клипа; на паузе — точный кадр.
**UC-49. Клавиатура и инспектор.** F-43 · постусловия: клавиши таблицы [23](23-editor-playback-timeline.md) §10 дают ожидаемые изменения; изменение поля инспектора — одна ревизия, значение вне диапазона — без ревизии.
