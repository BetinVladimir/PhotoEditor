## 1. Допущения

| № | Допущение | Статус | Доказательство | Следствие для плана |
|---|---|---|---|---|
| A-1 | Lease задачи можно продлевать heartbeat на часы | **подтверждено частично** | Heartbeat и продление есть: `photo.heartbeat_task(...)` (`backend/db/migrations/00015_task_leases.sql:102`), воркер шлёт heartbeat каждые `heartbeat_seconds` ≤ 10 и продлевает аренду каждые `renew_seconds` ≤ 10 (`workers/photo_worker/runtime/capacity_policy.py:41-44`, `runtime/service.py:911,929`); потеря аренды → `LEASE_LOST` (`runtime/gateway.py:135`). Верхней границы длительности задачи не нашёл, но она не проверялась ни тестом, ни нагрузкой: поведение на задаче в часы **не доказано** | `TK-214` (условная) оставить в плане: добавить тест «задача 6 ч держит lease» на стенде. Не считать ограничением до измерения |
| A-2 | Gateway читает объект потоково и поддерживает чтение диапазона | **подтверждено с ограничением** | `ObjectReader.Open/OpenRange` (`backend/internal/gateway/download.go:22-25`), `Accept-Ranges: bytes` (`:137`), `Content-Range` (`:108`). Ограничение: `maxRangeBytes = 16 MiB` на один запрос, суффиксные, множественные и неограниченные диапазоны отклоняются (`:27-40`) | Для воркера (чтение больших исходников) Range пригоден порциями ≤ 16 МиБ; для стрима клиенту — отдельный прокси портала (`TK-7xx`), gateway не годится «как есть». Новый лимит видео-профиля — в WP-02 |
| A-3 | MinIO поддерживает контрольные суммы частей multipart | **не подтверждено** | `multipart.go:157-164` завершает multipart по `PartNumber` + `ETag`, `ChecksumSHA256` частей не используется; sha256 всего объекта считается после загрузки чтением (`multipart.go:220-234`). Образ MinIO — `${MINIO_IMAGE}` «source-built», версия в репозитории не зафиксирована (`deploy/compose.yaml:92-93`) | Использовать запасной путь из [05](05-storage-quota-retention.md): проверка хеша на ingest. Поддержку частичных контрольных сумм в закреплённом образе проверить отдельным прототипом (`не проверено: нужен запуск стенда`) |
| A-4 | Реестр операций допускает пул/класс «видео» | **не подтверждено** | В `docs/implementation-v2/contracts/operations.json` `execution_pool` принимает значения только `cpu` (26), `gpu` (11), `signer` (1); `resource_class` — `cpu`/`gpu`. Класса «видео» нет | Нужно расширить реестр и политику ёмкости (WP-02, `TK-906`); карточка обязательна, не условна |
| A-5 | Расширение `holder_type` резервов и `output_role` не ломает биллинг | **подтверждено частично** | `quota_reservations.holder_type` — `text NOT NULL` без CHECK-перечисления (`00004_ingest_sharing.sql:127`); значение `'upload'` используется в логике функций (`00079_upload_failure_accounting.sql:9`, `02641_…:32`). Перечисляющего CHECK для `output_role` не найдено | Расширение вероятно без DDL, но логика биллинговых функций (`02598–02609`, `026*`) может фильтровать по `holder_type`. Перед `TK-107` выполнить шаги инспекции карточки; изменения — отдельным коммитом по правилам billing (R9, R11, R16, R33). Согласовать с владельцем биллинга |
| A-6 | `share_links`/сессия портала допускают `content_kind` без изменения защиты | **не подтверждено** | `share_links` связаны FK с `collections (tenant_id, collection_id)` (`00010_constraints_security.sql:93`); поля `content_kind` в репозитории нет (`grep content_kind` по `backend/internal/portal` и миграциям — пусто). Портал работает на уровне `collection_id`/`share_id` (`backend/internal/portal/service.go:52,102`) | Нужен отдельный разбор безопасности в WP-13 перед `TK-106/112/210`: новая колонка на `collections` со значением по умолчанию `'photo'` не меняет существующие проверки, но ответы портала должны ветвиться по `content_kind` |
| A-7 | MLX поддерживает нужные операции с достаточной скоростью | **не проверено** | Требует прототипа на Apple Silicon; в репозитории MLX отсутствует (бэкенды `cpu/cuda/mps`, `workers/photo_worker/models/backend_support.py`) | Решение откладывается на этап 4; запасной вариант — `mps`/ONNX на Mac или `mlx` как явно недоступный |
| A-8 | Лимит одновременных NVENC-сессий позволяет заданную параллельность | **не проверено** | Нужен стенд RTX | Замер в этапе 1 (WP-03); пока параллельность рендера — 1 |
| A-9 | Лицензии библиотек и весов (включая данные обучения) пригодны для коммерции | **не проверено** | Гейта SBOM (`TK-921`) ещё нет, `scripts/`/`tools/` не содержат проверки лицензий; юридическая проверка не проведена | V1 не зависит от сторонних весов (D-18) — риск снижен, но не закрыт; решение за юристом |
| A-10 | `expo-video` работает с текущей версией Expo | **не подтверждено** | В `apps/photographer/package.json` Expo SDK `~57.0.30`, RN `0.86.3`; **`expo-video` не установлен** (из `expo-*` есть только `document-picker`, `file-system`, `router`, `secure-store`) | Зависимость добавляется картой экрана V-03; перед этим — прототип нативной сборки (`не проверено: нужен запуск`). Правило «не добавлять зависимости вне карточки» — добавление только по карточке |
| A-11 | `activeWorkers`/`poolAheadCost` доступны из отчёта ёмкости | **не подтверждено** | Идентификаторы `activeWorkers`, `poolAheadCost` в коде и документах (`backend`, `workers`, `docs/implementation-v2`) отсутствуют. Есть документ ёмкости (`18-capacity-operations.md`, `ComputeScaleDecision`) и `resource_slots/resource_reservations` | Использовать запасной путь ТЗ: `poolAheadCost` — запрос по `video_jobs`, `activeWorkers = 1` (`TK-903`) |
| A-12 | Планировщик умеет задержку перед повторной выдачей | **подтверждено** | `photo.tasks.next_attempt_at`, состояние `retry_wait`, индекс по `(tenant_id, state, next_attempt_at, id)` (`00015_task_leases.sql:201,223`; `00010_constraints_security.sql:475`) | Условная часть `TK-409` не нужна: задержку использовать готовую |
| A-13 | Условия пула H.264 допускают схему «рендерим, клиент скачивает» без платы | **не проверено** | Юридический вопрос (Q-16) | Блокирует внешнюю выдачу, не разработку; H.264 только через аппаратные кодировщики |
| A-14 | Чекпойнты Beat This! лицензированы для коммерции | **не проверено** | Нужно прочитать репозиторий модели и написать авторам; в этой проверке сеть не использовалась | Основной алгоритм темпа ML-04 — `numpy/scipy` (D-21), модель не нужна для V1 |
