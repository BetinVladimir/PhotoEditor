# 07. Документ монтажа и спецификация рендера

Статус: спроектировано, не реализовано (2026-10-22). Начало: [README](README.md). Этот документ — единственный источник формата данных монтажа для клиента (`packages/api-client/src/video-timeline.ts`), бэкенда (проверка и сохранение ревизий) и воркера (компиляция графа). Любое расхождение трёх реализаций считается дефектом.

## 1. Принципы

1. **Недеструктивность.** Документ ссылается на источники по идентификатору и SHA-256, не содержит данных пикселей и звука.
2. **Целочисленное время.** Все позиции и длительности — целые «тики» (раздел 2); плавающей арифметики во времени нет.
3. **Каноническая форма.** Документ сериализуется по RFC 8785 (JCS), SHA-256 канонических байтов — `document_sha256`. В репозитории канонизация уже используется: [`packages/api-client/src/canonical.ts`](../../packages/api-client/src/canonical.ts), [`backend/internal/canonical`](../../backend/internal/canonical), `rfc8785` в [`workers/pyproject.toml`](../../workers/pyproject.toml).
4. **Неизменяемые ревизии, изменение через CAS** ([04](04-data-model-and-api.md), раздел 2.3), по образцу рецептов редактора ([`editor-store.ts`](../../apps/photographer/src/editor-store.ts)).
5. **Замороженный рендер.** Рендер выполняется по конкретной ревизии и замороженному замыканию источников; последующие правки не влияют на уже запущенный рендер.
6. **Единая математика.** Генерация 3D-LUT и преобразования кадра — один код в воркере для превью-кадров и рендера.

## 2. Время

- `ticks_per_second = 705 600 000`. Значение делится нацело на кадр любой из частот 24, 25, 30, 50, 60, 24000/1001, 30000/1001, 60000/1001 и на длину отсчёта звука при 44 100 и 48 000 Гц, поэтому все привычные границы кадров и отсчётов — целые.
- Максимальная длительность 3 часа = 7.6·10¹² тиков < 2⁵³: безопасно для JSON-чисел и `number` в TypeScript; `BigInt` не требуется.
- Позиция видеоклипа на таймлайне и его длительность кратны тикам кадра таймлайна; `src_in` приводится к сетке кадров источника — допустимое отклонение до 1 кадра (редактор привязывает, валидатор отклоняет большее).
- Кадр таймлайна `n` соответствует моменту `n · fps.den · tps / fps.num` тиков (целое по построению для перечисленных частот).

### 3.1 Источники

| `source.kind` | Ссылка | Заметки |
|---|---|---|
| `video` | `media_id` + `sha256` оригинала | рендер читает оригинал (не proxy) |
| `audio` | `media_id` + `sha256` | |
| `photo` | `asset_version_id` + `sha256` версии | берётся выбранная версия из существующей системы активов проекта ([`backend/internal/asset`](../../backend/internal/asset)); цвет/ICC по существующим правилам |
| `lut` (в эффекте) | `media_id` + `sha256` | файл `.cube`, проверенный `video.lut_validate`; в таблице `video_media` значение `kind` расширяется до `video|audio|lut` |

Рендер завершается ошибкой `VIDEO_SOURCE_MISSING`, если хеш источника не совпадает с ранее зафиксированным.

### 3.2 Эффекты

| Тип | Параметры (диапазоны) | Математика |
|---|---|---|
| `color.basic` | `exposure_ev` [−5; 5], `temperature` [−100; 100], `tint` [−100; 100], `contrast` [−100; 100], `highlights`/`shadows`/`whites`/`blacks` [−100; 100], `saturation`, `vibrance` [−100; 100] | операции в линейном свете с фиксированным порядком; сворачиваются в LUT |
| `color.cdl` | `slope`, `offset`, `power` (по каналам), `saturation` | ASC CDL; «колёса» lift/gamma/gain — интерфейс над CDL |
| `color.curves` | `master`, `r`, `g`, `b`: 2–16 точек, `x` строго возрастает в [0; 1] | монотонная кубическая интерполяция (PCHIP), 4096 узлов |
| `color.lut3d` | `lut` (источник), `intensity` [0; 1] | 3D-LUT размерности 17…65, `DOMAIN_MIN/MAX` по спецификации `.cube`; смешивание с тождественным преобразованием по `intensity` |
| `color.match` | результат авто-подбора записан как `color.cdl`/`color.curves`; ссылки на кадры-образцы хранятся в `meta` для объяснения | живой зависимости от эталона нет |
| `audio.gain`, `audio.fade` | `gain_db` [−60; 24], `fade_*` в тиках | кривая fade — линейная (`afade` по умолчанию); звуковой кроссфейд — линейный: пара `afade … curve=tri` (выход A, вход B), [24](24-render-compiler.md) D-45 ([23](23-editor-playback-timeline.md), D-28) |
| `audio.duck` | `sidechain_tracks`, `threshold_db`, `depth_db` [0; 40], `attack_ms`, `release_ms` | `sidechaincompress` с фиксированными параметрами |
| Мастер-громкость | `target_lufs` [−30; −9], `true_peak_db` [−6; 0] | двухпроходный `loudnorm` + `alimiter` |

Порядок эффектов клипа сохраняется; порядок свёртки в LUT определён: `basic → cdl → curves → lut3d`, затем по порядку списка для повторов. Неизвестный тип эффекта — отказ валидатора (схема закрыта: неизвестные ключи отклоняются, как в [`schemas/config.schema.json`](../../schemas/config.schema.json)).

### 3.3 Переходы

`cut` (по умолчанию), `crossfade`, `dip_to_black`, `fade_in`/`fade_out` для крайних клипов. Длительность перехода не превышает половины меньшего из соседних клипов. Центрированному переходу нужны «запасные» кадры за краем клипов; при их нехватке рендер детерминированно сокращает переход до доступного и записывает это в план рендера (редактор показывает предупреждение при сохранении). Точное правило сокращения, общее для предпросмотра и рендера, — FN-E-02 ([23](23-editor-playback-timeline.md), раздел 3).

### 3.4 Скорость

Постоянная `speed = num/den ∈ [1/4; 4]`; изменение скорости меняет длительность клипа на таймлайне (`duration = (src_out − src_in)/speed`). Видео — повтор/пропуск кадров по ближайшему (`fps round=near`), без смешивания; звук — `atempo` с сохранением высоты тона.

## 4. Проверка документа

Выполняется одинаковыми правилами в клиенте (быстрая), бэкенде (обязательная) и воркере (перед рендером).

| ID | Правило |
|---|---|
| VT-01 | Схема закрыта; все числа целые там, где указаны тики; `schema_version` известна. |
| VT-02 | Размер канонического документа ≤ 8 МиБ; ≤ 4 видео- и ≤ 4 аудиодорожки; ≤ 2 000 клипов; длительность ≤ 3 ч. |
| VT-03 | Идентификаторы дорожек, клипов, эффектов, маркеров уникальны и соответствуют шаблону. |
| VT-04 | Клипы на одной дорожке не пересекаются, отсортированы по `at`; зазор допустим (чёрный кадр/тишина). |
| VT-05 | `0 ≤ src_in < src_out ≤ длительность источника` (сверяется по probe); `src_out − src_in > 0`. |
| VT-06 | Все источники принадлежат тому же tenant/project и находятся в состоянии `ready`; хеши совпадают. |
| VT-07 | Параметры эффектов в диапазонах раздела 3.2; кривые монотонны; LUT валиден. |
| VT-08 | Переходы не длиннее допустимого; переход на первом клипе дорожки допускается только `fade_in`. |
| VT-09 | `sidechain_tracks` ссылаются на существующие аудиодорожки и не образуют цикла. |
| VT-10 | При наличии аудиоклипа из пользовательских файлов, помеченного как музыка, `rights.music_declared = true` обязательна к рендеру (не к сохранению). |

Результат проверки сервера — список ошибок с путями JSON Pointer; клиент подсвечивает проблемные клипы.

## 5. Команды редактирования (клиентская модель)

Каждая операция редактора — команда над документом с обратной командой; сохранение отправляет итоговый документ (не журнал команд). Полный список с ошибками и обратными операциями: FN-T-05…10 ([14](14-function-catalog.md)) и FN-T-15…28 ([23](23-editor-playback-timeline.md), раздел 11). Обрезка со сдвигом (ripple trim) — V2.

Привязка (snap): к кадру; к краям клипов; к маркерам (`cut`, `beat`, пользовательским); к playhead. Порог — 8 экранных пикселей; выключается глобально клавишей N и временно удержанием Shift ([23](23-editor-playback-timeline.md), раздел 8).

`ApplyCuts` для каждой принятой границы находит клип-источник, содержащий её в диапазоне `src_in…src_out`, и делит клип; режимы: `split_at_start`, `split_at_middle` (для плавных переходов), `markers_only`. Повторное применение того же отчёта не создаёт дубликатов (разрезы вне диапазонов клипов игнорируются, разрез на существующей границе — no-op).

## 6. Компиляция в план рендера

Функция `compile_graph(document, preset, runtime) → render_plan` чистая и детерминированная ([06](06-workers-and-models.md), раздел 5.1). Правила:

1. **Раскладка**: чёрный холст и цепочка `overlay` по слоям, видеодорожки снизу вверх (`V1` — низ); пустые участки — фон; поля `fit` прозрачны; масштабирование `fit` (вписать с полями), `fill` (заполнить с обрезкой), `none`. Точные цепочки и порядок преобразований — [24](24-render-compiler.md), разделы 4–5.
2. **Частота кадров**: целевая частота пресета (по умолчанию — частота монтажа); преобразование источников — выбором ближайшего кадра, без смешивания.
3. **Цвет**: вход приводится к Rec.709 SDR с явным преобразованием по метаданным источника (HDR PQ/HLG → тональное отображение `zscale`+`tonemap=hable` с решением `HDR_TONEMAPPED`, [24](24-render-compiler.md) D-44); эффекты клипа и мастера сворачиваются в одну LUT на клип; промежуточные кадры — 8 бит `yuv420p` (10 бит и дизеринг — V2).
4. **Звук**: 48 кГц, стерео; моно → стерео `pan=stereo|c0=c0|c1=c0`; зазоры — тишина; звуковой кроссфейд — линейный (`tri`), D-28 в [23](23-editor-playback-timeline.md), реализация D-45 в [24](24-render-compiler.md).
5. **Фото**: масштабирование на суперсэмплированном холсте; позиция вычисляется целочисленной арифметикой в тиках, сглаживание `ease_in_out` = `3u² − 2u³` (FN-E-03, [23](23-editor-playback-timeline.md)).
6. **Строки графа** — только по [24](24-render-compiler.md) (FN-R-08…R-17); тексты G1/G2 в `vectors/golden_render.md` компилятор не определяют.
7. **Результат компиляции** — канонический JSON (граф, входы, параметры кодека, версии инструментов). Его SHA-256 — часть `render_fingerprint`.

Негативные случаи компиляции (должны давать явные ошибки, а не молчаливые значения): недоступный энкодер для запрошенного пресета, неподдерживаемая комбинация цветового пространства (`COMPILE_COLOR_UNSUPPORTED`), LUT неподходящей размерности, превышение лимита сложности графа (число одновременных слоёв > 8 в точке времени — `COMPILE_TOO_MANY_LAYERS`; входов > 128 — `COMPILE_TOO_MANY_INPUTS`), нет источника (`COMPILE_SOURCE_MISSING`), частота пресета ≠ частоты монтажа (`COMPILE_FPS_UNSUPPORTED`), пустой монтаж (`COMPILE_EMPTY`) — [24](24-render-compiler.md), раздел 8.

## 7. Превью-кадры

`video.preview_frames` получает ревизию и список моментов, находит клипы и эффекты, вызывает ту же функцию генерации LUT и преобразований, что и рендер, и возвращает JPEG sRGB (качество 90, длинная сторона ≤ 1280). Кэш на клиенте ключуется по `(document_sha256, момент, размер)`. Ответ с другим `document_sha256` отбрасывается как устаревший.

## 8. Проверка выходного файла

После кодирования рендер проходит проверку (`video_qc_report`): длительность в пределах ±1 кадра от `max(at + duration)`, ожидаемые потоки, полное декодирование, SHA-256, размер ≤ резерва, громкость ±0.5 LU. Ошибка проверки = ошибка рендера.

## 9. Требования

| ID | Требование |
|---|---|
| VID-T-01 | Клиент, бэкенд и воркер используют одну спецификацию документа; межъязыковые фикстуры (JSON-примеры + ожидаемые хеши) проходят во всех трёх реализациях (образец — [`delivery-metadata-crosslang.json`](../implementation-v2/contracts/delivery-metadata-crosslang.json)). |
| VID-T-02 | Каноническая сериализация и SHA-256 документа совпадают в TypeScript, Go и Python на наборе контрольных документов. |
| VID-T-03 | Правила VT-01…VT-10 реализованы одинаково; набор негативных документов отклоняется с одинаковыми кодами. |
| VID-T-04 | Все команды редактирования обратимы: применение команды и её инверсии возвращает байт-в-байт тот же канонический документ. |
| VID-T-05 | Компиляция графа детерминирована: один документ + пресет + версия среды → один и тот же план (golden-тесты). |
| VID-T-06 | Кадр превью и соответствующий кадр рендера расходятся в пределах допуска ΔE (стартово ≤ 1.0 до потерь кодека). |
| VID-T-07 | Сокращение переходов, приведение HDR, сжатие графа и любые другие неявные решения компилятора записаны в план рендера и показываются пользователю. |
