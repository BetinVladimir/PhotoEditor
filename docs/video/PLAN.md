## 2. Принципы исполнения

1. **Одна карточка за раз**; перед работой собрать пакет контекста: `python3 docs/video/tools/ctx.py TK-nnn` (бюджет окна 18 000 токенов; `--check` перед коммитом документов). Составные карточки (например `TK-606`) не выдавать — только их части.
2. **Тесты первыми** для функций с векторами `docs/video/vectors/*.json`; векторы — спецификация, красный тест = дефект кода, пока человек не подтвердил обратное.
3. **Нет значения — остановиться и спросить** (имя, лимит, цена, сигнатура). Ничего не изобретать.
4. **Один общий стенд** (PostgreSQL, MinIO, RabbitMQ): параллельные агенты не запускают конкурирующие установки.
5. **Пропущенный тест ≠ приёмка** (ffmpeg отсутствует → «не проверено», задача не закрыта).
6. Коммит — по карточке или связной группе; `git push` — только по явной просьбе.
7. UI — только React Native Paper (`paper-ui-policy.test.ts`); строки — ключи `video_<экран>_<элемент>` в трёх локалях EN/RU/BG.
8. Все числовые лимиты — стартовые значения в политике (`DS-01`), не константы кода.

## 3. Этапы и порядок

Граф зависимостей слоёв (из 12 §6): `0xx → {1xx, 3xx, 4xx}`, `1xx → 2xx`, `{3xx, 2xx} → 5xx → 6xx`, `2xx → 7xx`, `{6xx, 7xx} → 8xx`. Внутри этапа карточки без зависимостей можно вести параллельно.

### Этап 0 — Решения и разведка (VID-WP-00) — *блокирует всё*
- Исправить блокеры B-1…B-5.
- `TK-001` отчёт V0 (`docs/video/v0-report.md`): A-1…A-14, первый прогон лицензионного гейта, Q-16/Q-17.
- Независимая проверка формул (риск O-7): `FN-Q-09` (веса стоимости), классический детектор границ, пороги SLO.
- Прототипы: `expo-video` (A-10), MLX на Apple Silicon (A-7), лимит NVENC-сессий (A-8), сборка LGPL-ffmpeg 6.1.x.
- **Выход:** подписанные решения Q-01…Q-06, отчёт с измерениями, обновлённый список условных карточек.

### Этап 1 — Контракты, каркас, среда (WP-01, 02, 03, 18)
- `TK-002…005`: загрузчики векторов (TS/Go/Py), генератор фикстур ffmpeg, JSON-схемы + межъязыковые фикстуры, каркас локализации.

- **Выход:** один набор фикстур проходит TS/Go/Python; видео-задача не вытесняет фото; `doctor` зелёный.

## 8. Состояние реализации DEMO MVP (на 2026-11-04)

Реализован сквозной сценарий «загрузка → probe → монтаж → рендер → выдача», проверен e2e на локальной БД и на хосте с libx264.
Решение владельца: **монтажная студия остаётся веб-редактором** (в согласии с Q-11 — нативный редактор не в V1); экраны в `apps/photographer` не переносятся.
Страница клиента — в `apps/portal` (`/{locale}/v/{share_id}`).

**Миграции 02699–02711** (после `02698`; отступление от §«очереди»: видео использует собственную очередь `photo.video_jobs`, а не общую `tasks`):

| 02703 | функции воркера: `register_video_artifact`, `get_video_job_inputs` |
| 02704–02705 | чтение для API и зрителя |
| 02706 | исправление `exchange_share_session` (двусмысленность `tenant_id`, ломала обмен любой ссылки) |
| 02707 | возврат зависших завершений загрузки, список выдач/ссылок |
| 02708 | двухфазное снятие медиа (FN-D-13) |

| 02710 | аренды трафика зрителя (FN-D-19/20), учёт просроченных аренд |

**Код:** `backend/internal/video/{probe,render,worker,api}`, `backend/cmd/video-demo` (dev-сервер и веб-студия, только loopback), `apps/portal` (страница клиента).

**Не реализовано / решения впереди:**
- FN-D-18 `set_video_tenant_limits` — спецификация требует роль `photo_admin`, которой нет в миграциях; нужно решение, создавать ли её.
- Месячные партиции `video_egress_events` (FN-D-21): создание партиций требует владения таблицей; сейчас все события в `DEFAULT`-партиции.
- Многочастная загрузка в MinIO и подписанные URL (сейчас один `PUT`, локальный диск); SSE-прогресс.
- Реальная авторизация студии: веб-студия работает только через `cmd/video-demo` со встроенным пользователем; в `cmd/photo` маршруты API зарегистрированы, но свипер и полный прогон с авторизацией/CSRF не подключены.
- Видео-эндпоинты не описаны в `packages/contracts` (нужны схемы в `docs/implementation-v2/contracts/schemas.json` и генерация); без этого экраны `apps/photographer` не пройдут `routes.test.ts`.
- NVENC не проверен (на хосте нет сборки ffmpeg с ним).
- Компилятор рендера — подмножество (канва, fit/fill, микс, обрезка); переходы, движение, скорость, LUT, ducking, двухпроходная громкость — нет.
- `baseline.sql` для чистой сборки БД после `02650`.
