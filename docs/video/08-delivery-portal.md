## 2. Решение (D-07)

**Видео-выдача — это коллекция с `content_kind = 'video'`**, опубликованная существующим механизмом, с существующими `share_links` и сессией портала. Для владельца это отдельные сущности «Видео-выдача» (экраны V-11/V-12), для БД — коллекция с элементами `video_collection_items` ([04](04-data-model-and-api.md), раздел 2.6). Преимущества: реиспользуются выпуск ссылки, секрет, срок, отзыв, CSRF, сессия, аудит и логика публикации; не создаётся параллельная система доступа.

Рассмотренные и отклонённые варианты: (A) отдельный `video_share` с собственной сессией — дубль безопасностной поверхности; (B) расширение фото-`delivery_packages` — пакеты завязаны на пресеты экспорта и подписание метаданных ([`01219_v30_delivery_storage.sql`](../../backend/db/migrations/01219_v30_delivery_storage.sql)), для видео избыточны; (C) прямые публичные URL MinIO — нарушает модель авторизации и отзыва.

Права ссылки видео-коллекции: `view`, `download`; `select` и гостевая загрузка (`upload`) для видео не допускаются в V1 (отказ на уровне `Authorize`). Выбор/утверждение клиентом и комментарии — V2.

## 3. Эндпоинты портала (предлагаемые)

Сессия и CSRF — как у фото (`POST /api/v1/portal/sessions`, заголовок `X-CSRF-Token`).

| Метод и путь | Назначение |
|---|---|
| `GET /api/v1/portal/collection` | существующий; ответ получает `content_kind` |
| `GET /api/v1/portal/videos?after=&limit=` | список видео-элементов: `id`, `title`, `duration_ticks`, `width`, `height`, `poster` (ссылка на миниатюру), `bytes`, `can_download` |
| `GET /api/v1/portal/videos/{id}` | карточка элемента |
| `GET /api/v1/portal/videos/{id}/poster` | подписанная ссылка на постер (≤ 60 с) |
| `GET /api/v1/portal/videos/{id}/stream` | **потоковое чтение с поддержкой `Range`** (раздел 4) |
| `POST /api/v1/portal/videos/{id}/download-intent` | намерение скачивания → общий `/api/v1/downloads/redeem` (как `items/{id}/download-intent` у фото) |

Ответы клиента проверяются на область (share, коллекция, элемент) и типизированы так же строго, как существующие `readCollection`/`readItems`.

## 4. Стриминг: ограничение и решение

Ограничение: подписанные ссылки живут ≤ 60 с (инвариант отзыва). Видеоплеер читает один ролик минутами, причём диапазонами; единая ссылка с длинным сроком нарушила бы инвариант.

**Решение V1 — аутентифицированный Range-прокси.** `GET …/stream` проверяет сессию портала, публикацию коллекции, срок и лимит трафика **на каждый запрос диапазона**, читает объект из MinIO и отдаёт `206 Partial Content`. Свойства: мгновенный отзыв доступа (следующий запрос диапазона получает отказ), точный учёт отданных байт, никаких долгоживущих URL. Контроль нагрузки: лимит одновременных потоков на сессию и на share, ограничение скорости по профилю, `Cache-Control: private, no-store`, защита от слишком мелких диапазонов, закрытие при отмене запроса клиентом.

Стоимость: трафик проходит через Go-сервис. Допустимо для V1 (малые студии, закрытый запуск). Масштабирование: режимы доставки `proxy` → `redirect` → `cdn`, триггеры перехода, числовые лимиты потоков и скорости, аренды бюджета трафика и воспроизведение proxy владельцем описаны в [20](20-saas-scaling-operations.md), разделы 5.2 и 6. CDN/edge со ссылками-куки малого срока и отзывом по ключам требует отдельного ТЗ; требование к переходу — измеренная нагрузка и сохранение мгновенного отзыва в допустимых пределах.

**Формат для стриминга**: отдельный «веб-вариант» результата — тот же H.264/AAC MP4 с `faststart` (первый вариант рендера сразу пригоден). Дополнительный пониженный вариант (720p) для просмотра создаётся опционально заданием `video.render` с пресетом «web preview»; он учитывается в квоте как производный. Нативный HLS откладывается в V2.

**Скачивание** идёт по существующему сценарию: намерение → `/api/v1/downloads/redeem` → подписанная ссылка ≤ 60 с на оригинал результата; байты учитываются как исходящий трафик. Многогигабайтные файлы скачиваются браузером напрямую по подписанной ссылке (один запрос), прерывания обрабатывает повторное получение намерения (механизм восстановления скачивания портала переиспользуется).

## 6. Управление выдачей владельцем

Экраны V-11/V-12 ([03](03-photographer-screens.md)) используют эндпоинты `video-deliveries` ([04](04-data-model-and-api.md)):

- Создание: выбор готовых рендеров; создаётся коллекция `content_kind = 'video'` в состоянии `draft`, затем публикуется явным действием `publish` (по аналогии с публикацией коллекции: CAS по `expected_revision`, без молчаливых изменений).
- Снятие с публикации: клиент теряет доступ на следующем запросе (диапазона или метаданных); подписанная ссылка скачивания, уже выданная, живёт ≤ 60 с.
- Отзыв ссылки и смена секрета: существующие операции `share_links`.
- Срок действия и лимит трафика ссылки проверяются на каждом запросе.
- Статистика: открытия сессий, просмотры (начало воспроизведения), скачивания, байты по видам — из `video_egress_events` и журнала сессий.

## 7. Жалобы и отключение

Администратор платформы может принудительно отключить ссылку или рендер (например, по жалобе на нарушение авторитетных прав) через [`backend/internal/admin`](../../backend/internal/admin); состояние «отключено администратором» отображается владельцу, клиенту — как недоступная ссылка. Сведения о причине не раскрываются клиенту.

## 8. Требования

| ID | Требование |
|---|---|
| VID-SH-01 | Видео-выдача использует существующие коллекции, `share_links` и сессию портала; отдельной системы доступа нет. |
| VID-SH-02 | Клиент по действующей ссылке может смотреть и (если разрешено) скачивать ролики; без секрета/после отзыва/истечения срока доступ невозможен, ответы не раскрывают существование объектов. |
| VID-SH-03 | Каждый запрос диапазона стрима повторно проверяет сессию, публикацию, срок, лимит трафика и принадлежность элемента; снятие с публикации действует на следующем запросе. |
| VID-SH-04 | Подписанные ссылки скачивания не живут дольше 60 с; повторная авторизация после подписи сохранена. |
| VID-SH-05 | Исходящий трафик стрима и скачивания учитывается по фактическим байтам и применяет лимиты (общий и на ссылку). |
| VID-SH-06 | Права `select` и гостевой `upload` для видео-коллекций отклоняются сервером. |
| VID-SH-07 | Портал показывает видео на EN/RU/BG, работает без данных в серверной оболочке и не раскрывает внутренние идентификаторы и пути. |
| VID-SH-08 | Параллельные потоки ограничены (`STREAMS_PER_SESSION` = 2, `STREAMS_PER_SHARE` = 4, скорость ≤ `STREAM_MAX_BYTES_PER_SECOND`); перегрузка отвечает `VIDEO_STREAM_LIMIT`, а не деградацией остальных клиентов портала. |
