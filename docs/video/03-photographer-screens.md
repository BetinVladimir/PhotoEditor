# 03. Экраны приложения фотографа (`apps/photographer`)

Статус: спроектировано, не реализовано (2026-10-22). Начало: [README](README.md). Данные и API — [04](04-data-model-and-api.md); загрузка и квоты — [05](05-storage-quota-retention.md); таймлайн — [07](07-timeline-edl-and-render-spec.md).

## 1. Правила построения экранов

Новые экраны строятся по схеме, уже принятой в приложении ([карта репозитория](../repository-layout.md), [Paper UI contract](../implementation-v2/photographer-paper-ui-contract.md)):

1. **Три файла на маршрут.** Экран живёт в `screens/video/…`; тонкая обёртка `app/video/….tsx` оборачивает его в `LegacyLocaleRoute`; зеркало `app/[locale]/video/….tsx` реэкспортирует экран (образец: [`app/deliveries/new.tsx`](../../apps/photographer/app/deliveries/new.tsx), [`app/[locale]/deliveries/new.tsx`](../../apps/photographer/app/[locale]/deliveries/new.tsx), [`screens/deliveries/new.tsx`](../../apps/photographer/screens/deliveries/new.tsx)). Логика и компоненты — в `src/video-*.ts(x)`.
2. **Параметры маршрута** — как у соседних экранов: `tenant`, `project` в query, идентификаторы объектов — сегменты пути. Все переходы — через [`localized-router`](../../apps/photographer/src/localized-router.tsx).
3. **Только Paper** для текста, кнопок, ввода, переключателей, диалогов, индикаторов: `Text`, `Button`, `TextInput`, `Switch`, `Modal`, `Pressable`, `Touchable*`, `ActivityIndicator` из `react-native` импортировать нельзя (проверяет [`paper-ui-policy.test.ts`](../../apps/photographer/src/paper-ui-policy.test.ts)). Диалоги — `Dialog` в `Portal`; нажимаемые области — `TouchableRipple`; прогресс — `ProgressBar`/`ActivityIndicator` из Paper. `react-native` остаётся для `View`, `ScrollView`, `FlatList`, `PanResponder`, `Platform`, `Image`; `SafeAreaView` — из `react-native-safe-area-context`. Цвета и шрифты — только из темы (`useTheme`, `variant`), общие элементы — из `src/ui` (ревью [ui-audit](../ui-audit/REPORT.md), план [PLAN.md](../ui-audit/PLAN.md)).
4. **Специализированные поверхности** (линейка таймлайна, колёса цвета, кривые, осциллограммы) — отдельные компоненты на `View`/`PanResponder`/SVG; каждая имеет парный числовой ввод на `TextInput` Paper и работу с клавиатуры (в Paper нет `Slider`).
5. **Состояния** обязательны на каждом экране: загрузка, пусто, ошибка, нет прав, отменено, восстановление после сбоя, офлайн, функция недоступна на сервере (`ReadResourceState` из [`read-resource-state`](../../apps/photographer/src/read-resource-state.tsx), `useReadResource`).
6. **Мутации**: `Idempotency-Key`, журнал попытки в `AsyncStorage` (как `*-attempt-store.ts`), `expected_revision`, `AbortController`, ограничение времени ожидания, без автоповтора неоднозначных POST — только явная сверка GET (правило из [collection-publication-contract](../implementation-v2/contracts/collection-publication-contract.md)).
7. **Платформы V1**: web (десктоп) — полный набор; планшет — просмотр, детекция, задания, выдача, ограниченный монтаж; телефон и нативные сборки — просмотр, задания, принятие результатов детекции, выдача; редактор таймлайна и цвет на узких экранах недоступны с понятной причиной (MVP ограничен web, см. [mvp-web-release-plan](../implementation-v2/mvp-web-release-plan-2026-10-20.md)).
8. **Доступность**: размер шрифта и контраст измеряются как на остальных экранах; клавиатурные сокращения в редакторе документируются и не конфликтуют с браузером; таймлайн экспортирует структуру клипов в доступное дерево (список клипов с позицией и длительностью).
9. **Локализация**: ключи `video_<экран>_<элемент>` в `locales/{en,ru,bg}/common.json`; тексты ошибок строятся по коду ошибки сервера.

Новая зависимость клиента `expo-video` нужна только для плеера V-03 в нативных сборках (допущение A-10). На web плеер V-03 и монитор редактора используют `<video>` напрямую ([23](23-editor-playback-timeline.md), D-24).

## 3. Описание экранов

### V-01. Медиатека видео проекта

- **Цель**: единая точка входа: все видео, аудио и монтажи проекта, статусы анализа, занятый объём.
- **Содержимое**: `Appbar` с названием проекта и `FAB` «Загрузить»; `SegmentedButtons` (Видео / Аудио / Фото / Монтажи); `Searchbar`; сетка `Card` с кадром-превью, длительностью, разрешением, `Chip` статуса (загружается / анализ / готово / отклонено / недоступно); блок «Хранилище» (`ProgressBar` + числа по категориям); `Banner`, если функция недоступна на сервере; список активных заданий (`List.Item` со ссылкой на V-10).
- **Действия**: открыть карточку (V-03), загрузить (V-02), создать монтаж (V-05/V-06), выбрать несколько и удалить (подтверждение в `Dialog`).
- **Данные**: `GET …/video/media?after=…&kind=…` (страницы с курсором, как галереи коллекций), `GET …/video/capabilities`, `GET …/video/usage`.
- **Состояния**: пусто («Загрузите первый ролик»); карточка в ingest показывает стадию и обновляется по SSE; отклонённое медиа показывает причину и не занимает квоту; нет права `edit` — действия записи скрыты и объяснены.
- **Файлы**: `src/video-library.tsx`, `src/video-media-card.tsx`, `src/video-usage-meter.tsx`, `src/video-capabilities.ts`, `src/video-media-list.ts` (клиент страниц и валидация ответа по образцу [`capture-list-contract.ts`](../../apps/photographer/src/capture-list-contract.ts)).
- **Тесты**: `video-library.dom.test.tsx` (пусто, список, пагинация, права, недоступность), `video-media-list.test.ts` (разбор ответа, отказ при неверной области tenant/project).

### V-02. Загрузка файлов

- **Цель**: надёжная загрузка нескольких крупных файлов.
- **Содержимое**: кнопка выбора (web: `input[type=file]` по образцу `pickWebArchive` в [`interchange-archive-screen.tsx`](../../apps/photographer/src/interchange-archive-screen.tsx)); очередь файлов: имя, размер, стадия (хеширование → загрузка → завершение → проверка), `ProgressBar`, скорость, оценка времени; кнопки «Пауза», «Продолжить», «Отменить»; предупреждения заранее: «не хватает места: нужно X, доступно Y», неподдерживаемый формат (по расширению — подсказка, окончательное решение после probe).
- **Поведение**: хеш SHA-256 считается потоково по срезам файла (`@noble/hashes` уже в зависимостях) с показом прогресса; загрузка частями с контрольными точками в `AsyncStorage`; после перезапуска вкладки очередь восстанавливается и предлагает выбрать тот же файл (сверка имени, размера, mtime и хеша — как `sameFile` в [`upload.ts`](../../packages/api-client/src/upload.ts)); «простой» без прогресса > 30 с останавливает попытку с возможностью продолжить (образец — таймер простоя в `interchange-archive-screen.tsx`).
- **API**: `video-uploads` begin / attempt-status / parts / complete / status / abort ([04](04-data-model-and-api.md)).
- **Состояния**: `aborted`, `expired` (нужен перезапуск), `reconciliation required` (кнопка «Проверить состояние»), квота исчерпана, нет сети.
- **Файлы**: `src/video-upload-screen.tsx`, `src/video-upload-controller.ts`, `src/video-upload-attempt-store.ts`, `src/video-upload-source.ts`, `packages/api-client/src/video-upload.ts`.
- **Тесты**: контроллер (возобновление, дубликаты частей, abort), хранилище попыток, DOM-тест очереди, регрессия «размер файла > 512 МиБ допускается только на видео-пути» (старый путь [`upload.ts`](../../packages/api-client/src/upload.ts) остаётся с прежним лимитом).

### V-03. Карточка исходника

- **Цель**: изучить исходник и запустить анализ.
- **Содержимое**: плеер на proxy (`src/video-player.tsx`); раскадровка и волна; таблица probe (контейнер, кодек, размер кадра, fps, цветовое пространство, длительность, битрейт, аудиодорожки); `Chip` предупреждений (VFR, HDR, поворот, нестандартная частота дискретизации); блок «Использование» (в каких монтажах); действия: «Найти границы склеек», «Анализ цвета», «Добавить в монтаж», «Удалить».
- **Запуск детекции**: `Dialog` параметров (режим, чувствительность, бэкенд — по списку доступных от сервера); показывается оценка времени и резерв квоты (для детекции мал: отчёт JSON).
- **Данные**: `GET …/video/media/{id}`; потоки proxy — подписанные ссылки или авторизованный Range ([08](08-delivery-portal.md) описывает схему для клиента; для владельца — те же правила).
- **Состояния**: идёт анализ (прогресс), анализ не удался (причина, «Повторить»), источник удалён/недоступен.
- **Файлы**: `src/video-media-detail.tsx`, `src/video-probe-table.tsx`, `src/video-filmstrip.tsx`, `src/video-waveform.tsx`, `src/video-detect-dialog.tsx`.

### V-04. Результат детекции границ склеек

- **Цель**: проверить и принять найденные границы.
- **Содержимое**: плеер с маркерами; полоса времени исходника с кандидатами (цвет и форма по типу: cut / dissolve / fade / flash); слайдер порога уверенности (пользовательский компонент + `TextInput`); список кандидатов (`FlatList` из `List.Item`): время, тип, уверенность, пара кадров «до/после» (миниатюры из отчёта); переключатели принять/отклонить; «Принять все выше порога»; «Применить к монтажу» → `Dialog` выбора назначения (новый монтаж / существующий / только метки).
- **Решения** хранятся на клиенте до применения; применение — идемпотентная мутация, создающая ревизию монтажа с разрезанными клипами (без нового рендера). Образец потока «решение человека»: [`interchange-prepared-review-screen.tsx`](../../apps/photographer/src/interchange-prepared-review-screen.tsx), [`import-mask-decision-attempt.ts`](../../apps/photographer/src/import-mask-decision-attempt.ts).
- **Состояния**: ноль границ; отчёт для другой версии исходника (отказ); задание отменено; результат метод=классический (пометка «резервный метод»).
- **Файлы**: `src/video-cuts-review.tsx`, `src/video-cut-report.ts` (разбор и проверка отчёта), `src/video-cut-apply-attempt-store.ts`, `src/video-range-control.tsx`.

### V-05. Список монтажей

- **Цель**: найти, создать, дублировать, архивировать монтаж.
- **Содержимое**: `List.Item` с превью, длительностью, временем изменения, последней ревизией и индикатором «есть неготовые источники»; создание (`Dialog`: имя, fps, разрешение, пресет); дублирование (новая последовательность от выбранной ревизии); архивирование.
- **Файлы**: `src/video-sequence-list.tsx`, `src/video-sequence-create-dialog.tsx`, `src/video-sequence-create-attempt-store.ts`.

### V-06. Редактор монтажа

**Нормативно:** геометрия, жесты, воспроизведение, звук, горячие клавиши, команды и инспектор — [23](23-editor-playback-timeline.md); при расхождении с этим разделом действует 23.

- **Цель**: нелинейный монтаж.
- **Раскладка (десктоп)**: слева бин (источники проекта: видео, аудио, фото; поиск, перетаскивание); сверху по центру монитор (плеер на proxy + безопасные зоны); справа инспектор (вкладки «Клип», «Цвет», «Звук», «Переход», «Скорость» — `SegmentedButtons`/`Tabs` Paper-совместимые); внизу таймлайн: линейка, дорожки, клипы с раскадровкой и волной, маркеры (границы склеек, биты, пользовательские), playhead; панель инструментов (`IconButton`): выбор, бритва, сдвиг, привязка, увеличение, undo/redo.
- **Операции редактирования**: добавить клип, разрезать, удалить, удалить с закрытием зазора, перетащить, обрезать начало/конец, изменить скорость, переход между клипами, дублировать, заблокировать/заглушить/скрыть дорожку, маркеры. Каждая операция — чистая функция над документом (команда) с обратной операцией; undo/redo — стек команд; сохранение — пакет команд → новая ревизия.
- **Воспроизведение**: монтаж целиком по proxy-колодам с предзагрузкой и переходами, звук — Web Audio по огибающим; приблизительно (без цвета, ducking и громкости), на паузе — точный кадр `video.preview_frames` ([23](23-editor-playback-timeline.md), разделы 3–6, D-27).
- **Сохранение**: автосохранение с задержкой и по границам операций; индикатор состояния («сохранено», «сохраняется», «конфликт», «офлайн, черновик на устройстве»); при конфликте — диалог «Загрузить серверную версию / Сохранить как копию / Перезаписать явно» (по образцу [`editor-draft-conflict.tsx`](../../apps/photographer/src/editor-draft-conflict.tsx)).
- **Клавиатура (web)**: таблица [23](23-editor-playback-timeline.md), раздел 10 (Пробел, J/K/L, I/O, S, Delete/Backspace, ←/→, ↑/↓, Ctrl/Cmd+Z и Ctrl/Cmd+Shift+Z, +/−/\\, M, C/V, N, Home/End, Escape).
- **Ограничения**: ≤ 4 видео и ≤ 4 аудио дорожки, ≤ 2 000 клипов, документ ≤ 8 МиБ; превышение — понятная ошибка до отправки.
- **Недоступные источники**: клип остаётся в документе с пометкой; кнопка «Рендер» заблокирована списком причин.
- **Файлы**: `src/video-editor.tsx` (оркестрация), `src/video-timeline-canvas.tsx` (специализированная поверхность), `src/video-timeline-store.ts` (состояние, команды, undo/redo), `src/video-timeline-commands.ts`, `src/video-sequence-save-attempt-store.ts`, `src/video-sequence-load.ts`, `src/video-bin.tsx`, `src/video-monitor.tsx`, `src/video-inspector.tsx`, `src/video-shortcuts.ts`, `packages/api-client/src/video-timeline.ts` (типы документа и валидатор, общий с рендерером по контракту — [07](07-timeline-edl-and-render-spec.md)).
- **Тесты**: команды (разрез, ripple, обрезка, привязка к границам, пересечения, скорость); инвариант «команда + обратная = исходный документ»; сериализация в канонический JSON и стабильный SHA-256; конфликт ревизий; восстановление черновика; DOM-тест клавиатуры; тест лимитов.

### V-07. Цветокоррекция

**Нормативно:** колёса, кривые, осциллограммы и поля — [23](23-editor-playback-timeline.md), раздел 14.

- **Цель**: настроить цвет клипа/дорожки/всего монтажа и увидеть результат.
- **Содержимое**: монитор «до/после» (разделитель, переключатель, сетка кадров клипа); вкладки: «Основное» (экспозиция, температура, оттенок, контраст, светá/тени, насыщенность, живость), «Кривые» (RGB и каналы), «Колёса» (lift/gamma/gain), «LUT» (импорт `.cube`, интенсивность), «Авто» (по эталонному кадру, по соседнему клипу); осциллограммы (waveform, vectorscope, гистограмма) — вычисляются на превью-кадре; кнопки «Скопировать на все клипы дорожки», «Сбросить».
- **Предпросмотр**: клиент отправляет `video.preview_frames` (список кадров и стек эффектов ревизии) — воркер возвращает JPEG; кадры кэшируются по хешу (клип, кадр, стек); на время ожидания остаётся прежний кадр с пометкой «устарело». Приближённый WebGL-предпросмотр — V2 с обязательным тестом паритета с рендером.
- **Авто-анализ**: `video.color_analyze` возвращает предложенные параметры; применение — решение пользователя, не молчаливое (правило MVP для AI-результатов).
- **Совпадение с фото**: цветовая наука, ICC и профили берутся из существующих модулей [`workers/photo_worker/color`](../../workers/photo_worker/color) и [`algorithms/color.py`](../../workers/photo_worker/algorithms/color.py); отдельная реализация допускается только с тестом согласованности.
- **Файлы**: `src/video-color-screen.tsx`, `src/video-color-controls.tsx`, `src/video-color-wheels.tsx`, `src/video-color-curves.tsx`, `src/video-scopes.tsx`, `src/video-lut-import.ts` (валидация `.cube`: размер, диапазоны, число точек), `src/video-preview-frames.ts` (запрос, кэш, отмена), `src/video-color-analyze-attempt.ts`.

### V-08. Музыка и звук

- **Содержимое**: дорожки с волнами; параметры выбранного клипа (громкость в дБ, fade in/out, панорама); «Музыкальная дорожка»: загрузка/выбор трека, сдвиг, обрезка, зацикливание, ducking (порог, глубина, атака/релиз), целевая громкость (LUFS) с пресетами; блок «Метки битов» (запуск `audio.analyze`, показ BPM и сетки, «Привязать склейки к битам» — предложение, применяется по подтверждению); декларация прав (`Checkbox` + текст; без неё рендер с музыкой блокируется).
- **Файлы**: `src/video-audio-screen.tsx`, `src/video-audio-controls.tsx`, `src/video-beat-grid.ts`, `src/video-rights-declaration.tsx`.

### V-09. Рендер

- **Содержимое**: выбор пресета (`RadioButton`/`Chip`): разрешение, fps, кодек/профиль качества, аудио; поле имени; оценка (размер, время, бэкенд); проверка (список блокеров: недоступный источник, нет декларации прав, недостаточно места, нет воркера); кнопка «Запустить рендер»; список прошлых рендеров этой и прежних ревизий с размером, датой, статусом, действиями (смотреть, скачать, выдать клиенту, удалить).
- **Поведение**: кнопка создаёт задание с `Idempotency-Key`; повтор того же намерения возвращает тот же рендер; на неоднозначном ответе показывается сверка (GET по ключу), без повторной отправки (как [`editor-render-submit.ts`](../../apps/photographer/src/editor-render-submit.ts)).
- **Файлы**: `src/video-render-screen.tsx`, `src/video-render-presets.ts`, `src/video-render-submit.ts`, `src/video-render-submit-attempt-store.ts`, `src/video-render-history.tsx`.

### V-10. Задание

- **Цель**: единая страница любого видео-задания (ingest, детекция, цветоанализ, превью, рендер).
- **Содержимое**: заголовок (тип, объект), `ProgressBar` + стадия + оценка остатка, журнал событий (ключевые), блок причины ожидания («нет свободного GPU-воркера», «ожидание лимита параллельности»), результат по типу (ссылка на V-04 для детекции, плеер для рендера, карточка файла), действия «Отменить» (с подтверждением) и «Повторить».
- **Основа**: [`screens/runs/[id].tsx`](../../apps/photographer/screens/runs/[id].tsx) с `watchRun`, `RunCancelAttemptStore`, `RunRetryAttemptStore`; допускается расширение существующего экрана веткой по `kind` вместо дублирования — решение принимается при реализации (критерий: повторное использование без копирования логики отмены/повтора).
- **Файлы**: `src/video-job-screen.tsx`, `src/video-job-watch.ts`, `src/video-job-result.tsx`.

### V-11. Новая выдача клиенту

- **Содержимое**: выбор готовых рендеров (список с превью, размером); название; срок действия; секрет ссылки (генерировать/задать); разрешить скачивание (переключатель Paper `Switch`); лимит трафика ссылки (опционально); предпросмотр «как клиент»; кнопка «Создать». По образцу [`delivery-create-screen.tsx`](../../apps/photographer/src/delivery-create-screen.tsx) и [`delivery-create-attempt-store.ts`](../../apps/photographer/src/delivery-create-attempt-store.ts).
- **Файлы**: `src/video-delivery-create-screen.tsx`, `src/video-delivery-create-attempt-store.ts`, `src/video-delivery-api.ts`.

### V-12. Выдача: статус и ссылка

- **Содержимое**: ссылка (копировать), статус (опубликована / снята / истекла), состав, статистика (открытия, просмотры, скачивания, исходящий трафик), история, кнопки «Снять с публикации», «Отозвать ссылку», «Продлить», «Сменить секрет». Образец — [`collection-access-links.tsx`](../../apps/photographer/src/collection-access-links.tsx).
- **Файлы**: `src/video-delivery-detail.tsx`, `src/video-delivery-stats.tsx`.

### V-13. Квоты и хранилище

Расширение существующего экрана: разбивка хранилища по категориям (оригиналы, производные, рендеры, музыка), активные резервы с ссылкой на задание, исходящий трафик за период, быстрые действия «Удалить производные неиспользуемых медиа» и «Показать самые большие объекты». Данные — из существующего `OwnerAPI.tenantSettings`, расширенного полями видео. Файл: `src/video-usage-breakdown.tsx`.

### V-14. Точки входа

На экране проекта — карточка «Видео» (число медиа, монтажей, занятый объём, активные задания); на экране `runs/[id]` — ссылка на V-10 для видео-runs; в меню рабочего пространства — пункт «Видео» при наличии capability.
