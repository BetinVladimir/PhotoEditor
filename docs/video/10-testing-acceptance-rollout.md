### Тестовые материалы

1. **Синтетика с известной разметкой** (генерируется самим тестом через `ffmpeg -f lavfi`): резкие склейки на заданных кадрах, наплывы `xfade`, затемнения, вспышки, VFR, поворот, разные частоты кадров, моно/стерео/без звука, HDR-теги, повреждённые хвосты. Это основной ground truth для детектора и компилятора.
2. **Реальные ролики с лицензиями, допускающими использование** (открытые фильмы и т. п.) — список, источники, лицензии и SHA-256 в манифесте `tests/fixtures/video/manifest.json`; сами файлы в Git не кладутся (по правилам размещения крупных входов, [карта репозитория](../repository-layout.md)); получение — отдельным документированным шагом.
3. **Негативные образцы**: усечённые контейнеры, декомпрессионные «бомбы», аномальные потоки, плейлисты со ссылками, LUT с некорректными данными.

## 5. Критерии приёмки по сценариям

| Сценарий | Критерий |
|---|---|
| S1 Загрузка | файл 16 ГиБ загружается при обрыве сети и закрытии вкладки; повтор продолжает с контрольной точки; хеш и размер подтверждены; при нехватке места передача не начинается; неподдерживаемый файл отклонён без списания квоты |
| S2 Детекция | на синтетическом наборе F1 по резким ≥ 0.9, по плавным ≥ 0.7 (цели); результат одинаков по структуре на `cuda`/`mlx`/CPU; применение границ идемпотентно |
| S3 Монтаж | 500 клипов, 60 кадр/с интерфейса (цель), сохранение < 500 мс на P95, конфликт ревизий не теряет правку, команды обратимы |
| S4 Цвет | превью-кадр и кадр рендера в допуске ΔE; недопустимый LUT отклонён; авто-параметры не применяются молча |
| S5 Звук | громкость результата в пределах ±0.5 LU от цели; ducking слышимо опускает музыку на речи (измерение уровней); декларация обязательна |
| S6 Рендер | результат соответствует ревизии (длительность ±1 кадр, потоки), размер ≤ резерва, отмена ≤ 10 с без остатков, повтор после падения воркера не дублирует результат |
| S7 Выдача | клиент видит и скачивает ролик; после снятия с публикации следующий запрос получает отказ; трафик учтён по фактическим байтам |
| S8 Квоты | входные, производные, результаты и музыка отражены в `used` по категориям; освобождение только после физического удаления; висящих резервов нет |

## 7. Определение готовности (DoD) для каждого пакета

1. Код, миграции (если есть) и контракты обновлены; генераторы и `check-docs.py` проходят.
2. Тесты слоя из раздела 4 написаны и пройдены **на финальных исходниках**; пропуски отдельно перечислены и не считаются приёмкой.
3. Для клиентских пакетов: `npm run typecheck`, `npm test`, `npx expo export --platform web`, проверка в реальном браузере.
4. Для воркеров: квалификация операции × бэкенд записана; `doctor` проходит.
5. Негативные сценарии (чужой tenant, отозванный доступ, отмена, повтор, восстановление) пройдены.
6. Документация эксплуатации и карта [репозитория](../repository-layout.md) обновлены; ссылки в `docs/video` проверены.
7. Запись состояния в реестре приёмки (по образцу [`current-status.md`](../implementation-v2/audit/mac-deep-testing-2026-10-17/current-status.md)) отражает только проверенное.

## 8. Выпуск

1. Capability `video` выключен по умолчанию; включается для tenant администратором; kill switch отключает новые задания и выдачу, не удаляя данные.
2. Стадии: внутреннее использование → закрытая бета (несколько студий) → расширение. Переход между стадиями — по метрикам ошибок, ёмкости и себестоимости.
3. Режим `video_billing_mode = beta_free` до замеров; затем `metered` ([05](05-storage-quota-retention.md), раздел 5).
4. Миграции допускают откат функции (флагом) без отката данных (forward-only).
