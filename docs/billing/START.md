# START — точка входа для разработки (Qwen 35B, окно 64K, OpenCode)

Читать только этот файл, затем `RULES.md`. Остальное подгружается по задаче, не целиком.

## Бюджет контекста

- Окно 64K, но OpenCode сам занимает около 10–15K (системный промпт и описания инструментов). Считать, что для работы есть 50K.
- Пакет материалов задачи — до 24K токенов, резерв на ответ и правки — не меньше 14K.
- Не читать каталоги и файлы целиком (`docs/billing/*.md`, `contracts/*.sql`). Только пакет из `build-pack.py` и то, что он перечислил.

## Цикл одной задачи

1. Выбрать задачу (порядок ниже). Одна сессия OpenCode — одна задача; после коммита начать новую сессию.
2. Собрать пакет:
   `python3 docs/billing/tools/build-pack.py --task <ID> --window 50000 --budget 24000 --reserve 14000 --out /tmp/pack.md`
   Если скрипт ругается на бюджет — задача слишком крупная: не расширять, а резать (`TASKS.md`, правило резки).
3. Прочитать `/tmp/pack.md` целиком, больше ничего не открывать, пока не понадобится файл из поля «Выход».
4. Написать код и тесты из поля «Тесты» вместе (R33). Формат ответа и STOP/ASK/OPEN — по `QWEN-PROMPT.md` §2.
5. Проверить: `bash docs/billing/tools/check-static.sh`, затем команды из «Критерия» задачи.
6. Сгенерированные файлы не править руками: менять source в `contracts/` и запускать генератор.
7. Если значения не хватает (цена, лимит, срок, налог, сигнатура) — STOP и строка в `OPEN.md`, не угадывать.
8. Коммит: только файлы из «Выхода». Миграции — только вперёд, следующий свободный номер по репозиторию (сейчас после 02656).

## Порядок задач

| Шаг | Что | Где |
|---|---|---|
| 0 | `TST-01…TST-05`: инфраструктура тестов | `backlog/BACKLOG-testinfra-1.md` |
| 1 | `T-02`, `T-03`, `T-04`: коды ошибок и Go-хелпер | `TASKS.md` |
| 2 | каркасы `*-00`, затем таблицы `*-T*`, функции `*-F*` группы: finance → provider → usage → legal | `backlog/README.md` |
| 3 | API `API-*` (только вместе с handler и тестом) | `backlog/BACKLOG-api-*.md` |
| 4 | Stripe `STR-00…13, 16` на fake-провайдере | `backlog/BACKLOG-stripe-*.md` |
| 5 | экраны `UI-*` | `backlog/BACKLOG-ui-*.md` |
| 6 | e2e `E01–E90`: сначала описание в docstring, потом тест | `backlog/BACKLOG-e2e-*.md` |
| 7 | приёмка модулей `ACC-*` | `backlog/BACKLOG-acceptance-*.md` |

Перед каждой функцией `*-F*` проверить строку «возможно покрыта»: этапы 1Б уже реализовали часть под другими именами.

## Не для модели (брать человеку или сильной модели)

- `T-01` / `ACC-1B7`: нужен ваш PostgreSQL и Go.
- `STR-14`, `STR-15`: нужны ключи и аккаунты Stripe (`OPEN-14`); ключи добавляются после написания кода по `STRIPE-CONFIG.md`.
- Логика квот, lease, settlement, erasure, любая правка блокировок: Qwen пишет, но только с обязательным ревью человеком.
- Любое значение из `OPEN.md` со статусом OPEN/BLOCKED.

## Что где лежит

- Правила: `RULES.md` (R1–R33), тесты: `TESTING.md`, образцы: `EXAMPLES*.md`.
- Контракты (источник правды): `contracts/`. Карточки этапов: `briefs/`.
- Журнал прогонов: `STATUS.md`. Открытые вопросы: `OPEN.md`.

## Ограничения этого набора

- Работа Qwen 35B на этих задачах не измерялась: первый прогон — на `TST-01` и одной таблице, смотреть, держит ли формат ответа.
- Go и PostgreSQL проверки выполняются у вас; статические — `check-static.sh`.
