# Навигация по PhotoEditor

PhotoEditor объединяет облачную систему обработки фотографий и исходный локальный редактор. Этот документ объясняет расположение файлов; он не заменяет планы разработки и не подтверждает приёмку системы. Структура проверена 19 октября 2026 года без запуска сервисов и сборок.

## Приложения и пользователи

| Каталог | Назначение и пользователь | Технологии |
|---|---|---|
| [apps/photographer](../apps/photographer) | Рабочее приложение фотографа: проекты, обработка, проверка результатов, доставка, настройки организации | Expo / React Native, TypeScript; React Native Paper; веб и мобильные цели |
| [apps/portal](../apps/portal) | Клиент фотографа: просмотр опубликованных материалов и получение файлов | Next.js / React, TypeScript |
| [apps/studio-agent](../apps/studio-agent) | Локальный агент студии для обмена файлами с системой | Python, отдельная команда `photo-studio-agent` |
| [apps/local-editor](../apps/local-editor) | Исходный локальный пакетный редактор, CLI и настольное приложение | Python; PySide6; существующие алгоритмы обработки и закреплённые зависимости |

У приложения фотографа маршруты находятся в `app/`, общие компоненты, клиентские модели и тесты — в `src/`. У портала исходники находятся в `src/`. Корневого `src/` нет: исходный редактор уже выделен в `apps/local-editor/src/`.

## Почему служебные каталоги остаются на месте

| Каталоги | Правило обращения |
|---|---|
| `.models/`, `.venv/`, `.venv-platform/`, `.venv-codeformer/`, `.runtime/` | Модели, установленные окружения и инструменты. Их пути используются командами и могут входить в закреплённые проверки. Не переносить и не удалять при обычной уборке. |
| `.cache/`, `.go-build-cache/`, `.pytest_cache/`, `.ruff_cache/`, `node_modules/` и вложенные `node_modules/` | Кэши и зависимости. Возможность восстановить содержимое не означает разрешение удалить его сейчас. Действуют проверки владельцев процессов и ранее принятое правило отдельного разрешения на очистку кэша. |
| `apps/portal/.next/`, `apps/photographer/.expo/`, `apps/photographer/dist/`, `__pycache__/` | Создаваемые инструментами данные. Конкретные файлы могут использоваться текущим стендом или быть закреплены в пакете проверки; их одноимённость с типовым временным каталогом не доказывает, что они свободны. |
| `work/` | Смешанный рабочий архив: frozen-пакеты, закрытия исходников, инструменты, приватные входы и доказательства. Это не корзина временных файлов. Существующие адреса и хеши сохраняются. |

`.gitignore` исключает часть таких файлов из Git, но не определяет их жизненный цикл и не даёт разрешения на удаление.

## Безопасный порядок дальнейшей уборки

1. Сначала улучшать навигацию: использовать этот документ и ссылку из README. Сейчас не требуется переносить исходники, окружения или доказательства.
2. Для каждого будущего переноса составить точный список файлов и потребителей: ссылки, импорты, Makefile, скрипты, генераторы, конфигурации, манифесты и закрепления исходников. Обновлять только новые версии пакетов; старые frozen-пакеты и их пути сохранять.
3. Освобождать место за счёт конкретных воспроизводимых артефактов сборки лишь после проверки, что текущие процессы и выбранные пакеты их не используют. Для кэшей соблюдать существующую процедуру разрешения на точный список. Не подменять её общим разрешением «навести порядок».
4. Доказательства приёмки, исходные фотографии, модели, приватные входы и окружения не включать в массовую очистку. Для чувствительных данных действует отдельный жизненный цикл владельца стенда.
5. После согласованного изменения путей проверить ссылки и затронутые команды; прежние результаты тестирования не переносить автоматически на новую структуру.

В рамках этой навигационной правки ничего не перемещено и не удалено. Документ не устанавливает новый порядок запуска стендов и не меняет текущую цель реализации и полной приёмки.
