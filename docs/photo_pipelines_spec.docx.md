Техническое задание на разработку  
Каноническая редакция 4.1 • 19 сентября 2026 года

Разработать self-hosted платформу для фотографа: анализ ручной обработки по парам, перенос стиля на новые кадры, ретушь, управление коллекциями и передача фотографий клиентам. # **1 Назначение и обязательный объём**

Пайплайн analyze принимает одну или несколько явно сопоставленных пар «оригинал — ручная обработка» и выпускает переносимый style.json с метриками уверенности. Пайплайн apply принимает стиль и snapshot новой коллекции, выполняет близкую обработку и создаёт новую коллекцию с новыми копиями обработанных фотографий. Система не восстанавливает историю Photoshop и не обещает точные значения его инструментов.

Включить все перечисленные ниже функции в разработку. «По запросу» означает поставляемую функцию, которую пользователь включает для конкретного задания; это не исключение из объёма. «С проверкой» означает обязательное сохранение предпросмотра и решения пользователя перед включением результата в финальную коллекцию. Наличие модели и ресурсная реализуемость не являются доказательством качества на любых фотографиях.

| Группа | Функции | Режим |
| :---- | :---- | :---- |
| Отбор | Дубликаты, серии, резкость, закрытые глаза, рейтинг, заданное число выбранных кадров | Авто и пересмотр |
| Единая серия | Группировка сцен, эталон, яркость, WB, цвет кожи, отклонения от серии | Авто с ограничениями |
| Маски | Люди, лицо, волосы, глаза, рот, небо, предмет, одежда, кисть и точки | Авто и ручное уточнение |
| Композиция | Горизонт, вертикали, перспектива, единый масштаб портретов, пропорции | Авто и пересмотр |
| Портрет | Бьюти, дефекты, фигура; зубы, блеск кожи, тени под глазами, волосы, очки | Смешанный |
| Качество | Шум, умеренная резкость, увеличение 2× и 4×, сенсорная пыль | По запросу |
| Фон | Очистка, вырезание, прозрачность, замена, размытие, небо | По запросу |

| Недвижимость | Брекетинг, HDR, окно из тёмной экспозиции, перспективная коррекция | По запросу |
| Рабочий процесс | GUI, пакетный экспорт, контактные листы, локальная галерея, обратная связь | Обязательный |

Коллекции создаются внутри приложения, в том числе пустые. Фотограф может сразу создать ссылку для просмотра или приёма фото. Гостевой портал открывает только опубликованный набор конкретной коллекции, разрешает скачивание и загрузку согласно правам ссылки. Обработка, настройки tenant и удаление чужих фото через гостевую ссылку недоступны.

Поддерживаемые входы: JPEG, PNG, TIFF RGB и RAW по зафиксированной проявке. PSD-слои, CMYK и видео вне объёма. HDR из брекетинга, PNG alpha, управляемая генерация и автоматический crop входят в объём по контрактам ниже. Принятый результат сохраняет исходник неизменным. Неидентифицируемые правки помечаются needs\_review; генеративные параметры нельзя достоверно восстановить по flattened-паре.

# **2 Архитектура и разделение ответственности**

Браузер и мобильное приложение обращаются к Caddy. Caddy передаёт /api/\* в Go, выдаёт web-сборку Expo и проксирует отдельный S3-домен в MinIO. Go авторизует пользователя, сохраняет изменения в PostgreSQL и планирует задачи. RabbitMQ доставляет команды и результаты. Воркеры читают входы из MinIO и контекст из PostgreSQL, выполняют одну операцию, сохраняют результат и публикуют событие через transactional outbox.

| Слой | Обязательный выбор |
| :---- | :---- |
| Вход HTTP/HTTPS | Caddy 2, Caddyfile, автоматический TLS, постоянные /data и /config; без обязательных сторонних модулей. |
| REST и управление | Go, net/http \+ chi, pgx/v5, sqlc, goose, rabbitmq/amqp091-go, minio-go/v7; slog; OpenAPI 3.1. Одна кодовая база, отдельные роли api, scheduler, publisher, event-consumer. |
| Хранение и очередь | PostgreSQL с RLS; MinIO S3; RabbitMQ durable exchanges/queues, publisher confirms, manual acknowledgements. Redis, Celery и отдельный workflow engine не требуются. |
| Атомарные воркеры | Python 3.11, Pydantic, pika, psycopg 3, minio Python SDK; модели и image tooling из разделов 1, 21–25, 31–35, 38\. SMTP-задачи — Go worker на net/smtp с обязательным TLS в production. |
| Клиент | Expo, React Native, TypeScript, Expo Router, React Native Paper MD3, React Native Web; TanStack Query, Zustand для временного состояния редактора, React Hook Form \+ Zod. |
| Темы и языки | PaperProvider, MD3LightTheme / MD3DarkTheme, expo-localization, i18next, react-i18next, Intl; expo-secure-store для native refresh token. |
| Сборка и контроль | Docker Compose v2, BuildKit, uv, Go modules, npm lock; pytest, go test, Playwright web, Maestro native. Mailpit — только локальная SMTP-среда. |

Точные совместимые версии и image digests фиксируются на этапе сборки, без latest. Поставка содержит dependency lock, models.lock.json, SBOM и реестр лицензий кода/весов. Community-репозиторий MinIO архивирован на дату ТЗ: собрать выбранный commit из исходников, зафиксировать digest и назначить сопровождение исправлений. Автоматической замены продукта на AIStor не делать \[28\].

Добавить отдельный сервис portal на Next.js App Router, TypeScript, @mui/material, @mui/material-nextjs, Emotion, React Photo Album, Yet Another React Lightbox и Motion for React. Portal слушает 3000 внутри Compose. Expo обслуживает фотографа и участников организации; Next.js обслуживает посетителей с capability-ссылкой. Paper остаётся UI-библиотекой Expo, MUI используется только веб\-порталом.

Вся авторизация, права ссылки, создание коллекций и jobs находятся в Go. Next.js не подключается к PostgreSQL, RabbitMQ и MinIO SDK с сервисными ключами и не запускает обработку самостоятельно. Разрешён SSR общедоступной оболочки; защищённые данные портал получает через Go API без общего server cache. Сборку и runtime Node фиксировать вместе с lock-файлом, поддерживать Linux arm64 и amd64 \[42,43\].

# **3 Организации и роли**

Tenant — рабочее пространство организации. Один пользователь может состоять в нескольких tenants. После подтверждения email при разрешённой регистрации создаётся личное пространство с ролью owner. Переключение workspace меняет контекст запросов, кэша и подписки событий. Чужие проекты, стили, изображения, embeddings, задачи и экспорты недоступны даже при известном UUID.

| Роль | Права |
| :---- | :---- |
| Owner | Все операции; участники, квоты, удаление tenant, передача владения. |
| Admin | Участники кроме передачи владельца; проекты, стили, обработка и настройки workspace. |
| Editor | Импорт, запуск, правки, review, создание версий стилей, экспорт. |
| Viewer | Просмотр разрешённых проектов и результатов; скачивание согласно политике проекта. |

Во всех бизнес-таблицах tenant\_id NOT NULL. Для связей использовать составные ключи и внешние ключи (tenant\_id, id). RLS включить и FORCE ROW LEVEL SECURITY; прикладная DB-роль не владелец таблиц и без BYPASSRLS. В каждом коротком transaction задавать SET LOCAL app.tenant\_id после проверки membership. Запрещено доверять tenant из заголовка или тела без этой проверки; пул соединений не должен сохранять контекст между запросами.

Глобальные users, OTP и sessions имеют отдельную политику доступа. Воркеры — доверенные внутренние сервисы с отдельными ролями и ограниченными SQL-функциями claim/heartbeat/commit; контекст tenant получают из сохранённой задачи. Они не исполняют произвольные SQL или пути от пользователя. На MinIO выдавать ограниченные префиксом права, без root-ключей в воркерах; предпочтительно краткоживущие credentials на задачу через внутренний Go endpoint с проверкой lease.

Кэш, дедупликация, векторный поиск и ключи TanStack Query обязательно включают tenant\_id. Запрет межтенантного поиска лиц. Квоты: bytes хранилища, число исходников, активных запусков и GPU-задач. Scheduler распределяет доступ между tenants справедливо; один массовый импорт не блокирует остальных. Audit log фиксирует actor, tenant, действие, resource и время, без OTP и подписанных URL.

Гость по ссылке — отдельный principal share\_session, не membership и не пользователь организации. Tenant и collection берутся из share\_link в БД; параметры клиента не могут расширить область доступа. Права гостя — пересечение link permissions, текущей политики коллекции и статуса конкретного фото. Viewer tenant не может создавать write-ссылки; это право Editor/Admin/Owner в разрешённом проекте.

# **4 Коллекции в приложении**

| Возможность | Требование |
| :---- | :---- |
| Создание | POST создаёт пустую коллекцию с id, названием, описанием, project\_id, cover, порядком сортировки и revision. При выборе «Создать и поделиться» коллекция и share\_link создаются одной SQL-транзакцией. |
| Состав | collection\_items связывает неизменяемую asset\_version с коллекцией: section\_id, position; display/download — производные того же фото, не другие правки. Один asset может входить в несколько коллекций своего tenant без копирования оригинала. |
| Версии и публикация | Оригинал, обработанная копия, preview и thumbnail имеют разные artifact\_id. Публикация открывает закреплённую версию item; подмена этой версии запрещена. Обработка создаёт новую коллекцию. Draft, published, archived — состояния; пустая published допустима для приёма файлов. |
| Организация | Обложка, секции/альбомы, ручная сортировка, поиск, фильтры, рейтинги и выбор нескольких фото. Скрытый item остаётся в рабочей коллекции, но не выдаётся гостю. |
| Пустая коллекция | Уникальный URL работает сразу; портал показывает название, пустое состояние и upload CTA при праве записи. Пока готовых файлов нет, скачивание отключено; затем список обновляется без смены ссылки. |
| Удаление | Удаление item из коллекции не удаляет исходник из других коллекций. Удаление asset — отдельная операция с проверкой ссылок, активных архивов и retention. Удаление/архивация коллекции отзывает её links и останавливает новые гостевые jobs. |

Термины: collection — изменяемый каталог принадлежностей; asset — логическое фото; asset\_version — неизменяемый снимок содержимого; artifact — конкретный объект MinIO; publication — доступность конкретного item гостю. Item всегда закреплён за asset\_version\_id, а не за latest. Изменять состав и порядок можно; заменять содержимое фото в существующем item нельзя. Обработка создаёт новую коллекцию (раздел 4.1). Изменения состава увеличивают revision; optimistic concurrency защищает изменения от потери.

Все действия доступны из Expo web/iOS/Android и REST. Поделиться означает показать/скопировать URL либо системный share sheet; автоматическая отправка email третьим лицам не требуется. История ссылок содержит название, права, сроки, статус и число загрузок/скачиваний без показа секретов в журнале.

## **4.1 Неизменяемые фотографии и новые коллекции результатов**

Два вида изменений различаются явно. Организация содержимого — название, описание, разделы, порядок, добавление/удаление принадлежностей, рейтинг и публикация — допускается в той же коллекции с новой revision. Изменение изображения — применение профиля, цвет, ретушь, геометрия, кадрирование, генерация или сохранение ручной правки — всегда создаёт новую коллекцию и новые фото. Кнопка «Заменить исходники» отсутствует; API не принимает in\_place=true.

В начале apply Go одной SQL-транзакцией создаёт run, output\_collection\_id и outbox; источник фиксируется как source\_collection\_id \+ source\_revision \+ упорядоченный snapshot item/version IDs. Повтор HTTP с тем же Idempotency-Key возвращает тот же run и ту же целевую коллекцию. Новый сознательный запуск создаёт другую коллекцию. Retry отдельных задач продолжает существующий результат запуска и не плодит коллекции.

Название результата по умолчанию: «Название источника — Название профиля · vN — дата и время»; его можно изменить. Результат изначально draft, без гостевых ссылок. Он имеет source\_collection\_id, source\_revision, source\_run\_id и применённую style\_version\_id. Для каждого обработанного кадра создаются новый asset\_id, immutable asset\_version\_id и MinIO object key, а также parent\_asset\_version\_id. Исходный объект нельзя перезаписывать даже при совпадении имени файла.

Обработка всей коллекции создаёт результат для её snapshot. При выборе части фотографий по умолчанию новая коллекция содержит только выбранные результаты; UI заранее показывает это правило и количество. Опциональный режим «Вся коллекция, изменить выбранные» переносит остальные кадры как новые memberships, закреплённые за прежними immutable версиями, без повторного рендера. Для отредактированных кадров новая копия обязательна.

Ошибка/отмена оставляет целевую draft коллекцию со статусом run и успешными результатами; пропущенные и ошибочные кадры перечисляются отдельно. Частичный результат не выдавать за полный. Изменение состава источника после старта не меняет snapshot. Удаление принадлежности не удаляет файл; физическое удаление разрешено только при отсутствии ссылок, snapshot leases и зависимостей.

Редактор сначала хранит недеструктивный черновик параметров. «Сохранить правки» создаёт новый run и новую коллекцию, в том числе для одного фото. Внутренние preview-артефакты черновика не являются сохранённой коллекцией. Обработка уже обработанного результата допустима как новая ветвь; UI показывает источник и предупреждает о повторном наложении стиля. Кнопка «От исходников» явно выбирает сохранённые родительские версии.

# **5 Ссылки доступа и право загрузки**

| Право | Семантика |
| :---- | :---- |
| view | Просмотр только опубликованных ready items и их разрешённых previews/thumbnails. |
| download | Получение разрешённой версии одного фото или архивов выбранных/всех фото. Независимо от view; при false кнопки скрыты и API запрещает download jobs. |
| upload | Добавление собственных исходников в указанную коллекцию. Не даёт edit/delete/publish/process и не разрешает замену существующего object key. |
| upload only | Отдельный режим приёма: upload=true, view=false, download=false. Гость видит свою upload-сессию, но не каталог чужих файлов. |
| read and write | view=true, upload=true; download задаётся отдельно. Публикация загруженного — после технической проверки и, по умолчанию, подтверждения фотографом. |

Формат: https://PORTAL\_DOMAIN/ru/s/{share\_id}\#k={secret}. Secret — 32 случайных байта CSPRNG, base64url; в БД только HMAC/хеш secret. share\_id не является секретом. Портал читает fragment и обменивает его через POST /api/v1/portal/sessions на host-only HttpOnly Secure SameSite cookie. После успешного обмена удалить fragment через history.replaceState. Секрет не отправляется в URL запроса, лог, analytics, Referer или HTML; Referrer-Policy: no-referrer, noindex/nofollow. Защита держится на capability, а не на robots.

Без email OTP для гостя: действующая ссылка достаточна. Guest session ограничена share\_id/tenant\_id/collection\_id, expires\_at и version ссылки; Go проверяет revocation, expiry и permissions при каждом запросе. Новая вкладка по исходной ссылке может создать новую сессию. Секрет показывается один раз при создании; после потери создать новую ссылку, существующие секреты из БД не восстанавливать.

Настройки ссылки: label, expires\_at (по умолчанию 30 дней, null только явно), permissions, max\_upload\_files, max\_upload\_bytes\_total, max\_file\_bytes, allowed\_formats, moderation=owner\_review|auto\_after\_validation. Срок можно продлить; отзыв и смена permissions действуют немедленно для новых API-запросов. Уже выданный presigned media/download URL действует не более 60 секунд; уже скачанные файлы отозвать нельзя.

Загрузка резервирует квоту tenant и link атомарно до выдачи parts; освобождает резерв после abort/expiry. Утверждать client Content-Type недостаточно: проверить magic bytes, фактический размер, dimensions/pixel limit и декодируемость в изолированной задаче. SVG/HTML и произвольные исполняемые файлы не принимать. EXIF/GPS не показывать гостю. Результат verification не равен публикации: pending\_review виден только фотографу и загрузившей сессии как статус.

# **6 Гостевой портал Next.js и MUI**

Визуальный ориентир — клиентские галереи Pixieset и Pic-Time: крупная обложка с названием съёмки, спокойная типографика, фотосетка, секции, полноэкранное фото, выбор и понятная выдача файлов. Реализовать собственный дизайн без копирования брендинга. MUI отвечает за toolbar, dialogs, кнопки, Snackbar, Skeleton и прогресс; фотография остаётся главным содержимым \[47,48\].

Возврат из Lightbox сохраняет scroll position. Временный отказ signed URL вызывает обновление адреса через API; ограниченный retry, без бесконечного цикла. Нельзя кэшировать защищённые галереи в Next.js Full Route/Data Cache, Service Worker или общем CDN.

# **7 Миниатюры и производные изображения**

Каждое принятое фото и каждая опубликованная версия имеют миниатюры в MinIO. Go после verification ставит atomic media.thumbnail; отдельная media.preview делает просмотровые варианты. Python worker использует pyvips/libvips \+ LittleCMS2; RAW сначала проходит фиксированный decode. Модели для уменьшения не нужны. Готовность оригинала и thumbnail независима; UI показывает skeleton до готовности, failed с повтором при ошибке.

| Вариант | Контракт |
| :---- | :---- |
| thumb\_320 / thumb\_640 | Длинная сторона 320/640 px, JPEG quality 82, sRGB, EXIF orientation применён, без upscale; оригинальное соотношение сторон. Обязательный thumb\_640, меньший вариант для мобильной сетки. |
| preview\_1600 / preview\_2560 | Длинная сторона до 1600/2560 px, JPEG quality 88, sRGB; используются Lightbox responsive srcSet. Не являются разрешением скачать master. |
| Alpha | Если выбран прозрачный результат — производные WebP с alpha либо явно заданный matte для JPEG; media\_type и aspect ratio возвращаются API. |
| Metadata | artifact\_id, source\_version\_id/hash, derivative\_kind, profile\_version, width, height, bytes, sha256, ICC, created\_at. GPS/камера/нежелательные EXIF удалены; безопасное авторство по политике. |

Путь tenants/{tenant\_id}/assets/{asset\_id}/versions/{version\_id}/derivatives/{profile\_hash}/… . Версии immutable; cache key включает tenant, source hash, orientation, ICC, variant и watermark policy. Повтор задачи использует idempotency contract и один canonical artifact. Нельзя выдавать thumbnail исходника для скрытой обработанной версии: права проверяются через опубликованный item.

Гостевые производные выдаются короткими presigned GET после проверки ссылки. API manifest возвращает размеры для резервирования layout и srcSet; TTL адресов не более 60 секунд, порционная подгрузка/обновление. При download=false просмотровые копии остаются доступными — это ограничение выдачи masters, не DRM. Удаление/смена публикации инвалидирует manifest; старые объекты очищаются только после проверки ссылок и retention.

# **8 Асинхронное скачивание и временные архивы**

Три действия: скачать одно фото, выбранные фото или всю коллекцию. Для одного готового разрешённого файла Go выдаёт одноразовый download-intent и короткую ссылку с Content-Disposition: attachment. Для выбранных/всех, в том числе selection из одного элемента, создаётся асинхронный ZIP job. Photo download никогда не означает сохранение thumbnail. Качество и metadata policy выбирает фотограф для ссылки.

1\. POST download-jobs принимает collection\_revision, scope=selected|all, item\_ids или selection\_snapshot\_id, preset и Idempotency-Key. Go проверяет права и квоты, фиксирует упорядоченный snapshot immutable artifact versions и безопасных имён. Изменения коллекции после запроса не добавляют новые фото в этот архив. Если запрошенное исчезло до snapshot — 409; пустая выборка — 422\.

2\. Go через outbox/Rabbit создаёт задачи получения отсутствующего разрешённого export preset, затем archive.build. Архиватор работает на CPU отдельно от GPU-очереди, потоково читает MinIO и записывает ZIP64 в /work/tmp/{tenant\_id}/{download\_job\_id}/{attempt}/archive.part. Это локальный временный volume воркера, не публичная папка Caddy. Проверить свободное место/резерв до старта; имена без ../, абсолютных путей и коллизий.

3\. После закрытия ZIP и проверки manifest/checksum локальный файл переименуется в archive.zip, загружается в private MinIO temporary-downloads/tenants/{tenant}/jobs/{job}/attempts/{attempt}/archive.zip. Затем одна DB-транзакция фиксирует artifact, expires\_at и outbox succeeded. Локальный temp удаляется после успешной выгрузки либо recovery cleanup. ready нельзя устанавливать до наличия полного объекта.

4\. Portal опрашивает GET job с cursor/backoff; показывает queued/building/uploading/ready/failed/expired, количество обработанных файлов и bytes. После ready повторно запрашивает download-intent, затем инициирует скачивание обычным browser navigation/anchor. Если браузер требует пользовательский жест, появляется «Архив готов — скачать». Не обещать бесшумную загрузку в закрытой вкладке; после возврата status восстанавливается.

5\. TTL готового архива — 24 часа, URL — 60 секунд; значения ENV. Новая загрузка после expiry создаёт новый job. Отзыв ссылки запрещает новые download-intents и отменяет ещё не завершённый гостевой job; уже выданная ссылка живёт до TTL. Архив привязан к share\_id, policy version и snapshot, не переиспользуется другой ссылкой без новой проверки доступа.

Максимум по умолчанию: 5 000 файлов и 10 GiB исходных данных на ZIP; эти пределы настраиваются. Большая коллекция автоматически делится на независимые ZIP-тома по byte/count limit; один слишком большой файл выдаётся отдельно, без потери пункта в manifest. UI предлагает каждый том; браузер может блокировать автоматическое скачивание нескольких файлов. JPEG/PNG/RAW уже сжаты: ZIP Store по умолчанию, JSON manifest можно Deflate. Отсутствующий файл — failed со списком причины; молчаливый частичный архив запрещён.

# **9 Групповые операции над коллекциями**

| Операция | Правила |
| :---- | :---- |
| Отбор и организация | Выбор всех/по фильтру, ratings, flags, tags, hide/publish, порядок и секции. Selection фиксируется до выполнения; список результатов по item. |
| Состав коллекции | Добавить/скопировать membership в другую коллекцию; переместить membership в пределах tenant; убрать из коллекции. Asset не копируется физически и не уничтожается неявно. |
| Обработка | Применить сохранённую версию профиля, beauty/body/quality, resize/watermark или другой рендер. Go создаёт новый run и новую output collection; исходная коллекция не меняется. Отбор без рендера меняет только membership/ratings. Обработка выполняется атомарными worker tasks. |
| Публикация | Открыть готовые items выбранной коллекции для клиентов; pending\_review/failed публиковать нельзя. Нельзя переключать item на обработанную версию другой коллекции. Ссылки на исходную коллекцию не перенаправляются на результат. |
| Выдача и обслуживание | Создать ZIP выбранных/всех, повторить failed thumbnail/preview, снять публикацию. Необратимое удаление asset — отдельная подтверждаемая операция owner/editor с проверкой зависимостей. |
| Гость | Может выбрать фото, скачать разрешённое и загрузить новые при upload=true. Групповой AI, delete, move и изменение чужих metadata гостю запрещены. |

POST bulk-operations принимает action, collection\_id, expected\_revision, selection snapshot, params и Idempotency-Key; 202 возвращает bulk\_operation\_id. Metadata операции исполняются atomic collection.mutate worker задачами пакетами до 500 items с короткими транзакциями. Отчёт item\_id/status/error\_code; completed\_with\_errors допустим и виден. Отмена прекращает оставшиеся пакеты и не откатывает уже применённые изменения. Для перемещения membership одного item внутри tenant — атомарная транзакция.

Tenant fairness, лимиты CPU/I/O и archive concurrency обязательны. Архив и thumbnails не должны ждать завершения длительной генерации на единственном GPU. Права перепроверяются перед мутацией; блокировка коллекции для удалений запрещает новые публикации и скачивания. Конфликт revision не обходить автоматически.

OpenAPI включает тела, ошибки, RBAC и примеры. POST создания run/upload/export принимает Idempotency-Key в tenant scope. Ошибка: {code, message\_key, args, request\_id}; 401/403/404/409/422/429 имеют стабильную семантику. UI не подключается к Rabbit, SQL или административному API MinIO. Preview — обычная задача с приоритетом; устаревший результат не заменяет новую правку.

OTP: 6 цифр из crypto/rand, TTL 5 минут, максимум 5 попыток, повторная отправка не чаще 60 секунд, лимиты email/IP. Ответ request — одинаковый 202 с challenge\_id. Хранить HMAC с серверным pepper и challenge context; код одноразовый, consumed\_at обновлять атомарно. Это passwordless вход, не второй фактор. Секрет для SMTP-доставки хранить только зашифрованным в краткоживущем mail payload в БД, без кода в Rabbit; удалить после отправки/истечения. SMTP worker не отправляет просроченные коды.

Access token короткий (5 минут), refresh token случайный, хеш в БД, rotation и reuse detection. Web refresh — HttpOnly Secure SameSite cookie с Origin/CSRF проверкой; native — SecureStore. Access token в памяти. Письма ru/bg/en, SMTP с TLS и проверкой сертификата; локально Mailpit. Приглашение в tenant не выдаёт membership до подтверждения email и принятия приглашения. Logout и отзыв роли должны прекращать доступ к API.

# **11 Рабочее приложение Paper и локализация**

Единая кодовая база Expo \+ TypeScript для web/iOS/Android. UI-компоненты React Native Paper, визуальная система Material Design 3; web-only пакет @mui/material не используется внутри Expo; он входит в отдельный Next.js портал. PaperProvider и темы навигации получают общие design tokens. Состояния loading, empty, disabled, error, offline и permission denied проектируются для каждого экрана.

Тема: light / dark / system, по умолчанию system. Переключение без перезапуска и без потери несохранённых правок. Сохранять preference в профиле и локально до авторизации. Семантические tokens: primary, surface, background, onSurface, outline, error, success; не кодировать произвольные цвета по компонентам. Canvas сравнения фото — нейтральный серый, цвет самой фотографии тема не меняет. Цвет дополняется текстом/иконкой для статусов. Keyboard focus, screen reader labels, крупный шрифт и контраст проверяются отдельно.

Языки первого релиза: ru — русский, bg — български, en — English. i18next \+ react-i18next, expo-localization и Intl. Приоритет: сохранённый выбор пользователя → локальный выбор → поддерживаемый язык устройства → en. Переключение без перезапуска; ru-RU/bg-BG/en-\* сопоставляются базовым каталогам. Строки не вшивать в компоненты, серверные коды или enum.

Локализовать навигацию, инструменты, подсказки, ошибки, onboarding, уведомления, OTP-письма, экспортные отчёты для пользователя и нативные permission descriptions. UUID, JSON keys, модельные имена и машинные значения остаются стабильными. Использовать plural rules, формат чисел/дат/единиц через Intl; даты в API ISO 8601 UTC, отображение в timezone пользователя. Locale письма передаётся whitelist-полем request и сохраняется в challenge.

{  
  "locale": "bg",  
  "theme": "system",  
  "timezone": "Europe/Sofia"  
}  
// Пример ключей каталогов (JSON без комментариев в поставке):  
// auth.enter\_email, auth.otp\_expired, jobs.waiting\_review,

Ресурсы locales/{ru,bg,en}/{auth,common,projects,editor,jobs,settings}.json с одинаковыми ключами. CI блокирует пропуски и raw translation keys. Переводы русского и болгарского проверяет владеющий языком редактор; машинный перевод не считается финальной приёмкой. Свободные пользовательские названия и prompts автоматически не переводить. Настройки проекта не должны менять язык других участников.

Общие namespaces common/errors/downloads/uploads доступны обоим клиентам. Namespace portal содержит гостевые формулировки, app — профессиональные инструменты. В языковой матрице обязательно одинаковое понимание прав view/download/upload. Archive manifest имеет машинные стабильные keys; человеческое readme и сообщения job переводятся по locale запроса. Имена пользовательских файлов не переводить.

## **12.1 Мастер профиля по парам и применение к коллекции**

В приложении добавить раздел «Профили правок». Профиль — пользовательское имя существующей сущности style, а не второй механизм обработки. Действия: создать по примерам, открыть, переименовать, изменить описание, архивировать, экспортировать JSON, импортировать JSON и применить конкретную версию к коллекции. Профили принадлежат tenant; права Editor/Admin/Owner, Viewer — только разрешённый просмотр.

Шаг 1\. «Создать профиль»: обязательное имя 1–120 символов после trim, описание до 2000 символов; одинаковые имена допустимы, идентификация по UUID. Шаг 2\. Две области «Оригиналы» и «После Photoshop». Загрузить одну или несколько пар через общий resumable upload; миниатюры и статус для каждого файла. Файлы после Photoshop — экспортированные JPEG/PNG/TIFF; разбор PSD-слоёв не требуется.

Шаг 3\. Сопоставление: явные карточки пар со сменой сторон, заменой файла и исключением пары. Предложение по имени допустимо, но неподтверждённые пары не запускать автоматически. Проверять доступность, формат, размеры, ориентацию, ICC, дубликаты, выравнивание и совпадение сцены. Несопоставленные файлы и причины отказа показывать рядом с карточкой. Разрешена одна валидная пара; исходные требования к оценке переноса остаются в разделах 27–29 и 44\.

Шаг 4\. «Рассчитать профиль»: POST analysis создаёт analyze run; Go управляет DAG из разделов 18–19. Показывать очереди, прогресс по парам, отмену и retry. Шаг 5\. Сравнение: оригинал, ручной эталон, реконструкция профилем, ошибки и уверенность; отдельный preview на новых пробных фотографиях. Из одного примера нельзя объявлять подтверждённое качество переноса.

Шаг 6\. «Сохранить профиль»: принять кандидат версии и записать immutable конфигурацию в PostgreSQL; присвоить номер версии, сохранить provenance и отчёт. Низкая уверенность требует явного подтверждения и остаётся видимой после сохранения. Новые пары и перерасчёт создают следующую версию; предыдущие версии и запущенные коллекции не меняются. Переименование профиля не меняет его конфигурацию.

На экране коллекции: «Применить профиль» → выбор имени и версии → весь snapshot или выбранные фото → сила и разрешённые overrides → preview → имя новой коллекции → запуск. Показать исходную и будущую коллекции, объём и политику частичных ошибок. После завершения открыть результат с кнопками сравнения, публикации и скачивания; исходник остаётся доступным.

RU/BG/EN: «Профили правок» / «Профили за обработка» / «Editing profiles»; «Оригинал» / «Оригинал» / «Original»; «После обработки» / «След обработка» / «Edited»; «Применить профиль» / «Прилагане на профил» / «Apply profile». Все состояния мастера, ошибки и подтверждения входят в общие словари; интерфейс Paper, light/dark/system, web/iOS/Android.

Бинарные веса, отчёты, пары и экспортные файлы остаются в MinIO. config\_hash вычислять по единой канонической сериализации JSON (UTF-8, определённый порядок ключей/чисел); экспорт в MinIO формируется из того же JSON, а не является второй редактируемой копией. Раздел 37 использует этот же порядок сериализации.

training\_sets(id, tenant\_id, style\_id, revision, state); training\_pairs(id, tenant\_id, training\_set\_id, before\_asset\_version\_id, after\_asset\_version\_id, session\_id, confirmed, included, validation\_status). На старте анализа создаётся immutable snapshot пар и hashes. Нельзя менять запущенный snapshot; изменения набора доступны следующему анализу. Удаление учебных файлов после retention не мешает apply сохранённой версии профиля.

collections дополнить source\_collection\_id, source\_revision, source\_run\_id, applied\_style\_version\_id; runs — input\_snapshot\_id и output\_collection\_id, UNIQUE(tenant\_id, output\_collection\_id) для создающего run. asset\_versions — parent\_asset\_version\_id и created\_by\_run\_id. collection\_items.asset\_version\_id закрепляется при добавлении; запрет UPDATE этого поля обеспечивается БД/сервисом. Замену фото выражать удалением membership и добавлением другого item, а не перезаписью байтов; редактирование изображения всё равно следует разделу 4.1.

Архивированный профиль скрыт из обычного выбора, но его исторические версии доступны для воспроизводимости разрешённых запусков.

# **14 MinIO загрузки и жизненный цикл**

REST начинает multipart upload после проверки размера и квоты. Go выдаёт короткоживущие presigned URL на конкретные parts; клиент сохраняет upload\_id и возобновляет передачу. Complete endpoint сверяет parts, размер и принадлежность, затем ставит checksum/inspect задачу. До verified файл не участвует в пайплайне. В случае истечения URL клиент получает новый; отменённые multipart очищаются по lifecycle.

Private buckets: originals, processing, outputs; отдельный закрытый model-cache без пользовательских прав. Browser/native не получают ListBucket и постоянные ключи. Скачивание разрешает Go по RBAC, выдавая короткую подписанную ссылку. Для owner API срок по умолчанию 10 минут; гостевые GET действуют до 60 секунд. Retention исходников, промежуточных файлов и экспортов задаётся раздельно.

Разделить private namespaces originals, processing, outputs, derivatives, temporary-downloads и model-cache. Guest upload идёт в staging namespace с уникальным серверным ключом; verification и owner review управляют дальнейшей доступностью. В multipart нельзя перезаписать готовый asset. Для upload owner/guest используется один протокол с разными проверками полномочий.

Подписанная PUT-part ссылка живёт до 10 минут; после revoke Go не выдаёт новые части и не разрешает complete, хотя уже выданная часть может успеть загрузиться в staging. Неподтверждённые parts удаляются по lifecycle. Media/download GET гостю ограничить 60 секундами. Для внутренних пользователей общий default presign может быть 10 минут; более строгая guest policy имеет отдельную ENV.

GC: PostgreSQL expires\_at — основной критерий, MinIO lifecycle — резервная уборка объектов. Не удалять опубликованные derivatives или snapshots с активным artifact lease. После expiry job помечается expired, выдача запрещается, объект удаляется maintenance задачей; повтор удаления безопасен. Локальный temp cleanup удаляет только папки неактивных attempts. Физическая недоступность объекта при ready — явная ошибка и повторная сборка по действующему snapshot.

RabbitMQ — транспорт, PostgreSQL — источник состояния. Семантика at-least-once: повторная доставка допустима и не должна создавать второй принятый результат. Publisher confirms подтверждают приём брокером, а consumer ack — обработку потребителем; это разные гарантии \[25\]. Каждый publish использует confirms и mandatory routing; unroutable сообщения не помечать отправленными.

Повторы планирует Go через next\_attempt\_at в PostgreSQL: задержки 5, 30, 120 секунд с jitter, максимум 3 повторных попытки по умолчанию. Ошибки схемы и отсутствующие права не повторять. OOM допускает до двух повторов с меньшим tile по единому профилю раздела 42\. Не использовать бесконечный nack/requeue или обязательный delayed-message plugin.

Consumer acknowledgement timeout для рабочих очередей должен превышать максимальный timeout операции с запасом. Для длинной генерации задать отдельный лимит; timeout задачи не должен зависеть от HTTP-запроса пользователя. Rabbit heartbeat и DB heartbeat задачи — разные механизмы. Прогресс публиковать с ограниченной частотой, финальные результаты — обязательно и долговечно.

Добавить photo.commands.v1 routing keys io.thumbnail, io.preview, io.archive, io.verify, collection.mutate; durable q.worker.media, q.worker.archive и q.worker.collection. Resource\_class media/archive/cpu/gpu/mail фиксируется registry. Archive worker prefetch=1, concurrency=1 на рабочей станции; media concurrency=1–2 в общем CPU/RAM бюджете. Исходящие события используют тот же events exchange и outbox. Привязки очередей не пересекаются: collection.mutate не входит в cpu.\*; каждая задача публикуется в одну рабочую очередь.

Технически atomic worker допускает несколько operation names в одном процессе, но исполняет только одну задачу за раз в выделенном slot. Новые операции: asset.verify, media.thumbnail, media.preview, collection.mutate, archive.build, storage.cleanup. Полноразмерный AI и архиватор не делят одну очередь. SMTP повтор может привести к повторной доставке того же письма при неизвестном результате внешнего SMTP; новый OTP при retry не генерировать.

# **17 Надёжность и состояния**

1\. Go в одной SQL-транзакции создаёт task и outbox command. Publisher отправляет её в Rabbit и после confirm помечает outbox. При сбое между publish и отметкой возможно дублирование — оно ожидаемо.

2\. Воркер атомарно claim-ит задачу, увеличивает fencing\_token и устанавливает lease. Дубликат уже завершённой задачи подтверждает без расчёта; занятую задачу не запускает параллельно. Короткий heartbeat, по умолчанию каждые 10 секунд при lease 60 секунд, продлевает владение. Не держать SQL-транзакцию во время инференса.

3\. Воркер пишет объекты в уникальный attempt prefix. Затем короткая SQL-транзакция проверяет актуальный fencing\_token, сохраняет artifact manifest, результат задачи и outbox event. Только после commit подтверждает команду Rabbit. Поздний результат старой попытки не может стать актуальным. Go publisher доставляет исходящее событие из outbox.

4\. Event-consumer в транзакции регистрирует inbox event\_id и обновляет граф. Дубликат события не создаёт следующий узел повторно. Scheduler периодически сверяет БД, чтобы восстановить просроченные lease и незавершённые outbox. Физическое вычисление может повториться; единственным является принятый результат.

Задачи: blocked → ready → queued → running → succeeded; отдельные retry\_wait, failed, cancelled, skipped. Запуски: draft, queued, running, waiting\_review, cancelling, cancelled, completed, completed\_with\_errors, failed. Счётчики выводятся из сохранённых задач, а не памяти процесса. Scheduler использует блокировки строк / SKIP LOCKED и tenant fairness.

Отмена запрещает создание новых узлов, помечает ожидающие cancelled, активным выставляет cancel\_requested. Воркер проверяет его между tiles/шагами; неподдерживаемый мгновенный interrupt заменяется завершением без публикации актуального результата. Повтор запуска использует новый run\_id или новую attempt в разрешённом retry; изменения style/overrides создают новый snapshot. Исходники не меняются.

Обязательные fault tests: остановка worker после upload и до SQL commit; после SQL commit и до ack; остановка publisher после confirm; повторная доставка события; истечение lease; недоступность MinIO, БД и Rabbit. После восстановления не теряются подтверждённые задачи и не появляется второй canonical output.

Download job state: queued → preparing → building → uploading → ready → expired; failed/cancelling/cancelled отдельно. ready требует всех томов, если job разбит. Worker scratch и MinIO writes не входят в SQL transaction; незавершённые attempt outputs не выдаются. Lease/fencing и inbox/outbox применяются к архивам и миниатюрам так же, как к AI.

# **18 Оркестрация двух пайплайнов**

Analyze: upload complete → inspect/decode каждого входа → register пары → необходимые features/masks → fit каждой пары → барьер пар → aggregate style → validate → review при необходимости → package. Go сохраняет каждый edge. Ошибка пары не скрывается: пользователь исключает её либо исправляет и запускает новую попытку.

Apply: upload complete → inspect/decode → features → барьер group/cull → подтверждение отбора → HDR при наличии bracket → denoise → нужные masks/landmarks/depth → resolve style → geometry → color → барьер series.balance → local/beauty/defects → background/inpaint/generate → crop/outpaint → upscale → derivative resize/sharpen/watermark → QC/review → encode → барьер экспорта → archive. Каждый переход — зависимость в Go DAG; неактивные операции skipped. Порядок операций фиксируется renderer\_version; алгоритмы описаны в разделах 26–36. После geometry маски переносятся тем же warp или пересчитываются. Принятое решение review сохраняется до разблокировки следующих узлов.

JSON run snapshot содержит pipeline\_version, style\_version\_id, collection\_id, ordered\_operations, resource\_profile, export\_options, review\_policy, overrides\_version, seed и model lock. operation params — отдельные версионированные JSON по схеме каждой операции. Координаты масок содержат canvas width/height, orientation, space и transform chain; параметры машинные, независимо от языка интерфейса.

{  
  "schema\_version": 1, "pipeline": "apply", "pipeline\_version": "3",  
  "style\_version\_id": "\<uuid\>", "collection\_id": "\<uuid\>",  
  "resource\_profile": "cuda\_12gb", "locale": "ru",  
  "review\_policy": {"generation": "always", "low\_confidence": "pause"},  
  "overrides\_version": "\<uuid\>", "seed": 42,  
  "export\_options": {"format": "jpeg", "quality": 95, "icc": "sRGB"}  
}  
Analyze fit-узлы упорядочить: при включённой геометрии pair.fit.body → warp согласованного входа → pair.fit.color → pair.fit.beauty/defect evidence. Этот порядок исключает смешение цветовой ошибки с деформацией. Aggregate получает только успешно принятые пары. Промежуточные masks/preview могут быть переиспользованы в пределах tenant при совпадении всех hashes.

Служебные графы Go: ingest \= reserve/upload → verify → inspect/decode → thumbnail \+ preview → owner review/auto publish; download \= snapshot → недостающие export variants → archive.build по томам → ready; bulk \= selection snapshot → collection.mutate batches либо AI fan-out → summary. Создание дочерней задачи всегда выполняет Go, никогда воркер. Асинхронный HTTP-запрос завершается 202 после долговечной записи job/outbox.

В обычном переносе LLM и генеративная замена содержимого не используются. ## **Хранение и перенос**

Численные параметры обработки и LUT сохраняются непосредственно в style.json. Веса LR-ASPP и рабочие ICC-профили устанавливаются один раз как ресурсы приложения и фиксируются в models.lock.json и реестре профилей с SHA-256. Внешние AI API во время analyze и apply не требуются; внутренние сервисы доступны по сети. На M2 Max и RTX 3060 используется одинаковая архитектура и один набор весов.

# **26 Цвет и воспроизводимый рендерер**

## **Входной контракт**

Пары задаются manifest с pair\_id, before\_artifact\_id, after\_artifact\_id, session\_id и optional ignore\_mask\_artifact\_id. Не сопоставлять файлы по сортировке. Минимум одна валидная пара. Входы 8/16 бит RGB; рекомендуются 16-битные TIFF из одного RAW-конвертера. Переносимый локальный manifest допускается только импортёром: он загружает файлы и преобразует пути в artifact IDs.

Сначала применить EXIF orientation и встроенный ICC. Для файла без профиля требовать assume\_profile в upload/analysis settings либо запись профиля в manifest. По умолчанию такой файл отклоняется. Все преобразования цвета должны учитывать профиль; простое присваивание ICC запрещено. Для analyze вход с alpha отклонять. В apply разрешить PNG/TIFF с straight alpha: сохранить исходную alpha, не анализировать прозрачные пиксели; внутри композитора применять premultiplied linear RGB. Экспорт alpha описан в разделе 36\.

## **Рабочее пространство**

В комплекте поставки зафиксировать ICC-профиль RGB с примариями Rec.2020, белой точкой D65 и степенной TRC 2.4: work\_rec2020\_gamma24\_v1. Это внутренний SDR-профиль, не стандартная OETF BT.2020. Его байты и SHA-256 входят в реестр ресурсов приложения. Конвертация LittleCMS2: relative colorimetric, black point compensation off, выход 16 бит \[4\]. Далее нормализация в float32 \[0,1\].

Обозначения: C — RGB в кодированном рабочем пространстве; L \= C^2.4 — линейный RGB. Обратное кодирование: C \= clamp(L,0,1)^(1/2.4). Не использовать 8-битные промежуточные файлы. Предпросмотр для модели и отчётов отдельно переводится в sRGB. Выходной TIFF по умолчанию сохраняет рабочий профиль, JPEG всегда конвертируется в sRGB.

## **Фиксированный порядок ColorProgram v1**

1\. Gains: L1 \= L × gains\_rgb; каждое значение 0.25–4.0. Они описывают совместный цветовой и экспозиционный сдвиг без заявления о точном WB или Kelvin. Отдельный exposure не оптимизируется, чтобы убрать дублирование параметров.

2\. Кодирование C1; общая монотонная кусочно-линейная кривая и затем три поканальные кривые. Абсциссы узлов: \[0, 0.0625, 0.125, 0.25, 0.5, 0.75, 1\]. Ординаты в \[0,1\], не убывают; концы допускают подъём чёрного и сжатие белого.

3\. Декодирование в L2. Y \= 0.2627R \+ 0.6780G \+ 0.0593B; L3 \= Y \+ saturation × (L2 − Y), saturation ∈ \[0,2\]. Повторное кодирование и остаточный LUT: C4 \= clamp(C3 \+ trilinear(residual,C3),0,1).

4\. Семантическая коррекция в линейном RGB после глобального преобразования: для каждой из областей person/background отдельно применить EV в \[−1,1\] и saturation в \[0.7,1.3\]. Смешать результаты по мягкой маске; затем кодировать. Общая strength ∈ \[0,1\] смешивает исходный и обработанный линейный RGB перед экспортом.

Каждое ограничение диапазона должно учитываться в диагностике clipping. Отрицательные и сверхдиапазонные значения не должны молча исчезать из отчёта. Одиночный SDR-кадр не содержит восстановимых данных в полностью выбитых светах. HDR из брекетинга выполняется отдельным препроцессором до этого SDR-контракта по разделу 36\.

# **28 Оптимизация цветовой конфигурации**

## **Модель и функция ошибки**

Начальная модель — тождественная: gains=1, все кривые identity, saturation=1, residual=0, local EV=0. Оптимизатор Adam в PyTorch, float32. Нейросеть сегментации заморожена и выгружается до fit. Интерполяция LUT реализуется через 8 соседних узлов и gather; собственные CUDA-расширения и обязательный 5D grid\_sample запрещены.

L \= Lrgb \+ 0.2·Llab \+ 0.01·Ridentity \+ 0.1·Rsmooth \+ 0.1·Rfold. Lrgb — средний Huber в кодированном рабочем RGB, delta=0.02. Llab — средний L1 в Lab D50, делённый на 100, через фиксированные матрицы RGB→XYZ и Bradford. Цветовые формулы должны иметь эталонные тесты. CIEDE2000 используется для приёмки, не для backprop.

Ridentity — средний квадрат отклонения нормированных параметров и LUT от identity. Rsmooth — средний квадрат вторых разностей residual по трём осям. Rfold — средний relu отрицательных первых разностей выходного R по входному R, G по G и B по B. Это ограничение уменьшает инверсии, но не является доказательством глобальной монотонности всех цветов.

## **Последовательная оптимизация**

| Этап | Настройка по умолчанию |
| :---- | :---- |
| Параметрическая часть | 400 шагов, learning rate 0.01. Положительные приращения кривых и ограниченные gains. Затем заморозить эти параметры. |
| Остаточный LUT | Решётка 17×17×17×3, диапазон residual \[−0.25,0.25\], 600 шагов, lr=0.003. Для одной пары lambda identity=0.1 и smooth=1.0. |
| Локальные параметры | Если надёжная маска: 200 шагов, lr=0.01; глобальная часть заморожена. Локальная модель отключается, если контрольная ошибка не снижается минимум на 5%. |
| Выбор лучшего состояния | Контроль каждые 25 шагов. Остановка после 100 шагов без относительного улучшения 0.1%. Сохранять лучший checkpoint, не последний. |

Предусмотреть до 3 детерминированных начальных состояний параметрической части и выбрать лучшее по контролю. Все веса loss, число шагов и seed записываются в отчёт. Значения по умолчанию — исходная инженерная настройка, корректируемая только на train/validation, не на закрытом test.

## **Защита от переобучения**

При недостаточном покрытии цветов сравнить LUT-модель с параметрической на контрольных блоках; сохранять остаточный LUT только при улучшении median ΔE00 ≥0.2 без ухудшения p95 более чем на 0.5. Для непокрытых областей действуют регуляризация и предупреждение, а не произвольная экстраполяция.

Из полной глобальной функции каждого прототипа скомпилировать absolute LUT 33³ для смешивания. Проверить её против исходного ColorProgram на 100 000 равномерных RGB-пробах. При p95 ΔE00\>0.3 увеличить до 65³; если порог всё ещё не достигнут, adaptive не выпускать и оставить точный fixed renderer.

## **Признаки StyleKNN v1**

Вектор из 20 чисел вычислять на исходном рабочем preview до обработки: пять квантилей линейной Y (5,25,50,75,95%); средние RGB (3); стандартные отклонения RGB (3); среднее и std величины max(RGB)−min(RGB) (2); доли Y\<0.02 и Y\>0.98 (2); доля person (1); четыре средние Y по квадрантам (4). Порядок является частью feature\_version=stats20\_v1.

Standardization: μ и σ по обучающим прототипам, σ\_eff=max(σ,0.05). Если N=1, μ равен признакам единственного кадра, σ\_eff=0.05. Расстояние d \= sqrt(mean(((f−fi)/σ\_eff)^2)). k=min(4,N); wi=exp(−di²/2) / сумму весов. При точном совпадении признаков выбрать первый по pair\_id. Вычисления весов — float64 на CPU.

Смешивать полные absolute LUT одинакового размера и одинакового рабочего пространства. Локальные EV и saturation смешивать теми же весами; маску вычислять заново на новом снимке. Никогда не переносить координатную маску исходной пары на другой кадр. В fixed используется точный ColorProgram, в adaptive — его проверенная LUT-компиляция.

Для adaptive всегда вычислять сегментацию; RGB-признаки считать в линейном рабочем RGB. Отключённые local-параметры прототипа трактуются как identity. При ненадёжной маске нового кадра пропускать всю локальную стадию и ставить needs\_review. Хранить максимум 32 прототипа для LUT33 или 8 для LUT65: выбирать последовательным farthest-point по stats20, начиная с первого pair\_id; контроль качества повторять после сокращения.

## **Оценка области применимости**

Порог OOD-distance: max(1.0, p95 расстояний до ближайшего прототипа из другой съёмки ×1.5). Если разных съёмок недостаточно — 1.0 и статус uncalibrated. Также хранить посещённые bins сетки 8³ исходных цветов; на новом изображении считать долю пикселей в непосещённых bins.

Для adaptive, если d до ближайшего прототипа превышает порог либо доля непокрытых цветов \>20%, использовать общий fixed-прототип, записать needs\_review и причину. По умолчанию кадр всё равно сохраняется с диагностикой; \--strict отправляет его в skipped. По одному примеру уверенность переноса не может объявляться high.

Для серии разрешён явный \--group-fixed: один выбор прототипа для заданной пользователем группы. В текущем контракте добавляется явный модуль series из раздела 33; его решения и коэффициенты протоколируются.

# **30 Полноразмерное применение и экспорт**

## **B1 Загрузка конфигурации**

Проверить JSON Schema, schema\_version, renderer\_version, все диапазоны, длины массивов, конечность чисел и доступность model/profile IDs. Никакой повторной оптимизации, обращения к исходным парам или загрузки неизвестного кода. Неизвестная major-версия — CONFIG\_INCOMPATIBLE. Все стилевые числовые данные находятся внутри JSON.

## **B2 Анализ нового кадра**

Прочитать изображение, применить ту же ориентацию, RAW-проявку и ICC-конвертацию. Получить preview; для adaptive обязательно вычислить person mask и stats20. Для fixed маска нужна только при local.enabled=true. Выбрать fixed или adaptive по разделу 29\. Никаких автоматических histogram matching, enhancement или white balance поверх конфигурации.

## **B3 Полноразмерная обработка**

Применить выбранное преобразование к исходному разрешению тайлами 1024×1024. При нехватке памяти уменьшить до 512, затем 256\. Маска увеличивается в глобальных координатах bilinear; guided refinement на полном размере использует radius=max(1,round(8×long\_side/1024)). Для guided filter halo должен быть не менее 2×radius. После фильтра обрезать halo, записывать только центральный тайл.

Глобальные статистики и веса одинаковы для всех тайлов кадра. Нельзя повторно определять экспозицию или маску независимо внутри каждого тайла. Глобальный LUT не требует overlap. Последовательная запись через libvips либо дисковый memmap позволяет не хранить коллекцию в памяти.

## **B4 Экспорт**

По умолчанию TIFF RGB 16-bit, lossless Deflate, встроенный рабочий ICC. Опции: TIFF с выбранным поддерживаемым ICC, PNG16, JPEG quality=95 и subsampling=4:4:4 с sRGB. Настройки экспорта не должны менять параметры стиля. Размер сохраняется после нормализации EXIF orientation; тег ориентации в выходе равен 1\.

Для внутреннего master сохранить DateTimeOriginal, параметры камеры и объектив; для портала использовать отдельный metadata preset; GPS переносить только при copy\_gps=true в export policy. Не копировать устаревшие thumbnails, ICC, orientation и размеры без обновления. Имена: относительный путь \+ \_\_styled \+ расширение; при коллизии добавить первые 8 символов input SHA-256. Оригиналы не перезаписывать.

## **B5 Надёжность и отчёт**

Для каждого файла: запись локального рабочего файла → проверка декодирования и размеров → upload immutable artifact в MinIO → SQL commit результата и outbox event. Manifest содержит input/output artifact IDs и версии, hashes, config hash, status, prototype weights, OOD, clipping, model confidence, timings, backend и error code. Summary содержит success/review/skipped/failed, время и память. Atomic rename допустим только внутри локального scratch, не как транзакция MinIO.

Go восстанавливает run по сохранённым задачам; reuse только при совпадении input/config/export/model hashes и проверенном output hash. Повреждённый файл даёт completed\_with\_errors по коллекции; некорректная конфигурация отклоняет весь запуск до обработки. HTTP возвращает job status, а не process exit code; диагностический CLI может отображать его своим кодом завершения.

# **31 Алгоритмы beauty и исправления дефектов**

## **Первый пайплайн анализ до и после**

A1–A2 сохраняются для общего совмещения. Затем на исходнике и результате определить лица, pose и контуры человека. Сопоставить объекты по перекрытию после общего совмещения и расстоянию ориентиров; неоднозначное соответствие нескольких людей не использовать для обучения геометрии. Координаты нормировать относительно локального лица или тела.

Сначала оценить BodyWarp на структуре и ориентирах; цветовую разницу не считать геометрией. SciPy least\_squares подбирает ограниченные коэффициенты деформации по ошибкам landmarks, контура person и яркостных градиентов с robust loss soft\_l1. Для силуэта использовать границу маски, потому что 17 pose-точек не содержат точек талии. Фон и защищённые прямые включаются в штраф за деформацию.

Далее применить оценённую геометрию к исходнику и подобрать ColorProgram по разделу 28\. BeautyFilter подбирается после цветового fit по лицевым ROI исходного разрешения: ограниченный поиск smoothing, tone\_evenness, texture\_keep по реконструкции низких/средних частот и штрафу за потерю текстуры. Цветовой fit не должен компенсировать удалённые дефекты остаточным LUT.

DefectRepair анализирует небольшие локальные остатки после геометрии, цвета и бьюти. Сохранять пороги, допустимый размер и силу ремонта; координаты удалённого прыща не переносить в стиль. По паре нельзя надёжно определить, временное ли пятно: неоднозначные зоны показывать в отчёте как кандидаты. Внутренний fit сохраняет диагностические маски отдельно.

По нескольким парам оценить параметры отдельно, затем использовать взвешенную медиану только уверенных оценок. Для beauty/geometry v1 не смешивать деформации через цветовой StyleKNN. При слабых свидетельствах ставить enabled=false и needs\_review вместо придуманной силы эффекта. Предусмотреть API override силы и ручные якоря в per-image overrides.json.

## **Второй пайплайн новая коллекция**

Порядок выполнения: ориентация и ICC → landmarks/pose/маски на исходнике → выбор цветового прототипа → единый BodyWarp → глобальный цвет и локальные поправки → BeautyFilter → DefectRepair → экспорт. Маски и ориентиры преобразовать тем же warp; дефекты искать заново после геометрии. Изображение ресэмплировать геометрически один раз.

BeautyFilter: линейный RGB ROI лица разложить на low/mid/high; edge-aware база на радиусах 0.01 и 0.03 ширины лица, минимум 1 px. Ослаблять mid через smoothing, сохранять high через texture\_keep. Tone\_evenness сглаживает низкочастотные цветовые отклонения. Кожу выделять консервативным полигоном лица с исключениями по 68 точкам и цветовым gate; это приблизительная маска, не универсальный skin parser. При волосах, бороде и закрытом лице — пропуск сомнительных областей.

Для точечных дефектов: LoG/DoG-кандидаты диаметром 0.002–0.012 ширины лица, вне защищённых зон. По умолчанию policy=review: автоматический ремонт применяется только к разрешённым per-image маскам; остальные кандидаты сохраняются для проверки. Опциональный conservative\_auto включается явно и помечается experimental. Telea выполнять поканально на float32 для малых областей; крупные дефекты отправлять на ручную ретушь \[9\].

Предусмотреть проверку кандидатов в интерфейсе и через REST: PNG-карта с ID и JSON принятых/отклонённых кандидатов. Неподтверждённый дефект не удаляется. Команды review-export и apply \--overrides остаются диагностическими адаптерами API.

# **32 Геометрия и безопасные ограничения**

## **BodyWarp и ограничения качества**

Использовать обратное отображение output→input по регулярной сетке в ROI человека. Управляющие точки задаются симметрично относительно оси торса из pose и поперечных сечений силуэта; face\_slim действует на нижний контур лица, сохраняя глаза и нос. Поле displacement — гладкая комбинация локальных радиальных базисов с нулевыми граничными якорями. Совместные body- и face-поля объединяются до однократного OpenCV remap; положительный Jacobian проверяется численно.

Ограничить смещение 2% длинной стороны изображения и det(J)≥0.5 на плотной сетке. При нарушении последовательно уменьшать силу вдвое, максимум три попытки; затем пропустить geometry. Для сложного фона, пересечения людей, закрытой талии, сидячей позы или недостатка точек по умолчанию geometry пропускается с причиной. Leg\_length включается только при надёжно видимых тазе, коленях и стопах.

Защита фона: фиксированные якоря на границе ROI и вне person, дополнительный контроль прямых через OpenCV LineSegmentDetector. Гарантировать неизменность всех пикселей фона при изменении силуэта невозможно: без генерации возникают раскрываемые участки. Если небольшое смещение нельзя выполнить без заметного изгиба фона либо растяжения соседних деталей, пропустить модуль; не дорисовывать фон молча.

Модели запускать последовательно и выгружать между стадиями; batch=1, inference\_mode, float32. LR-ASPP до 768 px, SFD до 1024 px по длинной стороне, FAN на лицевых crop 256×256 согласно зафиксированному preprocessing пакета. Keypoint R-CNN: min\_size=640, max\_size=1024. Уменьшение входа относительно исходного профиля модели требует отдельной проверки точности.

Для warp тайл читать с запасом max\_displacement плюс радиус интерполяции; для бьюти — запасом радиуса фильтра. Нельзя использовать фиксированный halo только цветового пайплайна. После resampling повторно проверить маски, границы и корректность tiled/untiled; обработка дефектов — по отдельным ROI полного разрешения.

MPS-поддержка NMS/ROIAlign, FAN/SFD подтверждается конкретной сборкой; гарантировать CPU backend. Общие бюджеты всей системы, включая портал, находятся в разделе 42\. Скорость geometry/beauty измеряется отдельно от базовой цветовой обработки.

# **33 Отбор согласование серии и кадрирование**

## **Отбор и поиск**

На preview извлечь EXIF-время, SHA-256, DCT pHash и DINO embedding. Точные копии группировать по хешу; похожие — по cosine distance и времени. Начальные пороги pHash distance≤6, DINO cosine≥0.94 и интервал≤3 секунд являются настраиваемыми стартовыми значениями, не доказанными константами. Камеры со сдвинутыми часами требуют offset либо ручного объединения. Семантическая похожесть сама по себе не означает дубликат.

Рейтинг: нормированная резкость лица/предмета, смаз, clipping и открытость глаз по FAN eye aspect ratio. При маленьком лице, профиле, очках либо низкой уверенности eye\_state=unknown. Пользователь задаёт исключения для поцелуев и намеренно закрытых глаз. Выбрать N либо процент с квотами по сценам и сохранением ручных picks. Если годных кадров меньше N — сообщить дефицит, не дополнять брак молча. Выдавать объяснение рейтинга; never\_delete=true.

## **Согласование серии**

Группировать по времени, DINO и статистикам света; фотограф может объединять и разделять сцены. Эталон — пользовательский кадр либо medoid технически пригодных кадров. После индивидуального ColorProgram робастно оценить поправки общей экспозиции и RGB chroma по сопоставимым маскам: лицо/кожа, нейтральные области или общий сюжет. Между разными людьми не выравнивать кожу к одному оттенку.

Минимизировать отклонение от эталона с регуляризацией к индивидуальному стилю. Границы: EV ±0.35, каждый RGB gain 0.95–1.05, без изменения исходного художественного освещения при confidence ниже порога. Сохранять raw и applied correction. Если новая поправка ухудшает контроль clipping или качество эталонных областей — оставить предыдущий результат и отметить кадр. Порядок файлов не должен менять группировку и выход.

## **Кадрирование и перспектива**

AutoCompose: выбрать aspect\_ratio из пресета, headroom и положение лица/основного предмета; защитить landmarks головы и конечностей. Оценить горизонт и вертикали по LineSegmentDetector/Hough и RANSAC. При неоднозначных линиях предложить ручные опоры. Ограничить автоповорот ±5°, изменение площади перспективной коррекцией ≤15%; большая коррекция требует просмотра. Crop выполняется без растяжения; недостаток поля вызывает needs\_review или отдельно включённый outpainting.

Хранить правила композиции в style.json, вычисленный crop и homography — в per-image JSON. При анализе пары сначала распознать crop/перспективу и оценить общую область, а цвет и ретушь обучать на пересечении. Для crop-пар минимальная общая область может быть снижена с 90% до 50% при явном geometry\_alignment=crop\_aware; такие пары не участвуют в оценке полноформатной пластики.

# **34 Маски и портретные операции**

Все маски привязаны к ориентированному исходнику, имеют confidence, model\_id, transform и owner object\_id. Семантические logits повышаются до полного размера с edge-aware уточнением; новые детали маски не изобретаются простым upscale. Для каждого человека строить отдельный ROI. Для одежды базовый режим — MobileSAM с рамкой/точками, затем ручная коррекция; автоматический поиск любых видов одежды не заявляется.

Кисть, polygon, positive/negative point и защита областей обязательны в GUI. Объединение масок: сначала исключения, затем защищённые признаки лица, затем целевая область. Пересекающиеся коррекции одного свойства нормируются, чтобы не удваивать эффект. Карта масок и её преобразования к cropped/warped canvas записываются в журнал.

Локальные цветовые правила задаются массивом region\_adjustments: region\_id, selector, ev, saturation, hue\_deg, strength и priority. Диапазоны: EV ±1, saturation 0.7–1.3, hue ±15°, strength \[0,1\]. Для кожи hue по умолчанию 0\. Цвет одежды можно менять по подтверждённой маске без генерации фактуры. Неподдержанный selector или отсутствующая область даёт skip с причиной.

## **Портретные операции**

| Операция | Реализация и границы |
| :---- | :---- |
| Зубы и белки глаз | Внутри mouth/eye ROI выделить консервативные светлые области; светлоту увеличить до 0.2 EV, chroma уменьшить до 25%. Губы, радужка и блики защищены; если зубы не видны, пропуск. |
| Блеск и тени под глазами | Landmarks \+ skin mask; локальная низкочастотная коррекция до ±0.3 EV, сохранение текстуры и естественных бликов. Не удалять все складки кожи. |

## **Обучение по парам**

Оценивать силу только операций, которые идентифицируемы на паре; удалённые объекты и восстановленные детали исключать из цветового fit. Маски дефектов заново находить на новом фото. Для нескольких людей разрешены per-object overrides без обязательного распознавания личности. По одной паре невозможно вывести, каких людей и какие постоянные отметины фотограф захочет менять в будущем.

Вести operation\_evidence: fitted, inferred, user\_set либо unavailable; confidence и supporting\_pair\_ids. Нельзя выдавать установленный разработчиком default за параметр, извлечённый из пары. Для недостаточно различимых операций сохранять enabled=false и рекомендацию настройки.

# **35 Восстановление фон и генерация**

## **Шум резкость и увеличение**

SCUNet работает до стилизации на проявленном sRGB float32. Чтобы сохранить wide-gamut мастер, предсказанную поправку переносить через явно заданный обратный цветовой адаптер, контролировать gamut clipping; при выходе за допуск отключать модуль в этих пикселях. Нельзя молча сводить весь TIFF к sRGB 8 бит. Strength смешивает результат в линейном пространстве. Резкость — unsharp mask на яркости после ресайза, с порогом и ограничением ореолов.

Real-ESRGAN запускается после творческой обработки до output sharpening; финальные 2×/4× увеличивают число пикселей в 4/16 раз. Проверять лимит выходных пикселей и место на диске до начала. Никакая модель здесь не гарантирует восстановление прочитанного текста или настоящих деталей лица. Не применять одновременно сильное denoise и denoise-поведение upscale без проверки фактуры.

## **Маскирование и фон**

U2NET даёт начальную маску; PyMatting получает trimap и ограниченные полосы по границе с контекстом. На сложных волосах, стекле и сетке показать неопределённые области. Сохранять straight alpha; композитирование делать в linear RGB. Для товара поддержать белый/цветной фон, позицию, масштаб, поля, простую контактную тень и шаблон каталога. Исходный товар и текст сохраняются по защитной маске.

Для LensBlur относительную глубину разбить на слои, использовать маску переднего плана и заполнение скрытого фона возле границы; регулировать условную силу, а не обещать физически точную диафрагму. Небо менять по SegFormer с уточнением маски и заданным image asset; глобальный подбор цвета ограничен и отключаем. Не затрагивать архитектуру, провода и деревья вне разрешённой маски.

## **Удаление и генерация**

LaMa: выделить bounding ROI маски с контекстом, масштабировать до ограниченного canvas, выполнить восстановление и вернуть только разрешённые пиксели с плавной границей. Крупная маска без достаточного контекста — review. SD Inpainting: отдельный цветовой адаптер sRGB, mask=1 означает разрешённое изменение, исходные размеры и ROI transform сохраняются. После генерации жёстко восстановить защищённые пиксели исходника; влияние допускается лишь в маске и явно заданном feather.

Outpainting расширяет холст до выбранного формата и заполняет только добавленную область; итерации по сторонам фиксируются в журнале. Фон товара и сумеречный вариант используют выбранные prompt/negative\_prompt, seed и одну модель. Несколько вариантов показываются локально; final export включает только принятый. Виртуальная меблировка допустима как творческий вариант по маске с ручной проверкой масштаба, перспективы и геометрии. Физическую достоверность освещения не обещать.

По flattened-паре нельзя восстановить исходный prompt или seed. Analyze может оценить область изменения и класс операции; генеративный рецепт задаёт пользователь. Генерацию никогда не включать автоматически только из\-за необъяснённой ошибки реконструкции.

# **36 HDR экспортные пресеты и обратная связь**

## **Брекетинг и интерьер**

Вход HDR — явная группа 3–9 исходников одной сцены с exposure time и фиксированным WB; автоматическая группировка EXIF служит подсказкой. MergeDebevec с корректной response curve и временем экспозиций формирует linear float32 radiance; tonemap выполняется до рабочего SDR ColorProgram. Mertens fusion — отдельный режим для экспозиционного смешивания, результат не называть радиометрическим HDR \[23\].

Совмещение: MTB/SIFT на preview, затем один общий transform каждого исходника. Движущиеся области выявляются по остаткам и берутся из выбранного reference exposure; сильный parallax — review. Window pull переносит окно из недоэкспонированного кадра по подтверждённой маске и экспозиционному согласованию. При отсутствии деталей во всех экспозициях модуль не восстанавливает реальный вид из окна. Передавать radiance-тайлы или memmap, не складывать весь стек в RAM.

## **Экспорт**

Один запуск создаёт master TIFF16, web JPEG sRGB, PNG с alpha и дополнительные версии по named presets. Каждый пресет задаёт размер/пропорции, JPEG quality, ICC, watermark asset, naming template и политику метаданных. GPS по умолчанию удаляется из клиентских копий; авторство сохраняется по настройке. Прозрачный результат для JPEG предварительно композитируется на явно заданный matte.

Именование исключает коллизии и path traversal. Worker пишет immutable attempt objects; SQL commit выбирает актуальный manifest. В manifest — source version, derivatives и hashes, review, размер, ICC и параметры экспорта. Master сохраняется до watermark и выходной резкости. Resume разрешён только при совпадении input/models/settings/overrides/assets/renderer hashes.

## **Обратная связь**

Исправленные фотографом результаты можно добавить как новые пары с provenance. Analyze выпускает новую версию профиля и сравнивает её со старой на отложенных съёмках. При ухудшении профиль не заменять автоматически. Это обучение параметров и прототипов, а не скрытое дообучение нейросетей; операция имеет собственную команду и отчёт.

Стандартные presets: master — TIFF RGB16 с рабочим ICC; web — JPEG sRGB quality 90, длинная сторона 2400 px, без увеличения. Портал использует только явно разрешённые presets. В RAW bracket хранить group\_id, asset\_version\_ids, exposure\_seconds и reference\_input; несогласованная длина массивов отклоняется до расчёта. Публикация и подготовка ZIP — отдельные задачи после image export.

# **37 Канонический JSON стиля**

Стиль использует schema\_version=2.0.0; beauty/geometry описаны в разделе 38, extensions — в разделе 39\. style.json — UTF-8, без NaN/Infinity, размер по умолчанию не более 100 МБ. Нельзя помещать в него абсолютные пути исходных фотографий. Ссылки на модели обозначают фиксированные ресурсы установленного приложения; LUT, параметры, признаки и статистика полностью встроены. Для численного стиля дополнительных файлов не требуется. В текущем контракте пользовательские фоны, логотипы и небо хранятся в переносимом assets-пакете по разделу 39; ссылки и SHA-256 находятся в JSON.

| Поле | Тип и контракт |
| :---- | :---- |
| schema\_version / renderer\_version | Версия схемы semver и ID рендерера: 2.0.0 и photo\_renderer\_v2. Миграция только явной командой migrate. |

## **Точный формат LUT**

Поля: kind=residual или absolute, size=17/33/65, order=RGB\_C, domain=\[0,1\], encoding=dense либо constant, values — массив чисел. Dense содержит size³×3 чисел. Индекс значения канала c: (((r×size)+g)×size+b)×3+c; координата узла (r,g,b)/(size−1), каналы c=0,1,2 означают R,G,B. B меняется быстрее G и R.

Constant содержит ровно 3 числа и разворачивается на все узлы; используется для нулевого residual. Trilinear — линейная интерполяция по восьми углам. Вход ровно 1 должен попадать в последнюю ячейку с весом 1, без выхода за массив. Residual ограничен ±0.25; absolute — \[0,1\]. Проверять длину до выделения памяти.

## **Валидация и целостность**

Pydantic-модели с extra=forbid порождают photo\_style.schema.json; JSON Schema задаёт типы, enum и размеры, дополнительный валидатор проверяет монотонность кривых, одинаковый размер LUT прототипов и совместимость mode. Поставить валидные и невалидные fixtures. Хеш конфигурации вычислять по фактическим UTF-8 байтам файла и сохранять в run manifest.

В реальном результате quality обязателен; отсутствие test-данных выражается null, а не нулевой ошибкой. Внутренние checkpoint и alignment-матрицы сохраняются отдельно как диагностические материалы и не являются зависимостью apply.

Единственная выдаваемая analyze версия — schema\_version=2.0.0. Основные поля этого раздела, beauty/defects/geometry из раздела 38 и extensions из раздела 39 составляют один документ. Фрагменты ниже не являются отдельными стилями. Legacy 1.0.0/1.1.0 принимаются только через явную миграцию в 2.0.0 с disabled defaults и проверкой неизменности результата; неизвестное активное поле запрещено.

Это данные конкретного изображения, а не универсальные координаты стиля.

overrides.json: input\_sha256, object\_id, module overrides, accepted\_candidate\_ids, rejected\_candidate\_ids, protected\_polygons и optional manual\_landmarks. Все координаты задаются в нормированных координатах оригинала после EXIF orientation; при работе на изменённом файле несовпадение хеша — ошибка. Маски преобразуются вместе с изображением. В run manifest записывать requested/applied параметры каждого модуля и причины пропуска.

# **40 Промежуточные артефакты и provenance**

Переносимыми могут быть правила кадра, сила шумоподавления и бьюти, ограничения серии, параметры масок и композитинга. Выбор лучших кадров, HDR-группы, конкретные удаляемые объекты, готовые фоны и генеративные prompt не восстанавливаются достоверно из одиночной пары; эти поля задаются job/user и маркируются user\_set. Независимые маски не усреднять между фотографиями.

Для принятых HDR-групп culling оценивает reference и итоговый preview, а не отбрасывает крайние экспозиции как брак. После значительной геометрии маски переносятся тем же transform либо пересчитываются; для генерации повторная детекция нужна только в изменённой зоне. Очередность модулей фиксируется renderer\_version; произвольная перестановка пользователем запрещена. Генеративные варианты не участвуют в автоматическом обучении стиля без явного добавления пары.

| Артефакт | Поля и формат |
| :---- | :---- |
| PostgreSQL / embeddings.npy в MinIO | input SHA, metadata, scene\_id, burst\_id, 384D embedding float32, ratings, selected. Кэш моделей и preprocessing включён в cache key. |
| culling.jsonl / series.json | Причины рейтинга, duplicate\_group, eye\_state; reference\_id, membership, raw/applied EV и gains, confidence. |
| masks/\*.png / depth/\*.npz | Маски uint16 \[0,65535\]; depth float32 relative, invalid mask. Metadata: shape, source SHA, transform 3×3, model hash и координатная система. |
| image\_state.json | input SHA, schema, object IDs, normalized crop, matrices, requested/applied modules, evidence, review decisions и backend. |
| job.json / overrides.json | Input paths, bracket groups/exposure times, scene edits, output presets, resource profile; overrides bound to input SHA. Координаты после EXIF до crop. |
| generation.json / manifest.jsonl | Prompt, seed, scheduler config, model hashes, dtype, device, ROI/mask hash, candidate/accepted output. Итоговые status, errors, timings и output hashes. |

Priority: per-image override \> явный job override \> style \> schema default. Любое переопределение протоколируется. Переносимый style не содержит приватных исходных путей или пиксельных масок обучающих фото. Стадии могут сохранять временные файлы для resume; cleanup удаляет лишь подтверждённые временные файлы текущего задания.

## **Промежуточные артефакты analyze**

pair.json хранит pair\_id, before/after artifact versions и hashes, ICC IDs, orientation, размеры, alignment 3×3, valid\_fraction, split и preprocessing versions. previews.npz: before/after float32 H×W×3, valid\_mask и person\_mask float32 H×W. Кэш пары хранится в processing namespace MinIO и удаляется по retention после завершения run.

fit.json содержит числовые global/local параметры, loss history, контрольные метрики, color coverage и причину выбора модели. analysis\_report.json содержит отдельные результаты каждой пары, общий fit, качество переноса и список отклонённых пар. Для больших наборов сохранять только текущую пару в RAM.

В сервисе before/after/input paths обозначают artifact references, а не произвольные пути с клиента. Python разрешает только локальные файлы, материализованные из артефактов текущей задачи. В collection manifest включить source asset/version, published variant, thumbnails, processing run, model lock, ICC и checksums. В archive manifest — snapshot revision, preset, entry names, hashes и volume index; без secrets и чужих tenant metadata.

# **41 Caddy и домены HTTP HTTPS**

Только Caddy публикует пользовательские HTTP/HTTPS порты 80/443. APP\_DOMAIN обслуживает Expo web и /api/\*, PORTAL\_DOMAIN — Next.js и /api/\*, STORAGE\_DOMAIN — S3 API MinIO. Go слушает api:8080, MinIO minio:9000 во внутренней сети. Отдельный storage hostname сохраняет совместимость presigned S3 URLs; не переписывать подписанные path, query и Host. Административные консоли MinIO, RabbitMQ и PostgreSQL наружу не публиковать.

## **Базовый production Caddyfile**

{  
    email {$ACME\_EMAIL}  
}  
{$APP\_DOMAIN} {  
    encode zstd gzip  
    @api path /api /api/\*  
    handle @api {  
        reverse\_proxy api:8080  
    }  
    handle {  
        root \* /srv/expo  
        try\_files {path} /index.html  
        file\_server  
    }  
}  
{$STORAGE\_DOMAIN} {  
    reverse\_proxy minio:9000  
}  
Web-сборка Expo использует SPA export и fallback index.html; API matcher стоит до fallback и сохраняет /api prefix. Не применять handle\_path к API. Caddy получает dist web-сборки из multi-stage image. HTTP перенаправляется на HTTPS при публичной TLS-конфигурации \[40\]. Для ACME нужны корректный DNS и доступный challenge; /data и /config — persistent volumes. HSTS включать только в production после настройки доменов.

Поставить три конфигурации: public ACME, local HTTP (явный http:// адрес), local HTTPS с tls internal и инструкцией установки локального CA на компьютер/телефон. Не обещать доверенный сертификат для произвольного LAN IP. Native клиент использует доступный с телефона API\_BASE\_URL, а не localhost контейнера.

MINIO\_PUBLIC\_ENDPOINT совпадает со storage origin Caddy; внутренний SDK endpoint отдельный. Go подписывает URL под публичный Host. MinIO CORS разрешает APP\_ORIGIN и PORTAL\_ORIGIN, необходимые PUT/GET/HEAD/POST и headers, включая чтение ETag для multipart. Передачу больших файлов потоково не буферизовать целиком; лимиты размера — в upload policy, размер частей по умолчанию 16 MiB, настраиваемый. Проверить multipart, Range и истечение ссылки через Caddy.

Go доверяет forwarded headers только от Caddy в приватной сети; client IP не брать из произвольного X-Forwarded-For. Caddy admin API не выставлять наружу. Исключить query подписанных S3 URL и auth payload из access logs. WebSocket/SSE при последующем включении проксируются отдельным проверенным маршрутом; основной контракт событий — cursor polling \[39\].

{$PORTAL\_DOMAIN} {

    @api path /api /api/\*

    }

}  
Три origin: APP\_DOMAIN — Expo, PORTAL\_DOMAIN — Next.js, STORAGE\_DOMAIN — MinIO. /api namespace зарезервирован для Go и на portal host; Next.js API routes для бизнес-логики не использовать. MinIO CORS разрешает APP\_ORIGIN и PORTAL\_ORIGIN. API CORS не wildcard с credentials. Статические хешированные bundles можно кэшировать; manifest/guest session/job status — Cache-Control: private, no-store. Гостевые секреты не включать в access logs; fragment URL не попадает на сервер. /work/tmp не раздаётся Caddy.

Порты DB/Rabbit/MinIO для него bind только 127.0.0.1, отдельные credentials. Операции без MPS поддержки направляются в CPU очередь \[24,29\].

Ресурсный профиль охватывает все сервисы, включая Next.js, thumbnails и архиватор. Итоговые лимиты приведены ниже. Точные throughput и peak памяти подтверждаются обязательным benchmark; Docker/MPS ограничения сохраняются.

Compose запускает backend и web frontend. iOS/Android приложение устанавливается на устройство; Docker не заменяет iOS SDK/Xcode и мобильную сборку. Поставка содержит Expo dev/build инструкции, web Dockerfile и native config. Для базовой работы не требовать платного Expo EAS. Все функции имеют проверенный CPU путь либо явно измеренный backend-specific адаптер; несовместимый модуль не считается выполненным.

Добавить portal image (Next.js standalone output, non-root Node runtime, /public и .next/static в image), worker-media и worker-archive. Архиватор получает ограниченный temp volume; портал не имеет MinIO root/DB/AMQP credentials. Все серверные сервисы и оба web-клиента стартуют одной Compose командой; native Expo остаётся установленным приложением.

## **Совокупные лимиты памяти и временного диска**

Единый бюджет Mac CPU: Docker VM ≤24 GiB, совокупная инфраструктура Go+PostgreSQL+Rabbit+MinIO+Caddy+Next.js ≤5 GiB, один тяжёлый worker ≤14 GiB, media/archive совместно ≤2 GiB, запас VM ≥3 GiB; хосту оставить около 8 GiB. Это заменяет независимые лимиты, которые нельзя суммировать без учёта портала. Hybrid MPS: инфраструктура+media+archive ≤7 GiB, native ML worker ≤14 GiB, суммарный app budget ≤21 GiB и запас ОС. Scheduler снижает CPU parallelism при давлении памяти.

RTX: VRAM ≤9 GiB, heavy GPU concurrency=1; при 16 GiB host RAM вся система ≤10 GiB, heavy host working set ≤4 GiB, инфраструктура ≤4 GiB, media/archive ≤2 GiB; требуется tiling/offload и измерение. При 32 GiB host RAM общий app budget ≤20 GiB. Build выполняется отдельно от benchmark. На обеих машинах archive concurrency=1; thumbnail допускает приоритет, но bounded CPU/I/O, без голодания фоновых jobs.

Единый OOM policy: не более двух повторов с уменьшением sample batch 65536→32768→16384, color tile 1024→512→256, restoration tile 512→256→128, ROI 1024→768→512; выбранный profile сохраняется. После исчерпания — явный CPU fallback, если укладывается в бюджет, иначе failed/review. Local temp reserve ≥ ожидаемый размер ZIP \+ один буфер/рабочий файл \+20%; в MinIO также резервировать конечный архив. Сжатие заранее не гарантировать.

# **44 Численная приёмка базовой обработки**

## **Наборы и отсутствие утечки**

До основной разработки согласовать репрезентативный benchmark: минимум 60 пар из 6 съёмок для прототипа. Полные съёмки разделить на train/validation/test в пропорции примерно 60/20/20; кадры одной серии не должны попадать в разные части. Съёмки должны покрывать реально нужные жанры, освещение и диапазон экспозиций. Если доступны только 1–2 пары, принимается функциональность fixed, а качество обобщения остаётся неподтверждённым.

Метрики считать на одинаково совмещённых валидных областях, без удаления пикселей только из\-за большой ошибки. CIEDE2000 — Lab D50 после управляемого преобразования; SSIM и PSNR — sRGB \[0,1\], одинаковый resize до длинной стороны 1024\. На полном размере дополнительно проверять детали, границы масок и тайлов. Сначала агрегировать метрики по кадру, затем по набору.

| Проверка | Критерий |
| :---- | :---- |
| Синтетические пары | Известные преобразования внутри ColorProgram: median ΔE00 ≤1.0, p95 ≤3.0, SSIM ≥0.99 для ≥95% пар; при geometry.enabled=false геометрия не меняется. |
| Реконструкция реальных пар | Для ≥90% пар в согласованной области поддержки: median ΔE00 ≤2.0, p95 ≤6.0, SSIM ≥0.98. Остальные явно needs\_review. |
| Перенос на закрытый test | Для ≥80% новых кадров: median ΔE00 ≤3.0, p95 ≤8.0, SSIM ≥0.97; median ΔE00 набора минимум на 20% лучше identity baseline. |
| Оценка фотографом | На ≥80% test-кадров оценка «принимается» либо «нужна только небольшая глобальная поправка»; остальные — причина и категория дефекта. |
| Межплатформенность | Один JSON на CPU/MPS/CUDA: p95 ΔE00 ≤0.2 и max ≤1.0 относительно CPU; различия байтов файлов допустимы. |
| Тайлы и identity | Tiled vs untiled max error ≤2/65535 внутри рабочего RGB. Identity renderer ≤2/65535 без ICC roundtrip; ICC проверяется отдельно на эталонных патчах. |

Пороги — исходные критерии для поддерживаемых коррекций, не универсальная гарантия. Провал benchmark требует улучшения алгоритма либо явного пересмотра области применения до основной реализации; запрещено добиваться успеха незаявленным исключением сложных фотографий.

## **Функциональная и ресурсная приёмка базового режима**

100 фотографий по 45 Мп подряд на каждой машине: без OOM, утечек, изменения исходников и внешних облачных AI вызовов. Прерывание и resume не создают дубликаты. Повреждённый файл, неизвестный ICC, несовместимый JSON и нехватка диска дают ожидаемые коды. Проверить одну пару, смешанные размеры, пустую маску, одинаковые имена и перенос JSON между платформами.

Скорость измерить отдельно для analyze и apply: cold/warm start, p50/p95, decode, mask, fit, render, encode, peak RAM/VRAM. Начальная цель apply ≤60 секунд на 45 Мп TIFF и analyze ≤10 минут на пару; это ориентиры прототипа, окончательное SLA фиксируется после замеров на обеих машинах. Фактические измерения приложить к релизу.

# **45 Приёмка ретуши и расширенных функций**

## **Дополнительная приёмка**

Добавить не менее 30 пар с бьюти и 30 с поддерживаемой пластикой, с разбиением по людям и съёмкам; предусмотреть разные оттенки кожи, размер лица, фон и позы. На синтетических допустимых warp медианная ошибка ориентиров ≤0.5% диагонали ROI. Вне области влияния отклонение ≤2/65535 относительно результата с выключенной geometry. Не требовать геометрического совпадения с оригиналом при включённой пластике.

Контрольный набор: ≥500 кадров из ≥10 независимых съёмок, не менее 100 групп похожих кадров; отдельные 50 портретов, 30 сложных масок/фонов, 20 HDR-групп и 30 генеративных задач. Числа далее — проектные критерии, а не уже полученные результаты.

Отбор: ≥90% групп должны содержать хотя бы один выбранный фотографом кадр в top-3; ложное отклонение пригодных кадров как технического брака ≤2% (невыбор из\-за квоты N не считается браком); unknown и skipped публикуются отдельно. Серии: на валидных сценах медианное отклонение яркости от размеченного эталона уменьшается ≥20%, без увеличения доли clipped pixels более чем на 0.5 процентного пункта.

Маски: person/sky/основной предмет mIoU≥0.90 на согласованном наборе; волосы дополнительно оцениваются по границе и фотографом, mIoU не заменяет matting QA. Кадрирование: ≥95% автоматических crop не нарушают защищённые landmarks. Ретушь и очистка: ≥90% автоматически принятых результатов без заметных швов, восковой кожи и повреждения защищённых деталей; доля review публикуется отдельно.

Восстановление: сравнение с clean reference на синтетическом шуме и слепая оценка реальных кадров; включённый модуль не должен ухудшать медианный SSIM теста, а фактура проверяется отдельно. Генерация: нет изменения защищённых пикселей вне mask+feather до последующих экспортных преобразований; все финальные варианты имеют recorded acceptance. Качество генерации не оценивается совпадением с единственным эталоном.

Ресурсы: 100 кадров 24/45 Мп и каждый тяжёлый модуль на обеих машинах без необработанного OOM; 4×-выход тестировать потоково и с предварительным disk check. Логировать p50/p95 времени, peak RSS/VRAM/MPS и CPU fallback. Для SD seed воспроизводим в пределах зафиксированной среды; побитовое совпадение CUDA и MPS не требовать. Остальные допуски брать из базовой приёмки и измерять отдельно по модулям.

Регрессия: выключенные модули сохраняют базовый результат; orientation/crop/warp не смещают маски; ICC/alpha/EXIF отвечают пресету; model/assets/overrides hash участвует в resume. Offline означает отсутствие внешних облачных AI вызовов: внутренние MinIO/PostgreSQL/Rabbit запросы необходимы. Сеть SMTP/ACME относится к инфраструктуре, не инференсу.

## **46.1 Приёмка профилей и неизменяемости коллекций**

1\. В web/iOS/Android создать именованный профиль из одной пары и из нескольких пар, подтвердить соответствия, выполнить анализ, просмотреть реконструкцию, сохранить и повторно открыть после перезапуска. Конфигурация присутствует в JSONB; её экспорт/импорт сохраняет hash канонического содержимого и результат рендера.

2\. Применить одну сохранённую версию к двум новым коллекциям: каждый запуск создаёт отдельную целевую коллекцию и новые копии обработанных фото. Сверить hash исходных MinIO объектов, asset\_version IDs, membership, revision и опубликованные ссылки источников: они не изменились. Различные сюжеты оцениваются по прежним критериям качества, единый стиль не означает одинаковые пиксели.

3\. Переименовать профиль, добавить пары и сохранить v2: v1 и уже начатые runs не изменяются. Запущенный apply завершает работу по зафиксированной v1 даже после создания v2 или архивирования профиля. Анализ без валидных пар не даёт готового профиля; needs\_review не превращается скрытно в validated.

4\. Добавление/удаление фото, сортировка и переименование коллекции меняют её состав/metadata и revision без изменения изображений. Сохранение ручной правки одного фото создаёт новую коллекцию. Замена содержимого item и попытка PUT поверх существующего master отклоняются. Прямые запросы in\_place и чужого tenant запрещены.

5\. Двойная отправка apply с тем же Idempotency-Key и повтор RabbitMQ не создают вторую целевую коллекцию или дубликаты результатов. Retry восстанавливает ту же коллекцию; новый сознательный запуск даёт новую. Отмена/частичная ошибка видны в draft результате, исходник сохранён. Удаление исходной membership не ломает активный snapshot.

6\. Проверить выбранную часть коллекции, режим с сохранением остальных memberships, создание новых preview/thumbnail, отсутствие наследования share links и публикацию только по решению фотографа. Все новые тексты и состояния доступны на ru/bg/en и в обеих темах. Контракты, миграции, API-примеры и автотесты этих сценариев входят в поставку.
