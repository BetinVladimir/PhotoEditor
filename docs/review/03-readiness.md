# 03. Готовность частей системы

Проценты — **экспертная оценка** «до выпуска закрытого web-MVP по плану `docs/implementation-v2/mvp-web-release-plan-2026-10-20.md`», а не вычисленная метрика (сам проект осознанно не выводит процент готовности). Диапазон отражает неопределённость, потому что запуск тестов и приложений в рамках ревью не выполнялся.

## 1. Сводная таблица

| Часть | Что реализовано (факты) | Чего нет / риски | Готовность |
|---|---|---|---|
| **Backend: ядро** (auth, tenant, проекты, коллекции, загрузка, объектное хранилище, портал-API, скачивание) | Полный набор сервисов в `backend/internal/*`; оптимистичные ревизии (`If-Match`), идемпотентность, multipart-загрузка, подписанные ссылки, OTP-вход, роли `editor`/владелец | Нет rate-limit кроме OTP; нет метрик; монолитные регистраторы маршрутов (`catalogRoutes` 3,8 тыс. строк) | **75–80 %** |
| **Backend: обработка** (run/apply, v2 workflow, квоты, outbox, scheduler) | Apply v4, v2 render, outbox → RabbitMQ, DRR-планировщик, ресурсные резервы; миграции 2598–2609 для quota kernel | Scheduler на проде остановлен; цепочка 2616–2625 не применена на согласованной установке (план R6/R7); одна функция `ApplyCoordinator.build` на 2,3 тыс. строк | **60–70 %** |
| **Worker: CPU/media/archive** | Контейнеры в compose, операции `export.*`, `archive.*`, `metadata`, `quality`; проверки SHA/идентичности файлов | Устойчивость к VPN (см. [MVP/01](MVP/01-worker-and-vpn.md)); часть операций требует квалификации | **60–65 %** |
| **Worker: GPU CUDA** | RTX-установка (`deploy/rtx_installation.py`, `compose.rtx-worker.yaml`); реальный прогон Apply на 3 фото (запись в `docs/implementation-v2/implementation-remaining-2026-10-14.md`, 23.10) | Один сервер-образец; кластер GPU не описан; квалификация моделей «awaiting_evidence» по большинству операций | **50–60 %** |
| **Worker: Apple Silicon (MPS)** | Бюджет памяти Metal, CapacityPolicy, поддержка части операций | Нет пакета развёртывания («native-host»); не поддержаны семантика, learning, restoration; Metal-результаты не признаются доказательством для CUDA | **35–45 %** |
| **Photographer (web)** | 42 экрана, 126 языковых URL; импорт RAW/JPEG/TIFF с докачкой частей, коллекции, отбор, редактор, review, apply, экспорт, доставка, настройки, участники; i18n EN/RU/BG | Нет e2e; контраст и размер шрифта не измерены; только тёмная тема; в дереве маршрутов — отложенные функции (interchange, signing, training); native (iOS/Android) не принято | **55–65 %** |
| **Portal** | Выдача по ссылке-секрету, галерея с виртуализацией, выбор, скачивание (файл/архив), гостевая загрузка, 3 языка, доступный lightbox | Нет e2e; домен захардкожен; нет декомпозиции главного компонента; не проверены кэширование и нагрузка | **75–80 %** |
| **Биллинг** | Только БД и ядро квот: каталог (02598/02599: 7 планов, 36 лимитов, 45 офферов), quota kernel (02600/02601) в режиме shadow, enforcement в Apply/V2/Editor — за флагами opt-in/default-disabled; этап 1Б.7 «приёмка не завершена» (`docs/billing/STATUS.md`) | **Нет Stripe-кода** (grep по `backend`, `apps`, `packages`, `workers` пуст), нет UI кабинета, нет вебхуков/ledger интеграции, продажи закрыты | **25–30 %** |
| **Видеоредактор** | 24 документа спецификации в `docs/video` | Кода нет (нет файлов/пакетов с «video» в `apps`, `packages`, `backend/internal`, `workers`) | **0 % кода** (спека ≈ завершена) |
| **Развёртывание/эксплуатация** | Compose с hardened-настройками (`read_only`, `cap_drop: ALL`, `no-new-privileges`, immutable digests), провижининг секретов и CA, backup/restore-операторы, SBOM | Один узел, нет HA, нет VPN-схемы, нет метрик/алертов, нет CI, RabbitMQ без TLS в compose | **30–40 %** |
| **Тестирование** | ≈6 000 Go-, ≈7 000 Python-, ≈2 800 JS-тестов | Нет e2e в репозитории, нет CI, нет измерения покрытия; часть тестов не запускалась | unit ≈80 %, e2e ≈10 % |

**Итог по MVP: ≈55–65 %.** Код функций опережает доказательства: «сделано, но не принято». Основной остаток — не новые функции, а **замыкание контура**: установка → реальные фото → UI-проверки → восстановление → эксплуатация.

## 2. Обязательные условия выпуска (из MVP-плана) — состояние

| № | Условие | Состояние | Комментарий |
|---|---|---|---|
| 1 | Новая установка и обновление, цепочка миграций | 🔴 | Прод на 2597; план R6/R7 (лимит чтения migration source уже исправлен в `backend/db/validation.go`, apply не завершён) |
| 2 | Вход/сессия/приглашения + негативные сценарии | 🟡 | Много Go/SQL-тестов; браузерные сценарии разрознены |
| 3 | Реальные фото проходят основной путь | 🟡 | Прогон на 3 фото на RTX-сервере (Apply → encode JPEG/TIFF, верификация SHA) — хороший признак, но выборка мала; архивирование/ZIP и скачивание владельцем — «впереди» |
| 4 | Apply: атомарность, идемпотентность, отмена | 🟢/🟡 | Сильное покрытие тестами; живые concurrency-прогоны — по записям |
| 5 | Экспорт, публикация, отзыв, скачивание клиентом | 🟡 | Кодирование проверено; цепочка packaging → archiving → portal download не закрыта |
| 6 | Очередь/worker не теряют задачи при отказах | 🟡 | Fault-тесты есть (`make test-fault`); отказы сети VPN не покрыты (см. A2) |
| 7 | Backup/restore, purge tenant | 🟡/🔴 | Огромный объём оператора восстановления; «tests authored NOT RUN»; нет реального drill-отчёта |
| 8 | Размер шрифта/контраст измерены, основной путь проверен | 🔴 | UI-аудит статический; измерения (UI-14) не выполнены |

🟢 закрыто, 🟡 есть основания, но нет приёмки, 🔴 не выполнено.

## 3. Что в первую очередь определяет срок выхода в MVP

1. Применённая согласованная установка (миграции 2615–2625+) и включённый scheduler с рабочей топологией worker.
2. Минимальный сквозной e2e-набор для `photographer` и `portal` в репозитории + CI.
3. Устойчивый worker для удалённого запуска (VPN) и TLS-цепочка брокера.
4. Измерения UI (контраст/размер) и закрытие найденных UI-отклонений (`docs/ui-audit/PLAN.md`: UI-01…UI-14).
5. Явный allowlist маршрутов/функций MVP в клиенте (убрать отложенное из навигации).
