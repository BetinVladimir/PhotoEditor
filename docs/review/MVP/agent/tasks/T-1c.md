## Goal
Read-only analysis that lets a human (or a later card) write `deploy/compose.e2e.yaml` without re-reading the 370-line production compose file.

## Output (<= 100 lines, markdown, exact sections)
1. `## Services needed for e2e`: table `service | role | profile/flags | depends_on | needs secrets (names only)`; mark which services can be omitted for the 20 e2e scenarios (justify each omission in 6 words).
2. `## Environment variables`: table of the variables every kept service requires (`${VAR:?required}` items) with a proposed e2e value pattern (never real secrets).
3. `## Secrets and certificates`: files expected under `${PHOTO_SECRETS_DIR}` (list paths seen in the volumes), and which can be generated by `deploy/framevela/provision.py`.
4. `## Gaps`: things that the production file does NOT provide but e2e needs (mail catcher, seed data, worker with backend=cpu, fixed ports), each with a one-line suggestion.
Quote service names exactly as in the file.
