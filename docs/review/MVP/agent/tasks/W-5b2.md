## Goal
A mid-transfer connection loss must not discard the whole download. `ArtifactStream.read` reopens the object at the current offset with `open_range` (up to 4 times per stream, backoff 0.5/1/2/4 s) and keeps returning bytes. Full SHA-256/size verification is done by the consumers (`materialize`) over all returned bytes, so resume stays transparent and safe.

## Spec
- `ArtifactStream.__init__` gets optional keyword `reopen=None` (a callable `reopen(offset:int, remaining:int) -> (response, connection)`); store it.
- In `read`, where the code raises `GatewayError('DEPENDENCY_UNAVAILABLE', True)` after `OSError/HTTPException` or after an empty read with `_remaining > 0`: if `self._reopen` is set and `self._resumes < 4`: close the old response/connection quietly, `self._resumes += 1`, `sleep(0.5 * 2 ** (self._resumes-1))` (import `sleep` from `time`), `self._check_active()`, then `self._response, self._connection = self._reopen(self._size - self._remaining, self._remaining)` and retry the read. Otherwise raise as before.
- In `Gateway.open_stream` pass `reopen=lambda off, rem: self._reopen_range(ref, off, rem)`; add method `_reopen_range(self, ref, offset, remaining)` that calls `open_range(ref, offset, min(remaining, 16*1024*1024))` and returns `(response, connection)`. Because a range response covers at most 16 MiB, ALSO handle the end of a block: when the current response is exhausted (`read` returns b'' while `_remaining > 0`) the same reopen path continues with the next block (this is the case already described above - no extra code path).
- A resumed block must not exceed the remaining bytes: `ArtifactStream.read` already limits by `_remaining`.

## Test
Fake response objects: first one yields 10 bytes then raises `OSError`; `reopen` returns a second fake yielding the rest. Assert the concatenated bytes equal the original, `reopen` called with the right offset, and that a 5th failure raises `GatewayError('DEPENDENCY_UNAVAILABLE')`. Patch `sleep`.
