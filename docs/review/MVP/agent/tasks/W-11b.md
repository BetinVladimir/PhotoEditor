## Goal
The acceptance criterion of W-11 as code: after a fault scenario every submitted task has EXACTLY ONE committed result and no result row/outbox event/object is duplicated.

## Spec (`invariants.py`)
- `assert_exactly_one_result(rows_by_task: dict[str, list[dict]])`: raises `AssertionError` with the offending task ids for 0 or >1 results.
- `fetch_results(conn, task_ids)`: runs one `SELECT task_id, count(*) ... FROM photo.task_results WHERE task_id = ANY(%s) GROUP BY task_id` style query - FIRST read how `commit_success` in `database.py` writes results (which function/table) and query that table; if the table name cannot be determined from the code, answer `BLOCKED: result table unknown`.
- `assert_no_duplicate_outbox(conn, task_ids)` and `assert_no_duplicate_objects(object_keys)` (pure function over a list: duplicates by key).
- `test_invariants.py`: pure-function tests with hand-made dictionaries (no database): ok case, lost, duplicated, duplicate object keys.

## Do not
- Do not open a database connection in the tests of this card.
