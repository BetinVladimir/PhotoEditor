# Что нельзя отдавать модели 35B (окно 64k) «как есть» - и во что это разложено

Три причины, почему пункт плана не годится как одна задача: (1) нужен контекст больше окна, (2) нужны железо / секреты / решение человека, (3) цена ошибки выше цены ревью. Каждый такой пункт теперь **разложен до простых карточек (XS/S)** или до **чек-листа для человека**. Принципы разложения:

* **Механика вместо переписывания.** Код, который надо только переставить, переносит скрипт (`tools/move_routes.py`, `move_methods.py`, `extract_stmts.py`, `cards_from_plan.py`): модель запускает команду и чинит импорты, а не перепечатывает тысячи строк.
* **Анализ → утверждённый контракт → реализация.** Анализ - отдельная read-only карточка с фиксированным форматом вывода; человек утверждает контракт (ворота `APPROVED-BY`), только потом идёт код.
* **Страховка раньше правки.** Перед разрезанием - golden/характеризационный тест (`B-5a`, `B-6t`, `PT-4t`).
* **Нет стенда - тест собирается и пропускается** (`skip`), а прогон делает человек.

Условные обозначения: ✅ - полностью в карточках (человек только запускает и ревьюит); 🟡 - карточки + ворота человека; 🔴 - работа человека, после неё идут карточки.

## Чек-листы человека

**H-W7 - control plane.** 1) `python3 scripts/gen_worker_rpc_allowlist.py` и прочитать `rpc_allowlist.json` целиком: нет ли запросов, которых воркеру не нужно. 2) Миграция роли БД `photo_worker` (ей нужны только `EXECUTE` на перечисленные функции). 3) Включить профиль `worker-api` на одном сервере, воркер на одном GPU-хосте - `PHOTO_WORKER_CONTROL_URL`. 4) Сравнить через сутки `photo.task_results` с обычным воркером. 5) Откат: убрать переменную. Единая точка отказа до O-3 - зафиксировать.

**H-W8 - идентичность.** Выпустить сертификат на каждый воркер (`issue_worker_cert.py`), вписать UUID в `PHOTO_WORKER_ID`, завести файл отзыва, назначить дату вывода общего сертификата `framevela-worker`, пройти ревью безопасности.

**H-W11 - стенд chaos.** toxiproxy между воркером и PG / AMQP / gateway; compose-профиль `fault`; переменные `PHOTO_FAULT_STAND=1`, `TOXIPROXY_URL`, `PHOTO_FAULT_DATABASE_URL`, `PHOTO_FAULT_API`; затем `pytest -m fault tests/integration/fault -rs`. Результат (зелёный/красный по каждому сценарию) - в `release/`.

**H-B3 - baseline.** Выбрать версию N; `pg_dump --schema-only` полной цепочки и baseline+хвоста (`B-3b` сравнит); решить судьбу `ValidateBundle` (лимит 64 MiB); старые файлы миграций **не удалять**. Карточку установщика формулирует человек по результату сравнения.

**H-PLAN - планы декомпозиции (P-9, B-6, B-7).** Открыть `notes/<ID>-plan.md`: диапазоны не режут блоки, у каждого диапазона понятны параметры и результаты, нет выхода `return` из середины. Затем `python3 docs/review/MVP/agent/tools/cards_from_plan.py docs/review/MVP/agent/notes/<ID>-plan.md` (создаёт карточки `<ID>x-*`, цепочка снизу вверх), `agent.py check`, дальше обычная очередь. Для B-6 сначала зелёный `B-6t`.

**H-P3 - массовое форматирование.** Заморозить PR; `npm run format` в `apps/photographer`, `apps/portal`, `packages/api-client`; один отдельный коммит; добавить его в `.git-blame-ignore-revs`; починить тесты, читающие исходный текст (`grep -rln readFileSync apps/*/src --include=*.test.*`); включить `format:check` в CI.

**H-P4 - контракт журнала.** Прочитать `notes/P-4-contract.md` (особенно «Behaviour changes» и «Open questions»), ответить, заменить последнюю строку на `APPROVED-BY: <имя>`.

**H-B9 - scheduler HA.** Решить схему лидера/standby, поднять 2 реплики на стенде, убить лидера, проверить смену ≤ 15 с и отсутствие двойного `claim` (fencing); метрика `scheduler_is_leader`; затем 1-2 карточки XS на compose/метрику.

**H-B10 - биллинг беты.** Продуктовое решение: лимиты Trial, какие операции в `shadow`; закрыть OPEN-08 в `docs/billing/OPEN.md`; затем карточки XS на флаги.

**H-O2 / H-O3 / H-O9.** Прод: сверить конфигурацию с репозиторием (доступ только у человека). HA: решить схему из `05-deploy-and-ops.md` (O-3), затем карточки на отдельные compose-файлы узлов. GPU-хост: `deploy/gpu-worker/install.sh` по образцу `O-9b` после проверки на железе.

**H-O7 - секреты.** `python3 scripts/scan-private-ids.py`, решить по каждой находке (убрать / разрешить в allow-файле), заменить на `*.example`; ротация паролей ролей раз в 90 дней.

**H-T1 - e2e стенд.** По `notes/T-1-e2e-stack.md` собрать `compose.e2e.yaml` (секреты вручную), дождаться зелёного `smoke.spec.ts`, затем запускать пары `T-2eNNr/s`; `UNKNOWN` в заметках E-NN - вопросы к человеку.

**H-X - продукт и люди.** X-1 корпус и квалификация моделей (данные + GPU), X-2 слепая приёмка качества, X-6 почта/DNS, X-9 юридическое.
