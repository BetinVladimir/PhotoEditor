# MVP-08. Ревью первой волны доработок

Дата: 2026-10-24. Объект — изменения, описанные в [IMPLEMENTED.md](IMPLEMENTED.md). Вопрос: достаточно ли для выхода на MVP? **Нет.** Это начало этапа 0.

## Что сделано и чего это стоит
Закрыто около десятка из ≈ 60 пунктов плана — самые дешёвые: терпимость heartbeat и commit воркера, IP клиента за прокси, домен портала, ключи идемпотентности, MVP-профиль маршрутов, skip-политика, первый CI. Они снимают конкретные дефекты, но не доказывают работоспособность MVP.

## Что блокирует выход
1. **Нет ни одного сквозного прогона** на стенде (фотограф → загрузка → воркер по VPN → результат → доставка → портал).
2. **Код не верифицирован:** не запускались полные наборы Go/pytest/vitest, `next build`, `expo export`, `caddy validate`; `ci.yml` не выполнялся; правки `executor.py` без новых тестов (закрывают карточки `W-1a/b`, `W-3a`).
3. **Транспорт под VPN не доделан:** RabbitMQ без TLS (`W-6*`), агрессивные таймауты (`W-6a`), БД без keepalive (`W-4a`), нет спула результата (`W-3b…d`), нет докачки (`W-5*`).
4. **Эксплуатация не начата:** бэкапы/restore-drill (`O-5a`), мониторинг/алерты (`B-2*`, `O-4a`), runbooks (`X-8*`), секреты, откат релиза.
5. **Нет e2e** (`T-1*`, `T-2*`) и порога покрытия (`T-5a`).

## Слабые места внесённого
* `TRUSTED_PROXY_CIDRS` по умолчанию пуст — без значения в проде лимит OTP остаётся общим (исправляется настройкой и проверкой на стенде; документировано в `B-4b`).
* HSTS `includeSubDomains` на app-домене рискован, пока не подтверждён HTTPS на всех поддоменах; CSP намеренно слабый (без `script-src`) — это не защита от XSS (`PT-2a` не меняет этого, нужен отдельный этап с nonce).
* MVP-профиль фотографа скрывал только локализованные маршруты — нелокализованные `app/interchange/*` оставались доступными (закрывает `P-1f`); серверная защита добавляется картой `B-4a`.
* Конверсия сроков lease через настенные часы (W-12) не решена: до `W-12a/b` рассинхронизация часов GPU-хоста сдвигает окно записи; защищает только SQL-fence.
* Heartbeat-ретрай опирается на локальный монотонный дедлайн; при ошибке конверсии воркер может писать чуть дольше — безопасно за счёт SQL-fence, но требует теста (`W-1b`).
