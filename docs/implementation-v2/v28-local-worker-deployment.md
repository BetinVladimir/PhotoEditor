# V28 hair/clothing worker installation

The CPU worker registers `portrait.hair` and `portrait.clothing` only when `PHOTO_LOCAL_PORTRAIT_ENABLED=true`. Set `PHOTO_LOCAL_PORTRAIT_RUNTIME_LOCK` to an absolute, regular canonical lock file and `PHOTO_LOCAL_PORTRAIT_RUNTIME_SHA` to its lowercase SHA-256. Startup loads the lock and verifies installed Python/package/component bytes before either operation enters the registry. The inventory includes the SQL manual-origin authority and the deployment config; a lock generated for older source bytes must be regenerated and independently qualified.

The API installs `POST /api/v1/tenants/{t}/projects/{id}/local-portrait-mask-pairs`, `local-portrait-preparations` and `local-portrait-intents` when `PHOTO_V28_LOCAL_PORTRAIT_CONFIG` points to canonical JSON `{"projects":[{"enabled":true,"max_reserved_bytes":<integer>,"policy_sha":"<64 lowercase hex>","project_id":"<uuid>","runtime_sha":"<64 lowercase hex>","tenant_id":"<uuid>"}],"schema_version":1}` and `V28_LOCAL_PORTRAIT_SCHEDULER_DATABASE_URL` is configured for `photo_scheduler`. Startup checks manual-pair, owner, queue and qualification SQL functions. The API database pool remains separate under `photo_api`. The catalog returns original target/protected mask pairs and their physical pixels. Preparation verifies editor-selected hair/clothing Params and original mask producer without creating a run. Submission rereads original source and mask documents, computes CPU resources and reservation, compiles a server-owned immutable owner request, then uses the durable owner/admission path. The same key resumes only an identical saved owner request. SQL still requires a current licensed runtime qualification before graph sealing; configuration alone cannot enable either operation.

The installed route calls `sql_manual_local_portrait_operations`. Each task checks its `portrait_runtime_sha`, live attempt lease, canonical SQL manual-pair origin, declared immutable inputs and current producer evidence. The CLI does not register either operation when enablement is absent or false. MPS is not used for this CPU-only path; the separate GPU/MPS capacity policy remains unchanged.

Before registration, the worker checks that `v28_local_portrait_lease_ready` and `v28_worker_manual_pair_origin` are installed as `photo_fn_owner` `SECURITY DEFINER` functions with a pinned search path, worker EXECUTE and no API/gateway EXECUTE. A partially migrated database prevents the worker from advertising hair/clothing.

The environment-loader and `run_worker` handoff unit cases are authored but not run. A migrated SQL role/lease test, qualified runtime lock, measured CPU quality/resource evidence and full result→review→Apply acceptance remain required before V28 completion.
