# V30 delivery read/publish source reconciliation — 2026-10-13

Authenticated tenant routes for `GetDelivery` and `PublishDelivery` are installed in `backend/internal/httpapi/delivery.go`. Get delegates to `delivery.Service.Get`, which opens a viewer-scoped tenant transaction, reads `photo.get_v30_delivery`, and validates the closed public resource against tenant/package identity. Publish validates the requested revision and idempotency key, then `delivery.Service.PublishWithReceipt` opens an editor-scoped transaction, repeats SQL publication authorization, commits `photo.publish_v30_delivery` through the idempotency ledger, rereads the package and validates the revision and ready manifest before returning. The handler revalidates the public receipt and exposes replay metadata. Migrations 01776–01777 replace the earlier public read projection; source review must use the final function.

These source paths exist despite the older `partial_runtime_path` labels. They are not acceptance evidence. A migrated PostgreSQL run, denied-role/tenant matrix, concurrent revision conflict, idempotent replay, physical manifest readiness, HTTP/client round trips, and cancellation after SQL mutation remain unverified. No tests, builds, validators or migrations were run for this reconciliation.

The adjacent `v2.delivery.prepare` and `v2.delivery.assemble` CPU operations are also registered by `workers/photo_worker/runtime/service.py` when the explicit delivery installation is enabled. `resolve_delivery_installation` constructs a SQL-backed admission port; the adapter checks operation/profile identity, calls admission before and after work, and stages one immutable result. The older partial worker labels therefore need migrated SQL/adoption and actual worker execution evidence rather than another operation registration. No worker tests were run in this source review.
