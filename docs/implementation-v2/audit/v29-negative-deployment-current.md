# V29 negative producer deployment wiring

Status: authored, not built or executed. Migrations 01418–01427 are not applied by this work. This record is not qualification evidence.

The HTTP server now accepts `POST /api/v1/tenants/{t}/projects/{id}/negative-intents` with authenticated tenant write access, an `Idempotency-Key`, and a closed JSON body limited to 8192 bytes: `{schema_version:1,snapshot_id,params}`. Params follows NegativeParams (base, strength, film_base_rgb, calibration, exposure_ev). Source bytes are resolved from the accepted snapshot using scheduler SQL authority, read by immutable version outside SQL, verified against the original SHA and canvas, and looked up again after reading.

Deployment configuration is optional. Set `PHOTO_V29_NEGATIVE_CONFIG`, `PHOTO_V29_NEGATIVE_CONFIG_SHA256`, and `V29_NEGATIVE_SCHEDULER_DATABASE_URL` to enable it. Absence leaves the producer unavailable. A configured but invalid deployment fails startup. The DSN is required to establish `photo_scheduler`; startup checks installation of source document/array readers, transport registration, graph admission and queued receipt functions. Credentials must use the existing scheduler connection policy.

The bounded configuration document has schema_version 1 and 1–2048 projects. Each project contains tenant_id, project_id, pin (NegativeQualificationPin), policy (DeploymentLocks), and capacity (NegativeResourceEstimate). Tenant/project pairs must be unique. Pin and policy must agree on optical.negative version 1, CPU, issuer, model/runtime/device/dataset hashes and policy SHA. Capacity bounds pixel_count to 200 million, VRAM to zero for this CPU operation, positive exact JSON integer RAM/material scratch/output scratch/total scratch/output ceilings, and total scratch at least the sum of its parts. The request cannot override these values. Actual report/calibration bytes and installed SQL evidence remain mandatory; a matching configuration does not establish qualification.

The coordinator first tries historical queued receipt recovery. Otherwise it verifies qualification, capacity and physical source arrays, publishes immutable Params and transport through dedicated quota/fence repositories, registers the full closure, repeats current permissions/qualification and exact array versions in the sealing transaction, and saves the queued receipt atomically with activation/outbox. Any stage failure triggers read-only recovery; no activation is repeated within that submission. A stale receipt does not grant permission to replace a sealed run: draft-save authority must reject it. Receipt is a historical acknowledgement, not current job status.

Client API, persistent retry journal, current-authority calibration discovery and editor submission form are authored but not executed. GET negative-capabilities returns only configured calibration and pixel ceiling after catalogue authorization; this is not qualification/admission evidence. The form restores unresolved requests before authoring another body, freezes numeric inputs once an attempt exists, and reauthorizes workflow navigation. Remaining work: UI DOM and lifecycle coverage, full positive/negative SQL lifecycle fixtures, source mutation/ambiguous-commit integration coverage, and deep end-to-end verification after implementation. Native V31 signer deployment/qualification remains independent. Future GPU qualification retains the agreed Metal limit of 10,000,000,000 bytes; this CPU operation does not consume that budget.
