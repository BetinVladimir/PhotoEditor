# V26 render-review result selection source — 2026-10-13

Current finalization source still completes `render.compose` review runs only for accepted candidate routes. The public `/reviews/{id}/result-selection` route reads only `optical.negative`; render reject/skip has no authoritative selected-output read. A decided review alone must not rewrite or promote the produced candidate.

Added `CompileRenderResultSelection`, sharing the exact candidate decision-plan/hash verification with the existing negative compiler while requiring `render.compose`. Accept selects candidate, reject selects the source/base image, and skip selects no image. Authored unit cases cover all three routes, actor and kind substitution, and route tampering. Tests were NOT RUN under the code-first sequence.

Forward-only migration 01788 adds a scheduler-only `v26_render_review_selection` source: current adopted canonical task/result, exact root and candidate links, frozen Params source, original WorkingImage input, live ready/versioned artifacts and immutable decided review plan must all agree before it returns candidate/base/null. It is intentionally not an API grant. Migration NOT APPLIED and its SQL behavior NOT RUN.

Forward-only migration 01789 now exposes a principal-scoped `get_v26_render_review_selection` API projection. The Go reader reconstructs the immutable decision plan, checks project authority, compares the SQL selection to the compiled receipt, and the authenticated no-store route exposes that receipt. The photographer API and review screen read the decided render selection. The shared client parser validates the owned before/after references even for `skip`, so a malformed review binding cannot yield a valid-looking empty selection. Authored Go integration, HTTP, and client unit cases cover access and substitution boundaries. None were run, and migration 01789 was not applied.
