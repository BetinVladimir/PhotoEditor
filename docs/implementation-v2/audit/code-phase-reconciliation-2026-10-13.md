Do not count a Metal pass of unrelated modules as V28 completion.

## V25 device RAW selection

V25 device RAW was qualified server-side but the studio-agent sent no `raw_development` body. It now accepts a strict optional operator policy, freezes canonical JSON with the RAW source hash in the SQLite journal, and sends that exact choice on first and replayed device Begin. Non-RAW files do not inherit the policy. Config/HTTP/restart cases are authored, not run; the server remains the current physical qualification authority. Real camera/decoder quality and current-build SQL/device lifecycle remain open.

The agent now treats an explicit `503 QUALIFICATION_UNAVAILABLE` as an operator hold, preserving the exact capture and Begin key with a five-minute recheck but no transport-retry increment. Local status schema v2 reports counts for qualification and Begin-reconciliation holds without filenames or source hashes. Authored runner and status cases cover refusal followed by restored qualification and scoped hold counts; they are not run. Other 5xx responses retain normal bounded transport retry.

Source trace of V24 device upload found that a lost `NewMultipartUpload` response could leave an unknown remote multipart ID and the next Begin replay could start another writer for the same key. Forward-only migration 01960 now adds `device_begin_token` and fences any pre-existing initializing device rows. `ensureMultipartDevice` commits a claim under the upload row lock before the external Begin and attaches only the matching token; a replay after an ambiguous outcome returns `CAPTURE_BEGIN_RECONCILIATION_REQUIRED` without another Begin. The production capture starter binds the canonical staging key and uses the installed single-dispatch HTTP transport guard to prevent SDK retries from creating a second writer inside one call. `DiscoverCaptureMultipart` offers bounded read-only observation of the exact tenant/upload staging key with unique-ID and ambiguity checks. Forward-only migration 01961 adds an operator-only bind/release function with token, state, key, expiration and evidence gates; runtime roles receive no EXECUTE grant. The procedure and quiescence requirement are in `v24-device-begin-reconciliation.md`. SQL-backed lost-response, wrong-token, bind-replay and object-listing scenarios are authored, not run. A privileged operator must prove the original Create terminated before invoking the function; an empty listing alone cannot do so. Physical SQL/MinIO and process-quiescence drills remain open.

The capture Begin claim/attach transitions now require exactly one updated SQL row. A malformed multipart receipt is never attached; retry remains fenced. If attach fails or a changed row makes its result ambiguous, the API does not abort the returned multipart ID without renewed authority, and exposes reconciliation instead. An invalid-receipt replay case is authored, not run.

The V24 operator bind/release update does not touch columns watched by the existing device-binding trigger; the current upload table also grants the function owner the required update privilege. Source inspection found a separate pre-dispatch trap: an object-store adapter without `BeginCaptureMultipart` previously caused a durable Begin claim before the method-set check. An isolated SQL-backed case requires zero upload rows and zero external Begin calls for that configuration; it is authored, not run.
