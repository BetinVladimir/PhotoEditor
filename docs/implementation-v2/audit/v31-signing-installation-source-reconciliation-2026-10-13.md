# V31 signing runtime source reconciliation — 2026-10-13

The older V31 notes in `15-execution-contracts.md` describe production policy publication and signer installation as open at the time they were written. Current source has since added `ImmutableSigningPolicyPublisher`, `SQLSigningPolicyStore`, tenant-scoped signing service/router installation, pinned API and scheduler deployment installers, and `PHOTO_SIGNING_DEPLOYMENT_FILE`/`PHOTO_SIGNING_DEPLOYMENT_SHA` wiring in `backend/cmd/photo`. The API process installs `TenantSigningRouter`; the scheduler constructs a separate `photo_api` pool and its delivery signing runtime from the same pinned declaration. Startup rejects a declaration without trusted native/tenant handles, a noncanonical file path or SHA, and incorrect SQL roles. This corrects the source-presence inventory; it is **not** evidence that the full V31 package is accepted.

No tests, builds, SQL migrations, native SDK verification or worker execution were run for this reconciliation, following the agreed code-first phase. Open proof includes actual certificate/key/TSA and trust installation, policy publication and replay on a migrated database, valid/invalid SDK signatures after final encode, byte-tamper refusal, key rotation, privacy redaction, signed delivery, role isolation and purge/GC behavior. The percentage of the complete V20–V32 implementation remains unmeasured by requirement-level traceability.

Ready policy replay previously returned the SQL-ready reference without checking object storage. The publisher now verifies the physical immutable JSON object, including key, SHA, size, MIME and the pinned object version. Forward-only migration 01885 adds a tenant/editor-scoped private version read that repeats export authority and exact ready artifact predicates; `SQLSigningPolicyStore` uses it only for a ready reservation. Unit refusal cases cover unavailable/corrupt/mismatched-version replay, and an isolated SQL case checks private-function ownership/ACL and absent-authority refusal. All cases NOT RUN and migration NOT APPLIED; physical replay acceptance remains unproven.

The ready replay reader now opens the exact SQL-pinned object version and consumes its complete bytes with SHA/size verification. This replaces latest-version recovery in the ready branch: a newer latest version cannot substitute for the pinned one or hide a still-readable pinned version. First-time uncertain PUT recovery remains unchanged. Unit cases include a changed latest version with valid pinned bytes, missing pinned version and corrupt pinned bytes; they are authored but NOT RUN.

Signing lineage had the same ready-replay gap. Forward-only migration 01887 adds a tenant/editor-scoped exact ready-version reader tied to the export pins and ready backend document/artifact. `ImmutableSigningLineagePublisher` now opens that pinned version and verifies complete bytes and SHA before returning a ready replay. Changed-latest, missing-version and corrupt-byte unit scenarios and private SQL ACL/absent-authority assertions are authored but NOT RUN; migration 01887 is NOT APPLIED.

API and scheduler signing startup now require both ready-version SQL helpers, `photo_fn_owner` SECURITY DEFINER ownership/search path, API-only EXECUTE and no PUBLIC grant before installing a signing runtime. This makes migrations 01885 and 01887 prerequisites for the pinned deployment. Startup refusal and the shared SQL ACL assertions are authored but NOT RUN.

Both direct immutable publishers now require the exact-version object reader before reservation or first publication, including when called outside the service factory. This prevents a write-only adapter from creating an artifact that the same installation cannot safely replay. Direct-call refusal scenarios are authored but NOT RUN.

Native execution source recheck: `sign_staged` verifies the embedded JPEG/PNG manifest, full source/output hashes, unchanged decoded pixels, the SDK Reader result, independent certificate/lineage/binary binding and current operator installation before returning its receipt. `execute` independently rehashes the staged output before upload and rechecks source metadata after upload. This is source wiring evidence only. Actual loaded c2pa-python wheel/SDK, PKCS#11 key and certificate chain, TSA and revocation behavior, valid/invalid signed files, key rotation, privacy redaction and final delivery verification remain unqualified until the deferred physical acceptance phase.
