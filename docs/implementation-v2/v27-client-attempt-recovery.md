# V27: сохранение и восстановление клиентского запроса

Production editor использует PersistentSemanticCreate вместо временной SemanticCreate. Перед чтением журнала запрашивается текущий /me; storage key включает origin/user/tenant/asset/version/collection. До отображения сохранённых параметров текущая editor authority дополнительно проверяется: для принятого ticket через semanticRunIntent с точным совпадением run/workflow, для неизвестного результата через v2Binding исходного asset. Если binding ещё не был закреплён, текущая версия должна совпадать с editor route. Уже сохранённый binding/body не заменяется текущей версией: сервер повторно проверяет frozen source при admission/replay. Отказ/ошибка чтения скрывает всю форму и не запускает mutations. Неизвестный journal сохраняется с исходными ключами, а не превращается в новый запрос после ошибки прав.

Маска не включена в key: изменение текущей маски не должно скрывать уже отправленный неизвестный запрос. Scope wrapper при изменении mask/revision перемонтируется и перечитывает исходный журнал.

StoredSemanticAttempt содержит schema_version=1, snapshotKey/proposalKey, collection id/revision, mask document ref, kind/strength/ev/prompt, nullable binding/snapshot/body/ticket. Размер JSON ≤32768 characters. Decoder требует exact fields, ненулевые UUID, int64 decimal revision и полную валидацию SemanticEditIntent даже до получения binding/snapshot. Сохранённый body должен совпадать с frozen полями. Ticket допускается только при наличии body. Повреждённый журнал блокирует отправку, а не заменяется новыми ключами.

SemanticAttemptStore.read/write/clear выполняются через последовательную очередь. В browser очередь дополнена origin-scoped exclusive Web Lock, удерживаемым на всём read/check/write или clear. Отсутствие Web Locks запрещает browser storage IO; небезопасного fallback нет. Native runtime без document использует локальную очередь. write запрещает замену request keys, исходных параметров и уже закреплённых стадий. clear требует исходный proposalKey.

Origin epoch запрещает старым store читать/писать после logout в том же runtime. Для других browser contexts store при первом чтении закрепляет сохранённый generation token. Logout под той же блокировкой сначала записывает новый UUID generation, затем удаляет журналы origin. Старый store с прежним generation отвергается даже при независимом module epoch. Generation marker сохраняется после очистки, без request/prompt/user data. clearSemanticAttempts передаёт ошибку storage вызывающему коду; AuthProvider включает очистку в существующий logout workflow. Исторические записи без expiry намеренно не удаляются по времени: неизвестный результат нельзя считать несуществующим после локального TTL.

Перед первым сетевым вызовом persist записывает исходные ключи/параметры. После binding записывается binding до selectionSnapshot; после snapshot фиксируется его ID; перед Propose сохраняется точное тело. После 202 записывается ticket до navigation. Ошибка storage блокирует следующий сетевой этап. При неизвестном результате retry использует те же данные и ключи. Terminal rejection очищает только соответствующий журнал; исходные HTTP authority и idempotency проверки остаются серверными.

При восстановлении сохранённая collection revision и document mask имеют приоритет над текущим состоянием формы. Поэтому для продолжения не требуется заново рисовать маску, а изменение коллекции не меняет frozen target snapshot. Восстановление не выполняет POST автоматически: пользователь явно продолжает исходный запрос. Форму нельзя редактировать до завершения попытки. При наличии ticket повторная кнопка только открывает parent run, без нового admission и без зависимости от availability генератора. Ошибка navigation сохраняет ticket для следующей попытки.

AppState background скрывает форму, отменяет authority flight и перемонтированием отменяет submission flight; foreground заново читает /me, journal и текущую authority. Late authority/receipt-clear results ограждены lifecycle epoch и не могут вернуть форму в фон или чужой scope. OwnerAPI.me и semanticRunIntent передают AbortSignal в реальный SDK/transport. Повторная проверка не выполняет POST и не обновляет frozen intent.

«Начать другую серию» разрешено только для подтверждённого сохранённого ticket; удаляется соответствующая запись, форма получает новый scope. При отсутствии текущей маски новая серия остаётся недоступной до её создания. Неизвестный admission нельзя отбросить этой кнопкой.

Отдельный случай — подтверждённый сервером HTTP 410 с публичным кодом `SNAPSHOT_EXPIRED` для истёкшего target snapshot. После успешного exact-key удаления журнала форма допускает новую явную отправку с новыми snapshot/proposal keys; иной 410 не открывает этот путь. Неопределённый сетевой исход продолжает повторяться со старыми ключами. Если удаление журнала не удалось, новая отправка блокируется, чтобы не создать конкурирующую попытку. Component unit-сценарии написаны, но не запускались в implementation-first фазе.

Проверки: journal restore/principal isolation, immutable keys/stages, corruption/size, origin logout fencing и ошибка очистки, exact-key clearing; component remount после неизвестного snapshot/admission без live mask, frozen revision, receipt-only navigation при disabled capability, отсутствие IO до успешной записи, отсутствие повторного POST при ошибке navigation.

Отдельные независимые module instances проверяют конкурентные initial writes (ровно один winner), cross-context generation logout fence и browser без Web Locks (нет storage IO). Настоящий browser probe собирает production semantic-attempt-store.ts через Vite и загружает его в два независимых iframe contexts с настоящими localStorage/Web Locks; подтверждены один winner, один conflict и logout fence. Probe не использует React form/API admission и не доказывает полный пользовательский сценарий.

Recovery authority tests: 401/403/404 accepted-parent refusal, workflow substitution refusal, unknown request/source403 refusal, unchanged original body после продвижения current asset version, background hide/foreground recheck, aborted late source read и late receipt clearing. API/SDK wire test проверяет parent path и cancellation на /me/resolver.

Ограничения: remount DOM tests и browser journal probe не заменяют process-kill/full editor/browser/native acceptance. Два отдельных browser processes/tabs и несколько native JS runtimes ещё не проверены end-to-end. Recovery authority DOM tests и отдельно проверенная физическая SQL authority не заменяют единую end-to-end матрицу с реальным UI/API/отзывом ACL; lifecycle purge также требует сквозной проверки. Непрерывный отзыв доступа без background/scope change обнаруживается последующим server read/mutation; отдельного фонового authority poll у формы нет. Весь V27 остаётся implementing; producer orchestration и остальные обязательные gates не закрыты.
