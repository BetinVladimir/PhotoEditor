# Historical face ancestry in conservative interchange

Current source implementation (unexecuted): migration `02461_canonical_image_ancestry.sql` authenticates a local accepted source and its historical WorkingImage through completed canonical producer traces. Every hop binds tenant/project, succeeded task, canonical result, attempt/fence, declared exact image input and verified immutable object. Traversal is bounded to 128 hops with duplicate elimination. Matching canvas alone is never authority. `SQLImportHistoricalImageAuthority` binds this original source before import UUID remapping to one frozen entry and rechecks its source authority. It does not rewrite a historical master into the current source.

Both worker preparation and scheduler adoption accept an explicitly process-installed historical authority with three methods: `ancestors(context, authority, plan, read_document, require_contract)`, `qualify_ancestor(context, authority, binding, reference, image)` and `qualify_faces(context, authority, binding, landmarks_ref, landmarks, boxes, historical_image)`. The first supplies only authorized declared historical inputs; the latter methods must return literal `True`. Preparation receives worker context/admission authority; adoption receives scheduler scope/adoption context. Neither an archive callback nor document fields select this authority. Existing runtime/model qualification remains mandatory in addition to these checks. Omitted authority preserves the safe rejection of face-bearing conservative reports.

Face checks retain exact historical image and FaceBoxes references, require matching current canvas/transform/color, and bind each report face to exactly one landmark and detector object. Physical label arrays and PNG equality remain independent gates. Historical source pixels are installed into the existing bounded physical array validator only after original-producer authority succeeds.

## Local receipt production wiring — 2026-10-17 source update

The previously listed local transport links are now authored in source, without execution:

- `02467_historical_origin_receipts.sql` adds generated receipt publication authority. The certificate binds the existing ready prepared parent, original inventory identity, project/workflow/run/entry/target and current canonical image/detector/model/backend qualification. Scope helpers remain private to SECURITY DEFINER owners; only the independent adoption-run accessor is executable by the scheduler. It does not create a foreign authority.
- `HistoricalOriginIssuer` signs a domain-separated JCS payload containing the distinct original/prepared document refs, original image/boxes refs, original accepted source, model/backend and tenant/project/workflow/run/entry/target. `historicalReceipts` publishes each local historical dependency's signed document after exact native qualification and registers its immutable typed resolver.
- `ImportPreparedNodeRegistry.AdditionalImportRootsFor` contributes only privately issued receipt artifacts whose prepared parents remain in the accepted semantic closure to `ResolveImportInputInventory`; activation repeats actual receipt/object/native authority resolution. Receipts are independent authorization roots, not invented semantic children of archived FaceLandmarks. The existing input digest therefore includes their exact IDs and SHA values.
- `SignedHistoricalOriginAuthority.bind_inputs` is called separately for each admitted worker execution and each scheduler adoption. It authenticates Ed25519 against process-pinned public keys, current declared-input refs, exact scope and entry target. Each ancestor/face qualification rechecks the frozen input inventory and signed payload. Face-bearing semantic checks retain physical/model qualification and exact historical image/FaceBoxes/FaceLandmarks binding.
- Dense-warp geometry uses `ResolveHistoricalGeometryField`: after the complete original/current canvas/color/chain equality gate, only the exact field ref already declared by the authenticated current master may be reused. Matching SHA or matching coordinates alone is insufficient. Historical RGB/alpha arrays stay independently copied and byte verified; current RGB pixels never replace historical ones. This preserves exact geometry refs rather than manufacturing a different equivalent chain.

Scheduler operator configuration accepts `historical_origins` with `private_key_path`, `public_key_sha256`, `issuer_id`, `key_id`. The path is a canonical absolute operator path; the shared owner-only secret loader reads an Ed25519 seed and verifies the resulting public-key SHA. No key is selected by archive/request fields. Missing configuration leaves historical receipt issuance unavailable with `historical_receipt_issuer_not_installed`.

Worker `sql_prepared_import_installation(..., historical_trusted_keys=...)` and scheduler `SchedulerImportRecipeAdoptionInstallation(..., historical_trusted_keys=...)` install the same independent public verifier. Alternatively load a pinned operator public declaration using `load_historical_origin_trust(path, sha)` and supply the resulting `historical_authority`. The declaration has exact shape `{"schema":"historical-origin-trust/v1","issuers":[{"issuer_id":"UUID","key_id":"operator-key-id","public_key_hex":"64 lowercase hex characters"}]}`. Do not expose or copy the scheduler signing seed to workers.
