# Collection gallery filters and effective ordering

Current source candidate, 2026-10-17. No tests, migration or generators executed.

`GET /api/v1/tenants/{t}/collections/{id}/items` keeps existing callers and adds optional `search` (trimmed, at most 200 Unicode characters), `review` (`pending_review|accepted|rejected`) and `visibility` (`hidden|visible`). Existing section, rating, flag and exact tag predicates remain available. Search is case-insensitive literal substring over asset UUID, tags and the original filename proved by the exact tenant/project/asset → ingest binding → upload id/run relation. It does not guess an asset metadata filename. Filters run before pagination.

The owner gallery component reads every matching page under one collection revision, validates membership and unique identities, and rechecks collection revision after the last page. Filtering changes only the visible gallery/comparison input. Bulk selection, contact sheets, organization and metadata retain the complete source collection; filters never silently redefine their immutable snapshots.

Migration 02553 adds the invoker `collection_item_order(tenant,collection)` helper. `manual` orders by manual position/id. `filename` orders by the proved original filename using lower-case C collation, then manual position/id; missing filenames are last. `captured_at` orders genuine offset-qualified capture instants first, then unknown timestamps by manual position/id. Multiple distinct capture receipts cannot supply an invented instant. Item wire `position` remains the manual position. Private page cursors carry effective rank, collection revision, sort identity and all predicates. Historical position cursors are refused, requiring a fresh read. Portal uses the same effective order through its existing authorized definer function, preserving function OID and ACL.

Ordinary JPEG/PNG/TIFF and supported RAW headers may supply EXIF DateTimeOriginal. A valid OffsetTimeOriginal is the only timezone authority: it produces `captured_at` normalized to UTC seconds. A valid date without an explicit valid offset produces `captured_local`; this floating local value is deliberately not ordered as an absolute instant. No filesystem time, upload time, server timezone or rawpy naive timestamp is substituted. Missing/invalid EXIF is unknown. Existing assets without capture sideband remain readable and sort in the unknown group; this release does not backfill their objects automatically.

Capture fields are optional AssetMetadata sideband, source SHA bound by the existing inspect/adoption pipeline. Absent fields are omitted to preserve historical document bytes. WorkingImage and pixel/color/alpha manifests are unchanged. Go and worker readers reject contradictory or invalid calendar values. Installed adoption validation accepts only the new explicit sideband keys and refuses dual evidence.

API startup requires the actual helper identities, invoker/owner/allowlist ACL, canonical source joins, installed portal ordinal patch and adoption guards within a five-second bounded query. Workflow startup also requires adoption sideband guards before scheduling. These checks do not load image data or GPU models.
