### Принятый порядок ускоренного тестирования — 2026-10-17

Пользователь принял следующий основной порядок. Для каждого дефекта выполнить воспроизведение, исправление, затем весь затронутый функциональный модуль. Общий регресс запускать после объединения нескольких модульных исправлений, а не после каждого изменения. Повторить общий регресс раньше, если изменён общий контракт/валидатор/граница доступа и модульных проверок недостаточно.

Независимые потоки Python, Go backend, Photographer/Portal выполняются параллельно. Тяжёлый SQL bootstrap/clone/migration/physical storage lifecycle занимает один согласованный слот; Metal quality/load также занимает отдельный последовательный слот. Не смешивать нагрузочные замеры с другими GPU-задачами. Использовать прогретые репозиторные кеши и изолированные клоны подготовленного тестового шаблона, когда механизм проверен и применим; миграционные upgrade-сценарии сохраняют собственную историю.

Не ослаблять отрицательные authority/hash/fence/tenant/quality проверки ради скорости. Перед финальным релизом сохранить полный регресс, сквозные пользовательские потоки и проверку качества на реальных фотографиях. RTX installation/qualification отложены до предоставления сервера; Metal без искусственного 10 ГБ cap с реальными RAM/allocator guards. Исторические/промежуточные PASS не заменяют доказательство итоговой сборки.

## Рабочий цикл

1. Закрывать целый пользовательский модуль: данные/миграции → сервер → worker → клиент → сохранение результата и recovery. Использовать существующие общие механизмы и компоненты. Не создавать параллельную инфраструктуру там, где достаточно расширить действующую.

- Editor: единый coordinator, восстановление build/seal/final, клиентский маршрут и сохранение замороженного recipe. Авторские слои сначала реально композятся на исходном изображении; затем выполняются fullstyle/geometry, seal и окончательный identity compose. Финальный этап не исполняет слои повторно. - Обработка изображений: фактические маски сгенерированных пикселей, объединение coverage и её перенос через геометрию по реальным участникам интерполяции; сохранение качества результата и review фотографа.
- Интеграция: полный Download, сверка общих контрактов и миграций, центральный учёт завершения. Агенты согласуют общие контракты до изменений; номера миграций резервируются без пересечений.

Import, Review и Collection Apply учтены как закрытые по кодированию без исполнения проверок. Незакрытый исторический face-bearing interchange сохраняется отдельным явным разрывом. ## Актуальное подтверждение основного плана и параллельной работы — 2026-10-17

Пользователь повторно принял ускоренный план как основной и явно разрешил параллельных агентов. Этот раздел заменяет прежнее распределение исполнителей, сохраняя требования и рабочий цикл выше.

- Region / Metal: завершить реальный установленный renderer и полную типизированную цепочку входных данных, admission и provenance. Промежуточная поддержка цвета не закрывает весь модуль.
- Glare / OpenEyes: завершить lifecycle, актуальность consent и preview, отзыв недействительных результатов и штатное освобождение ресурсов.
