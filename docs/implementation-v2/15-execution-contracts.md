# Сквозные контракты исполнения v2.2

Этот документ уточняет 02, 09, 10 и 13. Поля определены JSON Schema; алгоритмы фотоопераций — в [16](16-imaging-algorithms.md), транзакционные границы — в [17](17-integration-security.md). Обязательны обе части, а не только DTO. Ограничение 5000 означает максимальное число кадров одного workflow; фактический запрос также обязан проходить byte/resource limits.

## Artifact closure и привязка к исходнику

`ResolveInputs(params, principal) -> FrozenInputs` выполняется до admission. VersionBinding.source — canonical WorkingImage artifact данной asset_version, а не encoded RAW. Его Canvas.source_sha256 указывает исходный content SHA. Сравнивать binding.canvas_hash с JCS(Canvas), а source.sha256 — с байтами документа WorkingImage. Оригинал и его content SHA разрешаются сервером через asset lineage. В задаче эта информация уже заморожена; worker не ищет её в БД.

`WalkArtifactClosure(root, expected_type, inventory) -> sorted refs` рекурсивно проверяет schema, tenant/project permission, SHA, MIME, размеры и тип каждой ссылки. Обход с visited(artifact_id,sha,type), depth≤32, максимум1000000 уникальных refs; цикл отклоняется. Несовместимое повторное назначение типа одному artifact отклоняется. Decimal revision/sequence проверяются также на int64 overflow. Весь JSON UTF-8≤8MiB, HTTP≤1MiB; превышение → PAYLOAD_TOO_LARGE до запуска. Snapshot digest считается по JCS объекта без самого snapshot_digest; порядок items — ordinal0..N−1. Artifact SHA считается по фактически записанным каноническим JSON bytes.

Params refs разрешаются следующим образом: snapshot у session.describe→InputSnapshot; v2 workflow input_snapshot в общем случае→WorkflowSnapshot (image InputSnapshot либо ArtifactSnapshot); manifest у learning→TrainingManifest; candidate/base_profile/baseline→CandidateProfile; shards у session.plan→DescriptorShard; context→SessionPlanContext или CaptureContext по operation; intent→EditIntent; candidates→TransferCandidate; confirmation→DonorConfirmation; source_faces/donor_faces/faces→FaceObservations; consents→ConsentSnapshot; profile у lens→LensProfile; depth→RelativeDepth; lines→LineSegments; assembly→DeliveryAssemblyInput; plan у interchange→InterchangePlan; request.bundle→InterchangeArchive; lineage→SigningLineage; policy у signer→SigningPolicy. Все mask/protected/effective_mask/subject refs→MaskRef. calibration у negative→NegativeCalibration, у остальных→Calibration. proxy→WorkingImage с binding того же исходника и явным TransformChain. signer.export→encoded ready export; parsed→ParsedInterchange; ParsedInterchange.files[].content и InterchangeResult.imported_files[]→тип из exact validated manifest inventory. BundleManifest сам inline JSON без удалённых refs. QualificationReport.input_fixture_shas — hashes evidence, не download URLs. DenseWarpTransform.inverse_field→NPY float32 H×W×2. SigningPolicy certificate bytes/SDK/trust anchors загружаются из operator allowlist по pinned hashes, не worker DB lookup. Nullable refs обходятся только при non-null.

Логические task declared_inputs содержат весь доступный транзитивный closure (wire передаёт bounded manifest по19), включая ICC/model/calibration locks, но не private keys. Worker возвращает один root role `document` (считается файлом) и новые вложенные artifacts в ролях operations.json. Ссылка на неизменённый declared input допустима без повторной загрузки. Required role означает обязательный reachable artifact этого типа; staged count может быть0 при exact bypass с input reuse. Для новых файлов max_count/max_bytes действуют независимо от этого. Нельзя возвращать неиспользуемые staged outputs. `ValidateOutputClosure` требует каждый staged member reachable из root, каждый ref либо declared input, либо exact staged member, и соблюдение reservation по сумме uploaded bytes. При несоответствии весь result rejected; частичная adoption запрещена. Политика gateway должна поддержать reuse inputs, а не требовать лишних фиктивных файлов.

## Обучение: от одобрения до activation

`ResolveRecipe(recipe) -> FrozenRecipe`: проверить все refs и source. В порядке base StyleV2 → session delta → pinned learning prediction → ordered parameter overrides → recipe.parameter_delta вычислить итог. EV складывается; log gains складываются; saturation_delta и retouch_delta складываются. Base neutral: exposure0, log gains0, saturation1, smoothing0. В StyleV2 применять gains_rgb[c] *= 2**ev * exp(log_c), saturation += saturation_delta, beauty.smoothing += retouch_delta (beauty.enabled=true при ненулевой smoothing). Значения должны оставаться в существующих StyleV2 bounds; иначе PARAMETER_RANGE, без скрытого clamp стиля. Clamp разрешён только на выходе inference CorrectionVector. Не менять tone_evenness/texture_keep. Слои с enabled=true и opacity>0 исключают пример из параметрического обучения с NONPARAMETRIC_EDIT; пользовательский рендер таких слоёв остаётся разрешён. base и approved используют один base_style; различающийся стиль исключает событие. Неизменённые baseline поля копируются byte-for-byte.

`ApproveDraft`: сохранить отдельный v2_document_approvals с exact recipe SHA и resolved_artifact_id(FrozenRecipe); immutable документ не UPDATE. Один approval/document; повтор с тем же документом возвращает тот же approval. Первый base checkpoint фиксируется сервером при первой записи draft с исходным StyleV2 и нулевыми дельтами, без ложного human approval; base checkpoint допускается только как baseline. Конечный approved document обязан иметь human approval.

`FreezeTraining(profile, events)`: фильтровать по10/11, разрешить каждый RenderCase, проверить одинаковую source/renderer/ICC/model версию, approval_id→approved recipe, наличие valid pixels, protected mask и FaceObservations. faces пустой допустим; отсутствие consent означает embedding=null, а не выполнение скрытого matching. Для measurable identity закрепить парой `effective_mask` и `consent_snapshot`: обе ссылки указывают на immutable документы того же source, маска имеет общий canvas/transform и unprotected=true, snapshot включает действующие identity_matching grants с точными epoch и подтверждёнными лицами. Если эту пару доказательств получить нельзя, поле опускается и holdout identity остаётся not_measurable; отсутствие refs нельзя заменять нулевой/единичной синтетической маской. Source lineage SHA идентифицирует исходный capture, не SHA повторного JPEG. Повторные/конфликтные события устраняются до split. Заморозить input closure для ВСЕХ examples, не только holdout; test запрещает доступ worker к БД/network вне gateway. baseline CandidateProfile имеет means0, scales1, coefficients0, intercept0 при отсутствии active version. Иначе exact active version SHA. Fit и evaluate сверяют, что baseline params и manifest.baseline одинаковы.

`PrepareTrainingDraft` повторно проверяет envelope manifest до записи recovery: уникальные event/source lineage, refs и binding исходника, пару identity refs, target/features bounds, consent epochs, точное назначение holdout по seed=2026 и минимум 20 train/10 holdout events при 4/2 сессиях. Для photographer каждый subject_group_id совпадает с project_id. Эта проверка не заменяет транзакционную проверку live grants и artifact lineage во Freeze.

`CompileTrainingDraft` связывает выбранный запросом список с заблокированным inventory CorrectionEvent, preselection и разрешёнными immutable RenderCase; затем выполняет детерминированный `FreezeTrainingSplit`, `CompileTrainingManifest` и `PrepareTrainingDraft`. Для каждого допустимого события нужны точные source content/lineage SHA, session, approval и frozen case; отсутствующее evidence отклоняет admission. `TrainingFitOrchestrator.Admit` последовательно закрепляет snapshot, публикует Fit params и transport closure вне транзакции, затем атомарно регистрирует closure и запечатывает начальный граф из одного Fit task. Replayed draft возвращается через идемпотентный ticket path и не публикуется повторно.

Рецепты, на которые указывают `correction_events.base_document_id` и `approved_document_id`, имеют тип `EditingRecipeV3`. Источник обучения читает exact artifact refs из inventory, сверяет JCS/SHA, общие source binding и base_style, затем применяет `ResolveRecipe` со всеми проверенными зависимостями и публикует отдельные immutable `FrozenRecipe`. Нельзя записывать refs исходных документов в `RenderCase.base_recipe`/`approved_recipe` и выдавать их worker как `FrozenRecipe`.

При компиляции frozen пары `CompileTrainingRecipes` использует существующий `v2draft.ResolveRecipe`, проверяет одинаковые source/style/ICC/model locks и сверяет `LayerStackRef` с точными JCS/SHA байтами. `TrainingLayerActivity` валидирует сам LayerStack и исключает только слои с `enabled=true` и `opacity>0`; отключённый или нулевой слой не меняет параметрический target. Происхождение LayerStack и остальных nested refs должен доказать scoped artifact resolver до вызова компилятора.

`TrainingLayerSource` получает LayerStack только через `v2draft.SQLArtifactCatalog.Lookup` с путём `EditingRecipeV3.layer_stack`, контрактом `LayerStack` и project/version scope. Затем он проверяет точную версию объекта, JCS/SHA и source binding. Если recipe содержит learning_version_id, compiler дополнительно требует точные model/descriptor refs, analysis_id и ordinal; если версии нет, эти поля обязаны быть пустыми. Проверка активности или provenance не может основываться на переданном клиентом boolean.

Перед выдачей `ConsentSnapshot` в `learning.evaluate` resolver валидирует JCS, grant/face связи и соответствие подтверждённых лиц frozen `FaceObservations`, затем `v23_pin_evaluate_identity_consents` под действующим Evaluate lease и tenant lock сверяет каждый identity_matching grant с текущими status, epoch, person и проектом. Функция закрепляет epoch в `workflow_consent_links` learning workflow; отзыв согласия после закрепления отменяет выполняющийся run. После adoption `v23_learning_version_consents_live` учитывает эти ссылки, а триггер отзыва identity_matching отключает уже созданные версии и снимает активный указатель. Повторный grant с новой epoch не реактивирует отключённую версию.

`RenderCase.region_masks` — необязательный массив до 128 элементов `{region_id, mask: ArtifactRef}` с уникальным `region_id`; каждый `mask` указывает на immutable `MaskRef`, чей бинарный ребёнок имеет тот же canvas и TransformChain, `protected=false` и проверенный producer lineage. Fit замораживает корневые refs, Evaluate включает корни и `MaskArray` детей в closure. Evaluate resolver сверяет точное множество `region_id`, selector и confidence≥0.75 с замороженным StyleV2 до admission; worker повторяет проверку и применяет маски в том же порядке, что `image.local`. Отсутствие правила или маски отклоняет holdout, не даёт молчаливый skip. Admission учитывает дополнительные `4 × pixels × region_count` байт scratch у крупнейшего последовательного кадра.

`EvaluateCandidate`: проверить manifest/profile/training_sha/renderer/locks и split из10; evaluate cases строго holdout, один case на event. Для каждого кадра рендерить frozen base с baseline prediction, candidate prediction и human-approved recipe одной renderer версией. Protected pixels: max absolute RGB error(candidate, baseline) на protected>0 должен быть0; пустая маска даёт0. Цвет: ICC pinned conversion к Lab D50, CIEDE2000, valid=alpha>0, исключить invalid pixels. Percentile — sorted nearest rank ceil(.95*N)−1; tile streaming в детерминированном ordinal/pixel order, внешняя сортировка при необходимости; пустой valid set → EVALUATION_NOT_MEASURABLE. На case вычислить p95 разницу color и clipping fraction разницу. Aggregate color_p95_delta=max(case.color_delta), clipping_delta_fraction=max(case.clipping_delta); ухудшение одного кадра не скрывать усреднением. Loss — среднее по всем holdout events по10.

Identity safety вычислять примитивом16, поставляемым уже в V23. `no_person` допустим только при успешном face detector без найденных лиц; failed/unqualified detector → not_measurable. `fail` любого лица или protected error>0 ⇒ safety_status=fail. Иначе любой not_measurable ⇒ not_measurable, иначе pass. `metric_eligible` означает все численные quality/loss gates прошли. `eligible = metric_eligible && safety_status==pass`; ни worker, ни human не меняют immutable Evaluation. Adoption создаёт version_eligibility: rejected при fail/!metric_eligible; needs_review при metric_eligible+not_measurable; eligible при pass. Human review не может переопределить fail или численную регрессию.

`ReviewLearningSafety(id, expected_revision, evaluation_sha, accept, reason)`: creator/Owner; revision относится к version_eligibility, проверка всех consent epochs; только needs_review. Сервер проверяет exact evaluation SHA и metric_eligible. Сохранить immutable learning_safety_reviews, audit; accept→eligible, reject→rejected; reason непустой≤256. Это решение об измерительно неопределённом результате с просмотром before/after holdout, не изменение метрик. GET ListVersions.revision=eligibility.revision, review_id=последний review. Activate по-прежнему отдельная явная команда. После revoke даже accepted review не восстанавливает disabled.

## Review до5000 целей без преждевременного завершения

`ApplyApproved` работает только при parent waiting_review. expected_revision — runs.revision. Lock порядок17, проверка exact plan_sha, unique1..100 targets, все принадлежат intent, каждый ещё proposed. Сформировать decisions artifact и immutable v2_review_batches. Approve создаёт один child legacy Apply на выбранные targets, source-bound overrides, target.state=queued и child_run_id/batch_id. Reject→rejected, child_run_id=null. Если approve0, child=null и GPU/quota для Apply не резервируются. В одном commit также увеличить parent run revision. Ответ ReviewBatchResult.remaining = число proposed после batch. Unsupported/rejected уже считаются рассмотренными. Повтор Idempotency-Key возвращает исходный результат; новый ключ для ранее решённой цели409, без смешанного частичного успеха.

Parent остаётся waiting_review даже при remaining0. `CloseSemanticReview(expected_revision,plan_sha)` допускается только remaining0, сохраняет close batch, делает parent completed. До этого пользователь может закрыть страницу и продолжить review позже. Child completion обновляет только queued targets своего child: applied/failed/cancelled, никогда parent terminal. Parent completion означает закрытие решений, не успешное исполнение всех children. UI показывает оба уровня. Cancel parent запрещает новые batches, но не отменяет ранее admitted children; UI предлагает отдельный cancel этих run IDs. Повтор неудачного child — новый явно созданный semantic workflow над выбранными версиями, а не изменение уже принятого решения.

`ApplyAnalysis` остаётся одноразовым: approved_groups полный окончательный выбор из существующего плана; остальные группы явно отвергнуты этим действием. Parent expected_revision + plan_sha + source binding; один child Apply и завершение parent атомарно. Пустой выбор — CancelWorkflow. Это отличие от постраничного semantic review необходимо отображать в UI.

`AnalysisApply.recipe` указывает на принятый `style_versions.export_artifact_id` (`StyleV2`) того же проекта; SHA равен `config_hash`. Для каждого кадра выбранной группы сервер проверяет точный frozen InputSnapshot, CorrectionPlan и disposition, компилирует отдельный source-bound `OverrideV1` из базового StyleV2 и CorrectionVector, затем передаёт его соответствующему `style.resolve` дочернего Apply. `no_change` и `manual_locked` дают нулевой CorrectionVector. Неизменённые модули StyleV2 сохраняются, граф Apply включает объединение нужных стадий, а невыполнимая модельная привязка даёт 409 до создания child. Child selection snapshot содержит только кадры выбранных групп; SQL commit сверяет его точный item/version/artifact/SHA состав с родительским snapshot и сохраняет одно неизменяемое решение.

Повтор `AnalysisApply` с тем же ключом вычисляет SHA всего решения и до чтения истекающих объектов вызывает `v22_analysis_apply_replay` под текущей authenticated session. SECURITY DEFINER функция проверяет editor ACL, принадлежность shoot session, сохранённую idempotency запись и immutable decision, не выдавая API-роли прямой `SELECT` на таблицу решений. Совпавшее решение возвращает исходный child `run_id`; чужой SHA или повторное использование ключа для другого анализа даёт 409. Новый Apply проходит полный preflight и атомарный commit родительского решения с admission дочернего запуска.

## Delivery: полная декартова матрица

`FreezeDelivery`: frozen snapshot ordinals0..N−1, disjoint unique required/optional presets≤16. Для каждого snapshot ordinal × preset создать ровно один delivery_item; store preset_sha и required. Contact sheet является отдельным явно выбранным существующим preset/export resource; не создавать его неявно. Хранить ссылки на frozen preset config, не читать изменившиеся presets во время assembly.

`ObserveExport`: экспорт ребёнка может failed/cancelled без fail_fast родителя: это внешний child run, не failed task его sealed graph. Required failure ⇒ parent failed, package failed, publication невозможна. Optional failure ⇒ omitted только allow_omitted=true с непустым reason; иначе package failed. Состояния pending сохраняются до terminal child. Не запускать assembly при pending. Экспорт успешен только при ready, exact snapshot binding/preset SHA и при required provenance — проверенной подписи финальных encoded bytes. В V30 provenance required возвращает503 до квалифицированного V31; off полностью работает, зависимости пакетов не цикличны.

`BuildAssemblyInput`: отсортировать slots по(ordinal,preset_id), разбить по500, сохранить immutable DeliverySlotShard и DeliveryAssemblyInput. Это server-side preparation до leased assembly; повтор не меняет canonical SHA. Worker получает только assembly closure, не голый список export refs. Проверить slot_count=N*P, каждый pair ровно один, одинаковые snapshot_digest, preset_sha/required, bindings одного ordinal совпадают, ordinal range, presets exact. ready⇒export_id/export non-null и reason=null; omitted⇒optional && allow_omitted && reason nonempty && export_id/export null. failed в финальном manifest запрещён. Ready_count≥N*required_count. Output DeliveryManifest с assembly_sha и ссылками на ТОЧНО эти shards. Нет giant80000-items JSON root.

`AdoptDelivery`: только проверенный manifest, package state=review при require_review иначе ready; parent waiting_review/completed соответственно. `PublishDelivery(CAS package.revision)` одновременно является явным human acceptance в состоянии review: actor подтверждает весь frozen manifest, audit содержит SHA; lock package+parent, CompleteReview и ready+published_at+publication в одной TX. При ready публикация без повторного review. Запрет публикации при failed/cancelled, revoked inputs, missing provenance; новых email/SMS эта команда не отправляет. Повтор возвращает первоначальный publication. Истечение share links не меняет immutable manifest.

## Interchange: экспорт и импорт

`FreezeInterchangeExport`: InterchangePlan.entries уникальны по entry_id/external_id/path; привязки к snapshot, frozen recipe и encoded content. Все пути — UTF-8 NFC, relative POSIX, без empty/./../backslash/colon/NUL, casefold-коллизий; длина≤240. ZIP64, no encryption, regular files only, max30000 files, archive≤64GiB, expanded≤128GiB и меньшая tenant reservation. Compression ratio≤100:1 для каждого compressed entry и всего архива. Stream file count/bytes/hash, не доверять central directory. JSON/XML parser depth≤32, XML≤1MiB, без DTD/entities/network.

`ExportInterchange`: порядок записей path ascending; timestamps фиксированы1980-01-01, uid/gid omitted, compression stored для изображений, deflate level6 для sidecars. Создать manifest.json, изображения, sidecars, поддерживаемые mask files. Root InterchangeResult.bundle обязателен, report обязателен, draft_shards=[]; ZIP отдельная declared роль bundle. JSON/NPY recipes из архива остаются untrusted bytes до remap/validation; parser не регистрирует их как approved documents. Это двухфазный workflow: parser планирует entries/mapping; server после canonical ingest собирает proposed recipes, mapping shards и report как fenced CPU stage. Final InterchangeResult содержит только completed proposals, а не ссылку на будущий artifact. Imported artifacts входят в adoption inventory и lineage даже если корневой report ссылается на них через recipe→WorkingImage→original provenance; explicit original content refs сохраняются в InterchangeResult.imported_files; output files этой фазы являются declared inputs от parse. Формат PhotoEditor bundle: `manifest.json` с schema_version=1, entries[{entry_id,external_id,image_path,image_sha256,recipe_path,recipe_sha256,rating,pick,crop}], masks[{path,sha256,canvas_hash}], renderer_version="v2.2". Foreign learning models, consent, approvals, private signing policies не импортируются; resolved supported parameter values сохраняются, unsupported dependency блокирует proposal. Consent новых persons revoked. Архив не является резервной копией БД.

Crop в ориентированном normalized canvas, inverse EXIF orientation перед переводом в canonical canvas; invalid/rotated arbitrary-angle crop unsupported. WB/curves/RAW development не объявлять exact между различными renderers. captureone_sidecar в v2 читает/пишет только этот XMP subset рядом с TIFF; proprietary .cos/catalog unsupported. PSD/PSB не входит в baseline exporter: unsupported до отдельной qualification, не подменяется TIFF.

Import в существующий project создаёт отдельную draft collection и новые assets через обычный ingest, не обновляет старые. Proposed document сохраняется отдельным draft stream; user approval только через `DecideImport` batches1..100, CAS parent run revision и report_sha. approved выставляет approved pointer+immutable approval; rejected не публикует документ. Rejected bytes уходят обычным retirement/GC после удержания audit metadata; исходный загруженный bundle удаляется только обычной authorized deletion/retention policy. История решений сохраняется в v2_review_batches.

## Session, capture, semantic и signer

Ранний `v22_analysis_replay` принимает текущий authenticated session ID и перед возвратом сохранённого ticket заново проверяет editor ACL проекта и принадлежность исходной shoot session. Истёкший selection и изменившийся recipe при sealed replay не перечитываются; отзыв доступа прекращает выдачу ticket.

`SessionAnalysisRuntime.Coordinator` собирает SQL starter, frozen selection, consent pinner, document publisher, transport, stage, graph commit, профили и ticket reader на одном pool роли `photo_scheduler`. Transport создаётся отдельно для каждого draft и получает его tenant/run; общий publisher без этих scope не допускается. API вызывает этот coordinator только после проверки principal и project ACL, а SQL-фазы повторно авторизуют перед мутацией.

HTTP `AnalyzeSession` получает principal из существующего auth middleware и вызывает `v2sessions.Service.Analyze`. Сначала выполняется scheduler-role `Probe` по каноническому хешу запроса: sealed replay возвращает сохранённый ticket без preflight истёкшего selection; новый запуск проходит API-role preflight, получает qualified model lock и резервирует `128 MiB + 4 MiB × item_count`, затем вызывает полный coordinator. Успешный HTTP `202` выдаётся только после чтения sealed ticket. До установки всех функций admission V22 маршрут возвращает `DEPENDENCY_UNAVAILABLE`; API-role pool не получает прямых прав scheduler.

Для pending retry первая транзакция `begin_v22_analysis_draft` вместе с `save_v22_analysis_recovery` сохраняет в ещё не завершённом idempotency record точный InputSnapshot, SessionPlanContext, их SHA, model lock и размер резерва. `read_v22_analysis_recovery` повторно проверяет actor/session ACL, статус draft, snapshot/config hashes и действующий quota reservation. Go пересчитывает digest snapshot и context и проверяет структуру до публикации. Поэтому pending retry не зависит от срока selection; immutable recipe выбирается по сохранённому ref из исторического draft document той же asset version, даже если текущий draft уже изменился. При seal поле pending recovery заменяется сохранённым `202 JobTicket`.

`ValidateScenePlan`: ordinal каждого кадра встречается ровно1 раз, reference входит в свою группу; corrections совпадают по cardinality, binding и ordinal. manual reference задаётся previous_analysis_id+group_id, сервер замораживает previous_members. Новый reference разрешён только если новая группа содержит reference и имеет ровно тот же набор previous_members; split/merge ⇒ REFERENCE_GROUP_CHANGED. Ручные locks берутся из существующих подтверждённых picks/overrides до admission, worker не читает mutable editor state.

`AssessCapture`: requested checks unique. Focus score = q/(1+q), q=mean(Laplacian(luma512)^2)*10000, для каждого видимого face ROI и whole frame; focus_critical<focus_warning, меньше threshold хуже. Clipping — fraction RGB outside[0,1], больше critical/warning хуже. Eyes — minimum per-eye probability из qualified eye_open, меньше eye_open_min warning. Glare — доля mask>0.5 в face ROI, выше glare_warning_fraction warning. Непригодная ROI или отсутствующий model → unavailable, score=null. Duplicate — exact original content SHA в recent_content_shas, warning при совпадении, иначе pass. Shot-list — считать unique previously confirmed frames с quality≥requirement.min_quality; worker context обязан включать frozen coverage, см. schemas. Не считать текущий кадр подтверждённым по автоматическому matching. Queue age>30s ⇒ persisted QA_STALE alert, не трактовать задержку как pass. coalesce подавляет только push, все critical отчёты сохраняются.

`TransferIntent`: использовать ORB+homography из16 только для planar background. Для лиц/объектов без qualified semantic matching ⇒ unsupported, без неописанного fallback. Mask warp bilinear, clamp[0,1], source/target protected overlap>0 ⇒ unsupported. Confidence=inlier fraction. Assemble проверяет exact target snapshot coverage и сохраняет target candidate refs. Remove/background_cleanup после human approval компилируются в существующую qualified inpaint operation; local_exposure — EV*mask; retouch_region — существующая qualified retouch с тем же mask. Отсутствующий downstream adapter запрещает admission, не создаёт success no-op.

`SignExport`: policy ref сверяется с signing_policy_id и текущим trusted config; lineage frozen после последнего watermark/metadata/encode. Adapter process принимает только paths staged export, JCS manifest, key handle и policy; без shell interpolation. SDK должен поддержать create→sign→verify JPEG/PNG; его exact installed version/lock SHA и qualification — обязательный deployment input. Verify повторно читает output, проверяет content binding, certificate chain SHA, signing claims, timestamp если required, и сравнивает decoded pixel content с input. Ошибка/timeout не публикует файл. Certificate expiry/revocation policy и trust anchors входят в qualified operator SigningPolicy; без них signer unavailable. Ключи/remote timestamp URLs не принимаются от клиента; server allowlist разрешает сервис по ID. C2PA manifest — бинарный контейнер SDK, не JSON, переименованный в C2PA.

## Выбранный C2PA adapter

Baseline SDK — `c2pa-python==0.32.4`, модуль c2pa, изолированный Linux x86_64 signer. Официальный wheel manylinux_2_28_x86_64 имеет SHA256 `a98a594cf79655e3f29987f40bcc5a601de382d352a567bba6601cd4a5322c56`; это dependency pin, не утверждение об успешной квалификации PhotoEditor. В deployment lock дополнительно фиксируются Python/native dependency/container hashes. Источник: [страница релиза и hashes](https://pypi.org/project/c2pa-python/0.32.4/).

`C2paAdapter.sign(input_path,manifest,policy,key_provider)` оборачивает Builder и Signer; приватная операция подписи выполняется callback к key_provider по key_handle, алгоритм ES256. Builder подписывает stream в новый файл и возвращает manifest bytes. `C2paAdapter.verify(output_path,policy)` создаёт новый Reader и переводит validation results SDK в внутренний verdict; string contains "success" не считается проверкой. API mapping и sign/read smoke входят в qualification pinned wheel, при API mismatch не переходить молча на latest. Официальные примеры: [signer callback](https://github.com/contentauth/c2pa-python-example/blob/main/app.py), [Builder/Reader API](https://contentauth.github.io/c2pa-python/api/c2pa/c2pa/index.html).

Project design: assert signing algorithm/certificate chain against policy, require active manifest, no validation failure, full content binding, trust root из trust_bundle_sha, timestamp_mode и revocation_mode. `revocation_mode=required` требует успешной fresh online проверки через operator allowlist; network unavailable⇒SIGNING_TRUST_UNAVAILABLE. `off` допускается только явно выбранной private trust policy и не отображается как public trusted. SDK не получает произвольные download URLs: remote manifest fetching off, input ingredients supplied streams. Native settings конкретной версии адаптер проверяет при startup. Claims строятся из SigningLineage; вся генерация помечается, неизвестная операция не получает ложный standard action, сохраняется namespaced assertion. Signature-valid и trust-valid — разные gates, оба required для policy public trust. ### V26/V32: server-selected calibrated provider budgets

`RenderCalibration` pins the exact `RenderQualification` tuple (model/runtime/backend/device/dataset), independent evidence SHA, ICC lock SHA, tile size, alpha policy and1..256 dimension samples. Measurements must cover the installed provider graph and supported workload envelope; a digest or a dimension record alone does not establish measurement quality. Duplicate dimension pairs, unsupported execution choices and malformed pins reject the registry.

`RenderCalibration.Select(qualification,width,height,iccSHA)` requires exact qualification/ICC agreement. RAM and VRAM retain the sample's measured upper bound. Scratch and output overhead use exact integer `ceil(sample_bytes * target_pixels *6 / (sample_pixels *5))`, retaining the specified20% safety factor without floating-point rounding. Unsafe scaled results reject. The selected provider overhead is added to independently compiled orchestration costs; these estimates are not a reservation or a worker capability.

`NewPinnedRenderCalibrationCatalog(raw,expectedSHA)` consumes operator-supplied canonical JSON≤1MiB with exactly schema_version1 and profiles1..128. The SHA comes independently from deployment's authenticated allowlist. Reject extra fields, noncanonical bytes, digest mismatch and duplicate qualification tuples. The catalog owns parsed data and Resolve returns owned sample copies. No user request can install a profile.
