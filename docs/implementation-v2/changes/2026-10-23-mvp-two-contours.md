# MVP: два сквозных контура на одной фотосессии из 50 файлов

Решение пользователя от 2026-10-23. Этот документ имеет приоритет над ранее перечисленными отдельными worker/qualification gates для первого MVP. Полная цель V20–V32 сохраняется как дальнейший объём, но не блокирует первый релиз вне двух путей ниже.

## Обязательные два прогона

1. Локальный Mac Apple Silicon: весь прикладной контур с действительным MPS/Metal-путём для выбранной AI-обработки. CPU обслуживает обычные I/O/RAW/цвет/архивирование. Пользователь отдельно подтвердил существующий PyTorch MPS/Metal; перенос на MLX не нужен. Незаявленный CPU fallback для выбранной AI-операции не засчитывается.
2. Серверный CUDA: сначала развёртывание всего выбранного серверного контура штатным compose/мигратором, затем тот же сценарий и тот же входной manifest. RTX worker работает на CUDA. Размещение инфраструктуры уточняется: весь compose на192.168.1.3 либо публичныйbackend178.104.19.245 сRTX192.168.1.3. Пароли/ключи в документы не включаются.

Для каждого: фотограф входит/регистрируется штатным приложением → создаёт проект/фотосессию → загружает все50подготовленныхфайлов → запускает выбранный поддержанный сценарий → получает50результатов без потерь → публикует клиентскую выдачу → отдельный клиент открывает галерею → скачивает результаты штатным механизмом → проверяется полноразмерность, SHA/декодирование, архив и принадлежность tenant. Серверный путь не использует локальныйDB/gateway как скрытую зависимость.

## Подготовленный набор

Входные файлы и manifest сохраняются внутри репозитория в work/mvp-two-contours-50/input. На каждый файл: порядковыйномер, имя, исходныйпуть, SHA256, bytes, формат, размеры/ориентация и происхождение. До подготовки нет заявления о готовых50фото. Оригиналы не меняются. Пустые/повреждённыеfixtures, миниатюры и простое дублирование одного файла не заменяют фотосессию. Если используются варианты одного исходника, это явно указывается; такой набор проверяет50файлов нагрузки, а не50независимыхсцен. Приватные пользовательские фото не попадают в publicgit/публичныегалереи. Набор байтодинаков в обоих контурах; история исходных тестовыхфайлов/лицензии сохраняется.

## Критерии приёмки

| Проверка | Локальный MPS/Metal | Серверный CUDA |
|---|---|---|
| Полная штатная миграция/запуск сервисов | Обязательна | Обязательна после деплоя |
| Одна подготовленная фотосессия50файлов | SHAmanifestсовпадает | Тотжевходнойmanifest |
| Штатная загрузка/состояния/обработка | 50/50 | 50/50 |
| Реальный выбранный AI backend | MPSфактическоеисполнение | CUDAфактическоеисполнение |
| Выдача отдельному клиенту | Галереядоступнапоразрешённойссылке | То же на серверном контуре |
| Скачивание | 50валидныхполноразмерныхрезультатов | 50валидныхполноразмерныхрезультатов |
| Качество | Оригинальныедетали/размер/ICC не потеряны, результат фотографу на оценку | Проверка тех же критериев; побайтная одинаковость MPS/CUDA не требуется |
| Безопасность пути | Чужойtenantнечитаетфайлы; секретыневыдаче | То же, публичныеадреса/HTTPSкорректны |
| Evidence | Сборка/настройки/задачи/backend/времена/ошибки/SHAрезультатов | Те же +compose/образа/фактическийсервер |

Ошибки, найденные в этих двух путях, исправляются с точечными регрессиями. Нельзя помечать failed/cancelled задачи как succeeded, подменять результат вручную или обходить штатный API. Проверки соответствуют данному пользовательскому сценарию, без расширения на полный каталог AI перед релизом.

## Что перестаёт быть отдельным блокером первого MVP

- Физический тест5000записей и4ГиБ+ ZIP64: отложен; набор50 должен штатноархивироваться/скачиваться.
- Отдельный длительный смешанный CPUsoak: заменён работойCPUвобоих50фотопутях. Существующие исправления/диагностика сохраняются.
- Квалификация каждой AI-функции всехV20–V32: послеMVP; передрелизом подтверждаются только реально выбранные функции двухконтуров. Остальные не рекламируются какготовые.
- Полное закрытие authoredцепочек, включаяregion.authored_crop: послеMVP, если не являются зависимостью выбранной обработки. Автоматическиотключённый/неподдержанныйпуть не засчитывается как реализованный.

Эти пункты не удалены из общейцели. Историческиеотчёты/исходники остаются; никаких тяжёлых ZIP64окон сейчас не запускать.

## Подтверждённое размещение серверного контура

Пользователь выбрал: backend и серверная инфраструктура — `178.104.19.245`; CUDA worker — `ubuntu@192.168.1.3`. PostgreSQL на backend использует ранее выбранный раздел `/mnt/HC_Volume_107202006`. Серверы должны связываться напрямую через защищённые каналы; Mac не участвует как промежуточная DB/AMQP/gateway или reverse-tunnel зависимость. Точные сетевые настройки проверяются после команды на старт.

Вариант «весь compose на RTX» больше не является выбранным. Это уточнение подготовительного плана, а не отмена запрета на запуск: тестирование, миграции и деплой остаются на паузе.
